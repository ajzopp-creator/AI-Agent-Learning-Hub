================================================================================

--------------------------------------------------------------------------------

   (do not hardcode which of the dated twins is active).

--------------------------------------------------------------------------------
2b. One-shot migration script (only write path)
--------------------------------------------------------------------------------
File (proposed):
  python/migrations/stage_4b_purge_four_pattern_ident_doubles.py
  (~120-150 lines; PEH wrapper in verify/run_this.py)

Protocol (same family as topk migration):
1. catalog_checkout on live.
2. Copy live -> internal temp.
3. ALL deletes only on temp.
4. Verify exact deltas.
5. atomic_move (live -> .bak, temp -> live).
6. On any mismatch: leave temp, live untouched.

--------------------------------------------------------------------------------
2c. Deletes on temp (only remove-set)
--------------------------------------------------------------------------------
For each pid in {36, 405, 437, 487}:

  Table               Action
  ------------------  ----------------------------------------------------------
  pattern_bars        DELETE WHERE pattern_instance_id = pid
  forward_labels      DELETE WHERE pattern_instance_id = pid
  pattern_features    DELETE WHERE pattern_instance_id = pid (if any; expect 0)
  topk_cache          DELETE WHERE pattern_instance_id = pid
                        OR matched_pid = pid
  pattern_instances   DELETE WHERE pattern_instance_id = pid
  source_files        DELETE for that pid's source_file_id ONLY IF no remaining
                      pattern_instances reference it (each of these four should
                      be exclusive)

Do not touch keep-pids' instance/bars/labels/own topk rows
(except removing a dead matched_pid from OTHER patterns' topk -- see 2d).

--------------------------------------------------------------------------------
2d. topk_cache after delete (required; not optional)
--------------------------------------------------------------------------------
Deleting a duplicate is not enough: some live patterns list both twins as
neighbors (equal distance), e.g.:

  Pair              Patterns that currently list BOTH in topk
  ----------------  ----------------------------------------------------------
  26 & 437 (WFG)    pid 43 (ranks 8-9)
  17 & 36 (PLTR)    pids 2708, 7004
  353 & 405 (RRC)   pid 2722
  449 & 487 (BOIL)  none

Also low fan-in as matched_pid only (one or two patterns each).
After delete, those caches have a hole (19 of 20) or a missing neighbor.

Chosen approach for this WO (safe, scoped, no new ranking code):
1. After the four purges on temp: DROP and RE-SEED full topk_cache using the
   existing proven seeder (stage_4a / seed_full_catalog path -- same O(N^2)
   ~60 min already run successfully).
2. Expected post-seed:
   - patterns ~ 10,757 (10,761 - 4)
   - topk_cache rows ~ 20 x survivors (same thin-corpus shortfall as before)
   - zero TopKTieError preferred; if a real non-duplicate tie appears, STOP
     (same Finding-3 rule).

Why full reseed instead of surgical fill-one-slot:
  Only a handful of references, but surgical fill needs new "next-best
  neighbor" code and is easy to get subtly wrong on live data.
  Reseed is already proven.
