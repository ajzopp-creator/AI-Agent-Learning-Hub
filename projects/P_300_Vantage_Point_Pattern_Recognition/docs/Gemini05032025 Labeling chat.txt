# 1. Project Overview

## 1.1 Purpose

P_300_Vantage_Point_Pattern_Recognition is a VantagePoint-based research and development project focused on building a durable historical pattern catalog from SPY and later multi-symbol market data. Its purpose is to detect repeatable short-horizon market patterns, label them by forward profitability, and use those labels to support future IntelliScan-style matching and ranking workflows.

## 1.2 Scope

**What this system covers**
- Historical pattern extraction from VantagePoint / history-grid style data
- Pattern catalog creation using structured historical records
- Profitability labeling for 5-day to 10-day holding windows
- Future matching of current IntelliScan candidates to historical analog patterns
- AI-assisted research, planning, architecture, and workflow control

**What this system does not cover**
- Automated live brokerage execution
- Full enterprise data engineering infrastructure
- Long-horizon portfolio optimization
- Non-pattern-based discretionary market analysis unless explicitly added later

Protocol Steps:

2.3 Core Components
Component 1 — Data Input Layer
Responsibility: Load SPY and future multi-symbol historical data from VantagePoint exports, spreadsheets, CSV, or transformed files.

Inputs: History-grid exports, CSV files, Excel files, manually validated pattern examples.

Outputs: Clean bar-level records and normalized data tables.

Tools Used: Python, CSV/XLSX processing, hub folder structure.

Dependencies: Consistent source files, file naming discipline, project folder conventions.

Component 2 — Pattern Engineering Layer
Responsibility: Transform cleaned market records into comparable pattern feature vectors.

Inputs: Clean historical OHLCV-style records and derived indicators.

Outputs: Pattern signatures, window encodings, feature hashes, and similarity-ready representations.

Tools Used: Python scripts, reusable utilities from hub architecture.

Dependencies: Stable feature definitions and version-controlled logic.

Component 3 — Catalog & Labeling Layer
Responsibility: Persist pattern instances in SQLite and attach future profitability labels for defined hold periods.

Inputs: Pattern vectors plus future return windows.

Outputs: SQLite catalog tables, forward-return labels, win/loss classifications, hit-rate-ready records.

Tools Used: Python, SQLite.

Dependencies: Historical completeness, label definitions, schema control.

Component 4 — Matching & Decision Support Layer
Responsibility: Query historical analogs for current patterns and rank likely outcomes.

Inputs: Current candidate pattern, pattern catalog, match criteria.

Outputs: Ranked analogs, expected return tendencies, confidence context.

Tools Used: Python, AI reasoning workflow, future IntelliScan integration.

Dependencies: Pattern database quality, similarity rules, clean session context.

Component 5 — AI Session Control Layer
Responsibility: Maintain consistency across sessions using architecture documents, startup prompts, and documented rules.

Inputs: This architecture document, project summaries, thread startup instructions.

Outputs: Context continuity, reduced drift, more consistent task execution.

Tools Used: Claude/Gemini/Grok/LLM project workflows, markdown documentation.

Dependencies: User discipline to load architecture first every session.

2.5 Design Rationale
Simplicity: Start with SPY only, one repeatable pipeline, and a clean SQLite catalog before adding more assets.

AI-centric control: The AI is used for planning, schema design, workflow enforcement, and research support rather than replacing deterministic computation.

Maintainability: Documentation-first architecture reduces thread drift and creates a stable project memory anchor.

Independence: P_300 follows hub standards from P_000 while remaining a self-contained pattern-recognition system.

Alternatives considered

Option	Pros	Cons	Decision
Start multi-stock immediately	Faster expansion	Higher complexity, harder validation	Rejected for v1
Use flat CSV only	Simple to inspect	Weak for querying and scaling	Rejected
Build SQLite-first on SPY	Structured, queryable, scalable	Slightly more setup	Selected

def insert_safe(df, table_name, conn):
    """
    Dynamically checks the target SQLite table and ONLY inserts columns 
    that actually exist in the table, preventing OperationalErrors.
    """
    cursor = conn.cursor()
    cursor.execute(f"PRAGMA table_info({table_name})")
    valid_cols = [row[1] for row in cursor.fetchall()]
    
    cols_to_keep = [c for c in df.columns if c in valid_cols]
    
    if not cols_to_keep:
        return # Table exists but no columns match our data; skip safely.
        
    df_safe = df[cols_to_keep].copy()
    df_safe.to_sql(table_name, conn, if_exists='append', index=False)

def ingest_data(data_type, db_path):
    db_file = Path(db_path)

def run_labeling():
    if not os.path.exists(DB_PATH):
        print(f"Error: Database not found at {DB_PATH}")
        return

    print("--- P_300 LABEL GENERATION STARTING ---")
    conn = sqlite3.connect(DB_PATH)
    
    # Ensure schema exists
    conn.execute("""
        CREATE TABLE IF NOT EXISTS forward_labels (
            pattern_instance_id INTEGER,
            horizon_days INTEGER,
            future_date TEXT,
            return_pct REAL,
            is_profitable INTEGER
        )
    """)
    
    print("Computing forward labels (5d, 7d, 10d)...")
    
    # Target only new, unlabeled instances
    query_instances = """
        SELECT p.pattern_instance_id, p.anchor_date, p.close_0 
        FROM pattern_instances p
        LEFT JOIN forward_labels f ON p.pattern_instance_id = f.pattern_instance_id
        WHERE f.pattern_instance_id IS NULL
    """
    instances = pd.read_sql_query(query_instances, conn)
    
    if instances.empty:
        print("All pattern instances are already labeled. No new labels to generate.")
        conn.close()
        return

    print(f"Found {len(instances)} new pattern instances to label.")
    
    labels = []
    for row in instances.itertuples():
        try:
            anchor_dt = datetime.strptime(row.anchor_date, '%Y-%m-%d')
        except ValueError:
            continue
            
        for horizon in [5, 7, 10]:
            target_date = (anchor_dt + timedelta(days=horizon)).strftime('%Y-%m-%d')
            
            # Find the future price
            query = "SELECT close FROM price_bars WHERE bar_date >= ? ORDER BY bar_date ASC LIMIT 1"
            res = conn.execute(query, (target_date,)).fetchone()
            
            if res:
                future_price = res[0]
                pct_return = (future_price - row.close_0) / row.close_0
                labels.append((row.pattern_instance_id, horizon, target_date, pct_return, 1 if pct_return > 0 else 0))
    
    if labels:
        conn.executemany("INSERT INTO forward_labels VALUES (?, ?, ?, ?, ?)", labels)
        conn.commit()
        print(f"Successfully generated and inserted {len(labels)} new labels.")
    else:
        print("No future price data found to generate labels (likely due to dates at the edge of the dataset).")

    conn.close()
    print("--- LABEL GENERATION COMPLETE ---")

if __name__ == "__main__":
    run_labeling()

This is a brilliant architectural question. You are naturally thinking like a quant. A single-pass system is almost always flawed because it forces you to weigh "what it looks like" against "what the underlying mechanics are" in the exact same calculation, which usually dilutes both.

A Two-Pass Architecture is absolutely the gold standard for this type of system.

Based on how VantagePoint works and how pattern recognition scales, here is the breakdown of how we should structure the intelliscan.py pipeline, and my formal recommendation on the order of operations.

The Recommendation: Predictive Features First, Raw Price Second
If we want the highest probability of finding a true analog, we should do Pass 1: Feature Vector (Predictive State) followed by Pass 2: Raw Price (Visual Confirmation).

Here is why this is the superior approach:

1. The "VantagePoint Edge" Principle
VantagePoint's entire premise is that raw price action is a lagging illusion, and the predictive indicators (Neural Index, Predicted Differences, Triple Cross) reveal the true state of the market.

If we filter by raw price first, we might throw out a pattern that looks slightly different visually, but has the exact same hidden predictive signature as our live setup.

By filtering by Features first, we isolate the "Market Regime." We are effectively asking: "Show me all historical moments where the underlying momentum, sentiment, and neural predictions were behaving exactly like they are right now."

2. Computational Scaling (Future-Proofing for FR-5)
Right now, you have 394 rows. But when you expand to multi-stock (FR-5), you will have 50,000+ rows.

Calculating the distance between mathematical feature vectors (Cosine Similarity or Euclidean Distance) is computationally instantaneous. It acts as a lightning-fast net to drop the database from 50,000 rows down to the top 100 closest matches.

Matching raw price shape requires Dynamic Time Warping (DTW) to account for volatility stretching. DTW is computationally heavy. If you try to run DTW on 50,000 rows as your first pass, the system will crawl.

The IntelliScan Architecture (How it will work)
If we build the engine this way, the intelliscan.py script will execute the following workflow when you feed it a live 5-day setup:

Pass 1: The Predictive Filter (Vector Matching)

The engine looks at your live VantagePoint indicators (psi, neuralx, triple_cross, etc.).

It calculates the Euclidean distance against every pattern in the catalog.

Result: It immediately discards 90% of the catalog that doesn't match the underlying mechanics, returning the Top 50 "Regime Matches."

Pass 2: The Structural Filter (Price Matching)

The engine takes those Top 50 Regime Matches and runs a Dynamic Time Warping (DTW) algorithm on their raw 5-day OHLC prices against your live 5-day OHLC.

Result: It re-ranks the Top 50 to find the ones that share the same predictive state AND visually look identical to your current chart.

Output:

It presents the Top 5 matches to you, pulling their real Forward Labels from the database so you know exactly what happened next.

The Path Forward
This two-pass design gives you the speed of a vector database with the visual accuracy of a shape-matching algorithm.

def calculate_dtw(s1, s2):
    if len(s1) == 0 or len(s2) == 0: return float('inf')
    n, m = len(s1), len(s2)
    dtw_matrix = np.full((n+1, m+1), np.inf)
    dtw_matrix[0, 0] = 0
    for i in range(1, n+1):
        for j in range(1, m+1):
            cost = abs(s1[i-1] - s2[j-1])
            dtw_matrix[i, j] = cost + min(dtw_matrix[i-1, j], dtw_matrix[i, j-1], dtw_matrix[i-1, j-1])
    return dtw_matrix[n, m]

def get_5day_normalized_close(inst_id, conn):
    meta = pd.read_sql(f"SELECT symbol_id, anchor_date FROM pattern_instances WHERE pattern_instance_id = {inst_id}", conn)
    if meta.empty: return []
    s_id, anchor = meta.iloc[0]['symbol_id'], meta.iloc[0]['anchor_date']
    prices = pd.read_sql(f"SELECT bar_date, close FROM price_bars WHERE symbol_id = {s_id}", conn)
    prices['dt'] = pd.to_datetime(prices['bar_date'], format='mixed')
    history = prices[prices['dt'] <= pd.to_datetime(anchor)].sort_values(by='dt', ascending=False).head(5)
    closes = history.sort_values(by='dt')['close'].values
    if len(closes) < 2: return []
    base = closes[0]
    return [((p - base)/base)*100 if base != 0 else 0 for p in closes]

def get_intelliscan_results(target_id):
    conn = sqlite3.connect(DB_PATH)
    features_df = pd.read_sql("SELECT pattern_instance_id, feature_name, feature_value FROM pattern_features", conn)
    features_df = features_df.drop_duplicates(subset=['pattern_instance_id', 'feature_name'], keep='last')
    pivot_df = features_df.pivot(index='pattern_instance_id', columns='feature_name', values='feature_value').dropna()
    
    if target_id not in pivot_df.index: return []
    
    target_vec = pivot_df.loc[target_id]
    distances = []
    for inst_id, row in pivot_df.iterrows():
        if inst_id == target_id: continue
        distances.append((inst_id, np.linalg.norm(row.values - target_vec.values)))
    distances.sort(key=lambda x: x[1])
    top_50 = [x[0] for x in distances[:50]]
    
    target_shape = get_5day_normalized_close(target_id, conn)
    final_scores = []
    for cand_id in top_50:
        cand_shape = get_5day_normalized_close(cand_id, conn)
        if cand_shape:
            final_scores.append((cand_id, calculate_dtw(target_shape, cand_shape)))
    final_scores.sort(key=lambda x: x[1])
    
    results = []
    seen = set()
    for cand_id, dtw_score in final_scores:
        meta = pd.read_sql(f"SELECT symbol_id, anchor_date FROM pattern_instances WHERE pattern_instance_id = {cand_id}", conn).iloc[0]
        sym = pd.read_sql(f"SELECT ticker FROM symbols WHERE symbol_id = {meta['symbol_id']}", conn).iloc[0]['ticker']
        clean_date = pd.to_datetime(meta['anchor_date']).strftime('%Y-%m-%d')
        if f"{sym}_{clean_date}" in seen: continue
        seen.add(f"{sym}_{clean_date}")
        
        labels = pd.read_sql(f"SELECT horizon_days, return_pct FROM forward_labels WHERE pattern_instance_id = {cand_id}", conn)
        labels_dict = dict(zip(labels['horizon_days'], labels['return_pct']))
        
        results.append({
            'id': cand_id, 'sym': sym, 'date': clean_date, 'score': dtw_score,
            'ret_5d': labels_dict.get(5, 0) * 100
        })
        if len(results) >= 5: break
    conn.close()
    return results

if __name__ == '__main__':
    res = get_intelliscan_results(394)

import sys
import sqlite3
import pandas as pd
from pathlib import Path
sys.path.append(r'C:\Users\Trader\AI-Agent-Learning-Hub\projects\P_300_Vantage_Point_Pattern_Recognition\python\matching')
from intelliscan import get_intelliscan_results

DB_PATH = r'C:\Users\Trader\AI-Agent-Learning-Hub\projects\P_300_Vantage_Point_Pattern_Recognition\models\050326geminicatalog.db'

def get_latest_pattern_ids(limit=10):
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.cursor()
    # Grabs the most recently added patterns automatically
    cursor.execute("SELECT pattern_instance_id FROM pattern_instances ORDER BY pattern_instance_id DESC LIMIT ?", (limit,))
    ids = [row[0] for row in cursor.fetchall()]
    conn.close()
    return ids

def run_smart_report():
    target_ids = get_latest_pattern_ids()
    print(f"Auto-detected {len(target_ids)} recent patterns to scan...")
    
    for t_id in target_ids:
        results = get_intelliscan_results(t_id)
        if not results: continue
        
        df = pd.DataFrame(results)
        win_rate = (df[df['ret_5d'] > 0].shape[0] / df.shape[0]) * 100
        avg_ret = df['ret_5d'].mean()
        
        print("\n" + "="*50)
        print(f" P_300 CONFIDENCE REPORT (ID #{t_id})")
        print("="*50)
        print(f" Historical Analogs Found: {df.shape[0]}")
        print(f" 5-Day Win Rate: {win_rate:.1f}%")
        print(f" Avg 5-Day Return: {avg_ret:.2f}%")
        
        if win_rate >= 60 and avg_ret > 0:
            print(" SIGNAL: BULLISH - HIGH CONFIDENCE")
        else:
            print(" SIGNAL: NEUTRAL/BEARISH")
        print("="*50)

if __name__ == '__main__':
    run_smart_report()
"@
