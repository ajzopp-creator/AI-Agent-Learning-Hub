## WHY

Tier 2A's dossier (architecture doc Section 4.2, items 1-9) is currently
built by Claude reading TOS screenshots. With Schwab price-history bars
available (WO-P400-E4.002), items 1-8 -- trend, S/R, moving averages, RSI,
MACD, Bollinger Bands, volume, Fibonacci -- are well-defined, standard
formulas and become real computed Python, not eyeballed off an image.

Item 9 (chart pattern ID -- H&S, double top, cup-and-handle, flags) is a
different kind of problem. Geometric pattern recognition is unreliable
even in mature commercial TA software -- genuinely a judgment call, not
arithmetic. Confirmed with Tony (2026-07-21): item 9 stays Claude-narrated,
now reasoning over the computed indicator/OHLC table this WO produces
instead of a screenshot -- still removes the screenshot dependency, without
pretending shape recognition is deterministic.

Fibonacci's swing-high/swing-low detection reuses the pivot-window
algorithm already live in P_300's `find_swing_high_resistance()`
(`domain\pattern_detector.py`) -- same N-bar-window pivot convention,
generalized to plain bar tuples (same pattern as `atr.py`), with a
symmetric swing-low added (P_300's version only finds highs, above the
current close; Fibonacci needs both ends of the swing).

**Fibonacci swing-low: NOT verified, disclosed as a known gap.** TOS's
daily-chart FIB shows swing low 73.47. `cli.py dossier` computed 92.34.
Earlier session claim ("verified against a live TOS FIB(60d) display,"
in levels.py's module docstring and this WO's design addendum) compared

show 92.34 for its own FIB(60d) label. That was the wrong reference to
compare against; caught and corrected same session, not left standing.

What IS verified: the retracement formula itself (level = swing_high -
ratio * (swing_high - swing_low)) -- confirmed exactly against real
numbers, still correct arithmetic regardless of which swing points feed
into it.

What is NOT verified: swing_detector.py's pivot-window algorithm (ported
from P_300's find_swing_high_resistance()) does not necessarily find the
same "significant swing" TOS's own algorithm finds, even on matching
daily bars over what should be a comparable ~60-day window. Root cause
not diagnosed -- TOS's internal swing/pivot method isn't documented
anywhere accessible. Possibilities not yet investigated: different pivot
window width, a materially different significance threshold, or a
genuinely different lookback convention than 60 bars.
