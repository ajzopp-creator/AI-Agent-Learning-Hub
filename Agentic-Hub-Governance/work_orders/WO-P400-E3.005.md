# WO-P400-E3.005 -- Vertical Spread Legs Have No Viability Gate; Liquidity Warnings Never Surface to Output
**Status:** CLOSED
**Owner:** P_400
**Affects:** (none -- internal P_400 only; spread_sizer/evaluate_spread logic+display)
**Depends On:** None
**Acks:** N/A

---

## WHY

`domain\options_council.py` `run_options_council()` runs OI/spread/R:R-parity/
IV-rank viability gates on single-leg options trades (WO-P400-E3.001) and is
invoked on the single-leg path via `application\evaluate_options.py`. No
equivalent exists for vertical debit spreads. `domain\spread_sizer.py`
`size_vertical_debit_spread()` performs sizing math only -- it never checks
either leg's open interest or bid/ask spread against the Architecture v2.1
Section 3.8 thresholds (OI >= 150, spread <= 10% of mid).

The only liquidity check that exists anywhere near the spread path is
`infrastructure\chain_loader.py` `_warn_liquidity()`, which logs a
`logger.warning()` line per leg when OI/spread thresholds are exceeded.
This is a logging side effect of loading a chain file -- it is not a
council verdict, it does not block sizing, and it is not included in
`build_spread_spec.py`'s rendered output or `evaluate_spread.py`'s
`SpreadEvalResult`. Whether the warning is visible to Tony depends entirely
on the calling terminal's logging level.

Found live during WO-P400-E3.001/E3.002 verification, 2026-06-30: a real
ADBE vertical spread (long 215C / short 225C, both TOS-sourced) sized
cleanly to 1 contract via Gate 1 (RISK), R:R 4.71, no warning or block
surfaced in the printed `SPREAD SIZING` / Pattern C output. The short leg
(225C) carried spread_pct_of_mid=11.9% -- above the same 10% threshold
that would BLOCK this exact leg outright on the single-leg options path
via `options_council.py`'s `_check_spread()`. The spread was sized and a
fully formed Schwab-ready spec was rendered for a leg that would have been
refused as a standalone single-leg trade.

This is a structural inconsistency, not a one-off: the architecture
document's liquidity thresholds (3.8) are written as universal options
viability rules, not single-leg-only rules, but only the single-leg path
enforces them.

---

## SCOPE

1. New `domain\spread_council.py` (or extend `options_council.py` to accept
   either a single chain or a long/short pair) -- run OI and spread-pct
   checks against BOTH legs independently. A spread is only as liquid as
   its worse leg; either leg failing produces a BLOCK (severity resolved
   2026-07-04, see below).
2. `application\evaluate_spread.py` -- call the new council check before
   rendering the spec, mirroring the single-leg pattern in
   `evaluate_options.py` (council BLOCK -> no spec rendered).
3. `application\build_spread_spec.py` -- accept and render a verdict/blocks
   list the way `build_option_spec.py`'s caller surfaces council state in
   `cli.py`, so a CAUTION-level liquidity issue (e.g. one leg under 10%,
   one over) is visible in the printed Pattern C spec itself, not only in
   chain_loader's log line.
4. `cli.py` `--spread` dispatch -- print spread council verdict/blocks/
   cautions before the spec, matching the existing `--options` dispatch
   block already in place.
5. New `test_spread_council.py` -- both-legs-pass, long-leg-fails,
   short-leg-fails, both-fail cases. Regression test reproducing the exact
   ADBE 215C/225C case from this WO as a BLOCK (or explicit CAUTION,
   pending Tony's decision on severity -- see OUT OF SCOPE).

## OUT OF SCOPE

- R:R-parity-style cross-checks specific to spreads (e.g. comparing spread
  R:R against stock R:R the way single-leg does). Liquidity gating only.

## SEVERITY DECISION -- RESOLVED 2026-07-04

BLOCK. Either leg failing Section 3.8 liquidity thresholds (OI < 150 or
spread_pct_of_mid > 10%) is a hard BLOCK, same as the single-leg path --
no softer CAUTION tier for spreads. Rationale: a wide/thin leg means fill
cost alone can erode the trade's edge before the position starts working;
unlike an earnings-date CAUTION, there is no equivalent mitigating action
(e.g. defined-risk restructure) that offsets a bad fill on a spread leg.
The ADBE 215C/225C case (short leg spread_pct_of_mid=11.9%) is the
canonical BLOCK regression case for `test_spread_council.py`.

---

## ACCEPTANCE CRITERIA

- A spread where either leg fails the Section 3.8 liquidity thresholds
  produces a verdict visible in the printed CLI output (not log-only)
  before any spec is rendered.
- The ADBE 215C/225C case from this WO is captured as a named regression
  test.
- Regression: spreads where both legs pass liquidity thresholds are
  unaffected -- spec renders exactly as it does today.
