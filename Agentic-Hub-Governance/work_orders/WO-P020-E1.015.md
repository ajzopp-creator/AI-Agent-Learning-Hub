## WHY

Balance and positions pulls (`cli.py balance --account IRA`, `cli.py positions --account IRA`)
already work for 9885 via the shared `account_map` lookup. Transaction ingestion does not --
`schwab_trade_pull.py` / `ingest_pipeline.py` / `cli.py import` only target `AJZ6348`.

Tony's call (2026-08-20): the IRA account holds investments and swing trades worth tracking.
Extend ingestion so 9885 transactions land in `trades`/`exits` like AJZ's do.

## DECISIONS (2026-08-20)

1. **System/tag source:** IRA bypasses `system_resolver.py` (vault/tracker/default priority)
   entirely -- same as paper. Tags come from ThinkLog: `INV` for generic investment/swing
   trades with no specific signal system, or an actual existing project code (e.g. `P_115`,
   `P_300`) if the trade genuinely traces to one. Parser is open-vocabulary already, so `INV`
   needs no code change to accept -- add it to the WHY vocabulary table in
   `docs\P_020_MASTER_SYSTEM_DOCUMENTATION_v1_0.md` Section 9.5 for documentation consistency.
2. **Date scope:** 1/1/2026 forward -- same rule as AJZ, not full available history.
3. **Tag flow:** Follow the same rules as paper -- Symbol+Date join (±3-day window, LIFO
   concat), `reason`/`signal_strength` populated from ThinkLog, not left NULL.

## SCOPE

- `schwab_trade_pull.py`: accept `--account IRA`, resolve via existing `account_map` +
  `get_account_hash(last4)` (mirrors `cmd_balance`/`cmd_positions`).
- `ingest_pipeline.py` / `cli.py import`: thread `--account` through TRD filter, 10-min
  consolidation, and orphan detection -- already account-agnostic, just currently hardcoded
  to AJZ's call path.
- **Tag join:** the ThinkLog join logic currently gated `account_id='PAPER'` in
  `paper_import.py` needs to also run for `account_id='IRA9885'`. Either broaden that gate
  or extract the join into a shared function called by both paper and IRA ingestion --
  extraction is cleaner given BACKLOG-8 will need the same thing for AJZ6348 later.
  `system_resolver.py`'s vault/tracker path is explicitly NOT used for IRA (Decision 1).
- `db_writer.py`: write with `account_id='IRA9885'`. Dedup key unchanged
  (`schwab_transaction_id`), already account-agnostic.
- Date filter: 1/1/2026 forward only (Decision 2) -- no full-history backfill.
- No change to AJZ ingestion path, dedup logic, or `v_trade_summary` schema.

## ACCEPTANCE CRITERIA

- `cli.py import --account IRA` pulls, filters, consolidates, and writes IRA transactions
  (1/1/26 forward) without touching any AJZ6348 row.
- Trades written carry `account_id='IRA9885'`; `reason`/`signal_strength` populated from
  ThinkLog tags (`INV` or actual project code), not NULL.
- `system_resolver.py` vault/tracker priority confirmed NOT invoked for IRA rows.
- Dedup via `schwab_transaction_id` confirmed safe to re-run.
- Orphaned sells flagged in audit log, never dropped silently.
- `v_trade_summary` returns IRA rows correctly filtered by `account_id`.
- Compile-clean under p140 warnings-as-errors.
- Independent review confirms the fix in a separate session before CLOSED, per
  WO_COMPLETION_GATE.
