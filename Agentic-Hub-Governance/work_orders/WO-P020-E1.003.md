## WHY

SKILL.md's "Bugs Already Fixed" table is documentation, not enforcement.
On 2026-07-05, three regressions were found in one session: a timestamp
regex that silently dropped every ThinkLog tag match when TOS exports
omitted seconds, a column-name mismatch in paper_import.py that nulled
every options entry_price, and a NaN-propagation bug in the TOS parser's
fee parsing that had already been fixed once (in old_P_020_TOS_Parser_v2.py)
and quietly regressed when the parser was rewritten in v2.3/v2.4. None of
these were caught before they reached a commit workflow -- they surfaced
only because Tony manually reviewed output that looked wrong.

Writing the fix and updating SKILL.md does not stop the next rewrite from
reintroducing the same bug. A test that fails the moment the bug returns
does.

---

## SCOPE

1. `projects/P_020_AJZStrategies_PerformanceAnalysisSystem/tests/test_p020_known_bugs.py`
   -- one test per row in SKILL.md's Bugs Already Fixed table. Two kinds,
   both labeled in the file:
   - BEHAVIOR: calls the real function against a tiny synthetic input,
     checks actual output.
   - SOURCE: greps the fixed file for the fix's signature. Used where a
     full behavioral test needs live API/DB fixtures not worth building yet.
   Run standalone via python (no pytest dependency), prints PASS/FAIL per
   test plus a summary line, exits nonzero on any failure.

2. Every future fix to a file covered by SKILL.md's bug table gets a
   matching test added to this file in the same session, before the fix
   is called done.

3. Hub-wide recommendation: any project with a SKILL.md "Bugs Already
   Fixed" table (or equivalent) should have a matching
   `test_<project>_known_bugs.py` alongside it. P_020 is the first
   instance; P_300 and others should adopt the same pattern when their
   next regression surfaces.
