WHY:
The editable install currently maps exactly one top-level name -- hub_lib
(__editable__.hub_lib-0.1.0.pth; top_level.txt = hub_lib; pyproject
include = ["hub_lib*"]). shared_resources has NO __init__.py and is NOT a mapped
or namespace package. Today "from shared_resources.python_utils..." only resolves
because shared_resources\python_utils\vault_interface.py performs a runtime
sys.path.insert of the P_800 python folder, and consumers reach the contract by
importing vault_interface first. That couples every consumer to P_800's runtime
-- a layer reaching through another layer, the exact boundary violation the E2
shared-contract work is meant to remove.

A contract on "neutral ground" must resolve through the import system itself, not
through one project's sys.path side-channel. That requires shared_resources to be
a real installed package. That is hub-wide install configuration = P_000
infrastructure, not P_800 (P_800 is read-only relative to other projects and may
not edit hub packaging).

SCOPE:
  1. Add shared_resources\__init__.py (and python_utils already has one).
  2. Make package discovery include shared_resources* -- either a dedicated
     pyproject for shared_resources, or extend the hub_lib editable install's
     find config. P_000 chooses the mechanism.
  3. pip install -e the package into the p140 env.
  4. Do NOT remove vault_interface.py's existing sys.path insert in this WO
     (that is a separate cleanup); this WO only makes the clean import resolvable.

VERIFY:
  - Fresh python.exe (p140), NO manual sys.path edits:
      python -c "from shared_resources.python_utils.vault_interface import write_to_vault; print('OK')"
    -> prints OK.
  - python -c "import shared_resources, shared_resources.python_utils; print('pkg ok')"
    -> prints pkg ok.
