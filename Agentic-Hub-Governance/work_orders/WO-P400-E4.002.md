## WHY

STEP 4a/4b of the SIP currently require Tony to read TOS screenshots and
Claude to transcribe price/bid/ask/ATR14/volume into `snapshot_SYMBOL.json`
by hand, and similarly for `chain_SYMBOL.json`. The snapshot dict contract
(architecture doc Section 6.2) already anticipates `data_source:
"schwab_api"` as a valid value -- this WO makes it real.

`atr_14` is not fetched -- it's computed from Schwab's price-history OHLC
bars via the existing shared `compute_atr_wilder()`
(`shared_resources\python_utils\atr.py`), already live in P_300. No new
ATR math.

`next_earnings_date` and `sector` stay web-search-sourced (Tony's explicit
call, 2026-07-21) -- Schwab's fundamentals data isn't reliably populated
for earnings dates industry-wide. `fetch-snapshot` accepts them as optional
flags so Claude can hand Tony a fully-formed command after searching, per
the existing pattern of Claude constructing exact commands for Tony's
terminal.

## DESIGN ADDENDUM -- 2026-07-24 (before build, this session)

Original WO assumed Tony/Claude always hand `fetch-chain` an exact
strike+expiration already picked by eye off a chart. Tony's call: the
system should be able to select the optimal contract itself when not
given one explicitly.

Checked `P_115` `OPTIONS_RISK_METHODOLOGY.md` first (canonical options
authority per architecture doc Section 7.3) -- it governs stop/target/
sizing math for an ALREADY-CHOSEN contract, says nothing about which
strike/expiration to pick. Genuine gap, not an existing rule being
overridden. Researched externally (general options-desk practice,
converges across independent sources), reconciled against the
methodology doc's own MCHP worked example (delta 0.6074).

**Selection parameters (Tony's explicit call, not just research default):**
- Target delta: **0.50** (ATM -- max leverage/theta tradeoff, deliberate choice)
- DTE window: **21-45 days** (research default, accepted) -- "2-3x expected
  hold period" is the consistent rule of thumb across sources checked;
  P_400 swing-horizon trades (days to a few weeks to T1/T2) land in this band
- Config constants: `OPTION_SELECTION_TARGET_DELTA`, `OPTION_SELECTION_MIN_DTE`,
  `OPTION_SELECTION_MAX_DTE` in `config.py`

**Selector scope, deliberately narrow:** picks by DTE window + closest-to-
target-delta only. Does NOT duplicate R:R/OI/spread checks -- those need
the delta-translated stop/target math that only happens after a contract
is chosen (existing `options_council.py` job, unchanged). Selector hands
its pick to the exact same downstream path a manually-typed `--strike`/
`--expiration` contract already goes through today. `--strike`/
`--expiration` remain valid CLI overrides that skip selection entirely.

**New component:** `domain\chain_selector.py` -- pure logic, no I/O,
`select_optimal_contract(candidates, target_delta, min_dte, max_dte)`,
returns `None` honestly (never fabricates) when nothing in the DTE window
qualifies. `schwab_market_data.py`'s `get_chain_candidates()` now fetches
the DTE-filtered range, not one exact contract -- selection logic lives
in domain/, not infrastructure/.
## OUT OF SCOPE

- Technical indicators beyond ATR (MA/RSI/MACD/BB/S-R/Fibonacci) --
  WO-P400-E4.003.
- Changing the Entry Resolution Rule, Council, or any deterministic
  sizing/screen logic. This WO only changes how the snapshot/chain JSON
  files get populated, not how they're consumed downstream.

## ACCEPTANCE CRITERIA

- `fetch-snapshot SYMBOL` writes a `snapshot_SYMBOL.json` that passes
  `SnapshotDict` validation, using live Schwab data for every field except
  earnings/sector.
- `fetch-chain SYMBOL --expiration DATE` writes a valid `chain_SYMBOL.json`
  the same way for `OptionChainInput`.
- Mocked API failure (network error, bad symbol, market closed) prints a
  clear message and exits without writing a partial/corrupt file -- Tony
  falls back to the existing manual/TOS path, never blocked.
- Regression: `evaluate`/`compare`/`spec` paths unaffected -- they still
  just read whatever `snapshot_SYMBOL.json`/`chain_SYMBOL.json` exists on
  disk, regardless of how it was produced.
- `fetch-chain SYMBOL --type call` with no `--strike`/`--expiration` selects
  the candidate closest to 0.50 delta within the 21-45 DTE window and writes
  that contract's data -- never fabricates a pick when nothing qualifies.
- `--strike`/`--expiration` still work as explicit overrides, bypassing
  selection entirely (unchanged manual path).
