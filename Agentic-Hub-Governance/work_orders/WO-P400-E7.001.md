## WHY

Live 2026-08-31, 16:24 ET (after-hours, batch-2b): CME/SPGI/WFC all Tier-1
PASS, all three failed fetch-snapshot with `[ERROR] No live spread on
record -- can't price the close without fabricating a spread. Fetch this
symbol live during market hours first. No file written.` None of the three
had ever been fetched live during regular hours, so `last_spread_cache.py`
had nothing to reconstruct bid/ask from (WO-P400-E5.005's close-basis
fallback).

Researched same session: Schwab's `/marketdata/v1/quotes` endpoint (used
via schwab-py `Client.get_quote()`/`get_quotes()`) exposes a distinct
`extended` field group alongside `quote`/`fundamental`/`reference`/
`regular` -- `fields=quote,extended` returns live bid/ask/mark/size for
the current session, covering pre-market, after-hours, and overnight.
This is a different endpoint from what `fetch_snapshot.py` calls today
(`pricehistory` only, daily bars). Confirmed via Schwab's own
consumer-facing documentation: mark/bid/ask/size are populated for all
three extended sessions.

If wired in, this would have priced all three tonight directly from a
live Schwab quote -- no dependency on a previously-cached spread at all.
Not a fix to today's specific bug (E5.005's cached-spread fallback is
working as designed); a new pricing basis that removes the need for that
fallback during the extended-hours windows.

**Data-quality caveat, from Schwab's own docs (not our finding):**
extended-session quotes may reflect only one trading venue, not a
consolidated NBBO, and can diverge from other quote sources; liquidity is
thinner and spreads run wider than regular hours as a rule. The existing
`MAX_PLAUSIBLE_SPREAD_PCT` gate (E4.004, 2.0%) is tuned for regular-hours
spreads and will likely need a separate, looser threshold for this basis
rather than reusing 2.0% as-is -- exact value TBD, needs a look at real
extended-hours spread samples before picking a number, not a guess.

## WHAT

1. New `price_basis` value: `"extended"` (existing values: `"live"`,
   `"close"`, from E5.005).
2. Session-window detection ahead of the existing closed-market branch in
   `fetch_snapshot.py`: pre-market 4:00-9:30 ET, after-hours 16:00-20:00
   ET. Inside either window, call the quotes endpoint with
   `fields=quote,extended` instead of falling back to close + cached
   spread. Outside both windows (and outside 9:30-16:00 regular hours),
   current close-basis fallback behavior is unchanged.
3. New spread-sanity threshold for the extended basis, separate constant
   from `MAX_PLAUSIBLE_SPREAD_PCT` -- value set from real sample data
   gathered during build, not assumed.
4. New TAPE reason code for `price_basis == "extended"` (mirrors
   `RC_USING_CLOSE_DATA`'s pattern from E5.005) -- CAUTION-tier, not BLOCK,
   consistent with E5.005's philosophy that off-regular-hours pricing is a
   caution, not a hard stop.
5. `last_spread_cache.py` unaffected -- this is a parallel basis, not a
   replacement; regular-hours live fetches still populate it as before,
   and the close-basis fallback (for windows outside all three: regular,
   pre-market, after-hours) still needs it.

## FOUND LIVE (2026-09-01)

**Symbol:** SPY, 06:53-06:57 ET (pre-market window). Ran `fetch-snapshot SPY`
against this WO's newly-built code -- result: `[ERROR] Could not fetch
extended-hours quote for SPY (pre_market). No file written.` on the most
liquid instrument that exists, which is not plausible as a real "no
market" read. TOS confirmed a genuine live two-sided market at the same
moment: B 762.85 / A 762.91, timestamp 06:55:53 ET.

Raw diagnostic dump (`_debug_raw_quote.py`, throwaway script,
`python\_debug_raw_quote.py`) of Schwab's `/marketdata/v1/quotes?symbols=SPY`
response confirmed the root cause -- the response carries TWO different
bid/ask sources, and this WO's build read the wrong one:

- `entry["extended"]`: `bidPrice: 0.0, askPrice: 0.0, quoteTime: 0`,
  `tradeTime: 1788249580000` -> **2026-09-01 03:59:40 ET** -- one minute
  before the 4:00 ET pre-market boundary. Frozen there; never refreshed
  since. This is the node `get_extended_quote_data()` was built to read,
  per this WO's original WHAT section (Schwab's own docs describe
  `fields=quote,extended` as covering pre-market/after-hours/overnight).
- `entry["quote"]`: `bidPrice: 762.86, askPrice: 762.92`,
  `bidTime: 1788260224020` / `askTime: 1788260225039` -> **06:57:04-05
  ET** -- live, matches TOS's real quote to the penny. Top-level response
  fields `"quoteType": "NBBO", "realtime": true` confirm this node is the
  continuously-updated one across sessions.

Conclusion: Schwab's dedicated `extended` field group does not behave as
documented for this account/endpoint (or only refreshes for a narrower
window than "pre-market/after-hours/overnight" suggests) -- it is stale,
not empty-market. The main `quote` node is already live through
pre-market. 2026-08-31's CME/SPGI/WFC bid=0.0/ask=0.0 read at 17:41 ET
(originally logged as "no active extended-session market" in the Bugs
row above) was very likely the same stale-node problem, not proof of
empty liquidity -- unconfirmed, since `_debug_raw_quote.py` didn't exist
that night to check the `quote` node in parallel. Worth a repeat sample
during today's after-hours window (16:00-20:00 ET) with the diagnostic
script to confirm this applies to after-hours too, not just pre-market.
