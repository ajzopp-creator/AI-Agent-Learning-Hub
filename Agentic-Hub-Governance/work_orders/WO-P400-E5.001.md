# WO-P400-E5.001 -- record Command Cannot Set/Override trade_mode (Paper Decided at Fill, Not Eval)

**Status:** OWNER_DONE (2026-07-29) -- PEH verify passed clean, see EXECUTION/VERIFY below
**Owner:** P_400
**Affects:** none -- internal P_400 only
**Depends On:** none
**Related:** WO-P400-E2.005 (original Paper Trade Mode build, --paper on evaluate/spec only); WO-P400-E2.019 (paper/real book routing); 2026-07-24 audit-book incident (8 SUBMITTED records found never tagged --paper at evaluate time -- same root symptom, different cause)

---

## WHY

Tony decides paper vs. real at the moment he places the fill, not at
evaluate/spec time -- confirmed 2026-07-29: "Paper is a decision I make
when I go to BUY. Only in new implementations of trade strategy do I know
beforehand. In months where I am making money I rarely do paper; in a
losing streak like now I rarely make live trades."

`record` (cli.py -> commands.cmd_record -> record_commands.cmd_record_submit)
has no mode parameter of its own. It reads `trade_mode` out of whatever
`evaluate`/`spec` cached earlier in `infrastructure/eval_cache.py` and
unpacks it unchanged into `write_p400_record(order_id=order_id,
**_strip_cache_only_keys(cached))`. If Tony didn't pass `--paper` to the
earlier evaluate/spec call -- which by his own description he usually
can't know to do yet -- the record writes REAL regardless of what actually
happened at the broker.

Live 2026-07-29: CPAY evaluated/specced without `--paper` (correctly, mode
wasn't decided yet), Tony filled it as a paper trade, and `record` had no
way to express that. Workaround used: re-ran `spec CPAY ... --paper` to
overwrite the eval_cache entry with `trade_mode=PAPER` before `record`
would pick it up correctly. Same underlying gap as the 2026-07-24
audit-book incident (8 records silently written REAL), but that fix
(audit-book) only detects the mismatch after the fact -- it doesn't give
Tony a way to state the mode at the one point in his workflow where he
actually knows it.

## Scope (proposed, not yet built)

| File | Layer | Change |
|---|---|---|
| cli.py | entry | `record` subparser gains `--paper` (`action="store_true"`, mirrors `evaluate`/`spec`); passed through to `cmd_record` |
| application/commands.py | application | `cmd_record()` gains `paper: bool = False` param, passed to `cmd_record_submit` (decline path unaffected -- mode is moot for a non-submitted signal) |
| application/record_commands.py | application | `cmd_record_submit()` gains `paper: bool = False`. When True, override `cached["trade_mode"]` to PAPER before unpacking into `write_p400_record()` -- do not require a prior `--paper` on evaluate/spec, and do not mutate the eval_cache file itself (override is call-scoped, not persisted) |
| infrastructure/record_writer.py | infrastructure | Confirm `write_p400_record()`'s existing routing (status label, `P400\` vs `P400\paper\` folder, `schema_name`) responds correctly to an overridden `trade_mode` value, not just the original cached one -- likely no change needed if it already keys off the kwarg rather than re-reading eval_cache, but must be verified, not assumed |
| test_record_commands.py | tests | New case: cached `trade_mode=REAL` (or absent), `cmd_record_submit(..., paper=True)` -- confirms written record shows `PAPER` and routes to the paper folder without touching the eval_cache file |

**Explicitly out of scope:** no change to `evaluate`/`spec`'s existing
`--paper`/`--paper-session` flags or `_resolve_mode()` -- those stay as
the early-decision path for the (less common, per Tony) cases where he
does know the mode going in.

handed (`"P400_PAPER" if trade_mode_value == "PAPER" else "P400"`), not
off eval_cache or anything cached elsewhere. Verified by reading the file,
not assumed.
