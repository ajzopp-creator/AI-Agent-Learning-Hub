## WHY

Found live 2026-07-26 running CAE (P_300 signal) through Tier-2B. `fetch-snapshot`
returned bid=22.60, ask=27.28 on a stock trading at 25.20 -- a $4.68 spread
(18.6% of price) on a name averaging 624k shares/day, where a real spread
should be pennies. `application\evaluate_signal.py` computes
`half_spread = (ask - bid) / 2` unconditionally and feeds it straight into
`domain\sizing.py`'s `realistic_fill_rr()` with no sanity check on spread
width anywhere in between.

Result: half_spread ~= $2.34 corrupted the realistic-fill R:R math, producing
R:R = -1.00. QUANT correctly BLOCKed given that input (RR_BELOW_MIN) -- but
the number itself is nonsensical, and the underlying data question (why is
Schwab returning that spread) went unexamined until Tony caught the
contradiction between the BLOCK message's own numbers (T1=26.86 vs a
"needs >= 26.57" threshold that T1 clearly clears -- that threshold is built
from raw, non-spread-adjusted entry/stop inside council.py's own message
construction, so it never saw the bad spread at all).

This is not a council.py or sizing.py logic bug -- both did exactly what
they're built to do with the input they received. The gap is that nothing
between the Schwab fetch and the R:R math checks whether a spread is
plausible before it's allowed to shape a Council-blocking number. Options
viability already has this exact pattern (`domain\options_council.py`
SPREAD_TOO_WIDE gate, spread <= 10% of mid) -- the stock side has no
equivalent.

A bad spread reading could just as easily produce a false PASS in the
opposite direction (e.g., if bid/ask were corrupted narrow instead of wide,
or entry and target both shifted the same direction by the spread
adjustment). This WO is about the missing guardrail generally, not just the
CAE false-negative-that-happened-to-be-safe.

## Root Question -- DECIDED 2026-07-26

Tony's call: hard BLOCK, mirroring options' SPREAD_TOO_WIDE exactly (no
override path, "fill quality unacceptable" is unconditional). Reproduced
twice live same session (CAE, CDPYF) before the decision -- not a one-off.
