# WO-P300-E?.001 ? Stop Calibration: Guideline Stops Consistently Tighter Than 1x ATR

**Status:** CLOSED
**Owner:** P_300
**Affects:** P_400 (Quant gate STOP_TOO_TIGHT blocks)
**Depends On:** None
**Acks:** N/A

---

## WHY

Across the full 2026-06-15 session, P_300 guideline stops are consistently
tighter than 1x ATR(14) on nearly every signal evaluated. This causes the
P_400 Quant gate to block otherwise valid setups with STOP_TOO_TIGHT before
they reach the Council.

Examples from 2026-06-15:
  CARG:  stop distance $0.37 vs ATR $1.13 (0.33x ATR)
  DIS:   stop distance $1.63 vs ATR $2.06 (0.79x ATR)
  FMCC:  stop distance $0.11 vs ATR $0.41 (0.27x ATR)
  MSTR:  stop distance $9.73 vs ATR $9.73 (exact -- marginal)
  CRK:   stop distance $0.58 vs ATR $0.60 (0.97x ATR -- barely under)
  SGML:  stop distance $0.67 vs ATR $0.85 (0.79x ATR)
  BEKE:  stop distance $0.60 vs ATR $0.56 (passed -- but close)

P_300 stops are set to pattern analog technical levels, not ATR multiples.
This is by design for P_300 but creates a systematic conflict with P_400's
1x ATR minimum stop requirement.

---

## QUESTION TO RESOLVE

Does P_300's stop calculation need to:

A) Floor stops at 1x ATR minimum (widen to structure if tighter than ATR)
B) Emit both a technical stop AND an ATR-adjusted stop in the packet so
   P_400 can use the wider of the two
C) No change to P_300 -- P_400 Quant gate should use guideline_stop as-is
   and only block if stop is below a different threshold (e.g. 0.5x ATR)

Recommendation: Option B -- P_300 adds atr_adjusted_stop field to the
signal packet. P_400 uses it as guideline_stop_override when present.
This preserves P_300's technical stop for reference while giving P_400
a tradeable stop that clears the Quant gate.

---

## ACCEPTANCE CRITERIA

- P_300 signal packets include atr_adjusted_stop = max(technical_stop, entry - 1x ATR)
- P_400 evaluate_signal uses atr_adjusted_stop as guideline_stop_override when present
- STOP_TOO_TIGHT blocks drop materially on next full session run
- Technical stop preserved in packet for audit trail
