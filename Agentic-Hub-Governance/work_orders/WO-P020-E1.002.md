## WHY

Tony is planning to go live with multi-leg spread trades soon (he already
trades them regularly on paper -- 4-leg iron condors on SPY, not simple
verticals). Current code cannot represent them correctly.

**Confirmed affected file:** `python\parsers\P_020_TOS_Parser_v2.4.py` --
this is the live/active parser (last touched 2026-07-05, matching the most
recent paper `AccountStatement.csv` pull). It produces the `_OPTIONS_IMPORT.csv`
file that `infrastructure/paper_csv_reader.py` reads. **Do not confuse with**
the several older/archived copies sitting in the same folder:
`old_P_020_TOS_Parser_v2.py`, `P_020_TOS_Parser_v2.2.py`,
`P_020_TOS_Parser_v2.3.py` -- none of these are live.

`infrastructure/schwab_mapper.py` (Schwab API JSON `transferItems`, the
live-account pipeline) has its own, separate single-leg-only limitation
(`_extract_instrument()` returns only the first non-CURRENCY leg) -- this
is real and will need its own fix before live spreads can be traded, but
it is untouched by paper validation and **out of scope for this WO**. See
OUT OF SCOPE.

**Evidence the drop is silent, not just untested:** A real 4-leg iron
condor trade exists in the raw paper `AccountStatement.csv` (two TOS
orders, REF #5281971043 open / REF #5284552756 close -- see ACCEPTANCE
CRITERIA for the full detail). It does not appear in:
- The audit log (`*_AUDIT_LOG.csv`) -- zero mention, not even a "skipped" note
- The processed `_OPTIONS_IMPORT.csv` -- zero rows
- The `trades` table -- zero rows (confirmed via direct query, PAPER
  account, SPY, all dates)

The trade simply never existed anywhere downstream of the raw CSV. TOS
Account Statement CSV represents a multi-leg order as one line:
`BOT +1 1/-1/1/-1 CUSTOM SPY 100 20 FEB 26/20 FEB 26/20 FEB 26/20 FEB 26
665/675/705/695 CALL/CALL/PUT/PUT @14.45` -- ratio-per-leg, strikes, and
put/call all packed into slash-delimited groups in a single description
string. The parser's line-matching logic (built for single-symbol
`BOT +N SYMBOL ... @price` lines) does not recognize this format at all
and silently skips it -- not a "first leg only" bug like `schwab_mapper.py`
has; here it's a "whole order invisible" bug.

The `trades` table schema already accepts `asset_type = 'spread'`
(CHECK constraint exists), but no code path currently produces it.

## SCOPE

1. **Design first, before code.** Schema decision already made (2026-07-26):
   leg detail lives in a new `spread_legs` child table, mirroring the
   `exits` pattern:
   ```sql
   CREATE TABLE spread_legs (
       leg_id           INTEGER PRIMARY KEY AUTOINCREMENT,
       trade_id         INTEGER NOT NULL REFERENCES trades(trade_id),
       leg_number       INTEGER NOT NULL,
       full_symbol      TEXT NOT NULL,
       put_call         TEXT,
       position_effect  TEXT NOT NULL,
       direction        TEXT NOT NULL,
       qty              REAL NOT NULL,
       price            REAL NOT NULL,
       created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
   );
   ```
   Still open: exact regex/parsing strategy for the packed
   `ratio/ratio/.../CUSTOM SYMBOL .../.../strike/strike/.../CALL/CALL/...`
   description format -- needs a short session against real examples
   before coding (this WO now has two: a clean one and a messy one, see
   ACCEPTANCE CRITERIA).

2. Detect multi-leg CUSTOM/COMBO orders in `P_020_TOS_Parser_v2.4.py` --
   the description string's leg count (from the ratio group, e.g.
   `1/-1/1/-1` = 4 legs) instead of the current single-symbol line match
   that silently skips anything it doesn't recognize.

3. Compute net entry_price (debit) / exit_price (credit) directly from the
   `@price` already present in the TOS line (this is already the net
   figure for the whole combo -- no need to sum individual legs); set
   `asset_type = 'spread'`. Parse the slash-delimited groups into
   individual `spread_legs` rows (strike, put/call, ratio/direction each).

4. Validate exclusively against PAPER account pulls first. Hard gate in
   code: spread detection only activates for `account_id = 'PAPER'` until
   Tony has reviewed real output against what TOS shows for the same
   trades.

5. Remove the live gate only on Tony's explicit confirmation after paper
   validation -- not bundled into this WO's completion. Live-account
   support requires a *separate* fix to `schwab_mapper.py`'s
   `_extract_instrument()` (different file, different bug shape, different
   input format) -- track as a follow-on WO once this one closes, not
   folded in here.
