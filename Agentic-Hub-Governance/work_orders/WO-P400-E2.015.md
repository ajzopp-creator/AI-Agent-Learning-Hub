**Title:** cli.py evaluate archives signal packet from inbox on invocation, requiring manual zip restoration before re-run/spec can proceed.

**Description:**
`cli.py evaluate SYMBOL` moves/archives the corresponding inbox signal packet
(`*_v2.0.json`) into `signals\processed\<MMYY>_ProcessedJson.zip` as a side effect
of running -- independent of verdict (BLOCKED or otherwise; verdict not confirmed
on this occurrence). This breaks any re-run, retry after a transport/timeout
failure, or `cli.py spec SYMBOL` call that expects the packet still in the inbox.

**Occurrence log:**
- Observed 3x previously (informal, not filed)
- 4th occurrence: 2026-06-23, INSW. Windows-MCP transport timeout on the first
  evaluate call (no result returned to Claude) -- but the underlying process
  completed on the host and archived `2026-06-23_INSW_v2.0.json` into
  `2606_ProcessedJson.zip`. No P400 record was found written for INSW (book and
  recent-file scan both empty), so verdict from that run is unconfirmed -- record
  write may not have completed, or archiving happens before verdict logic runs.
  Packet manually restored from zip to inbox for this session.

**Suspected root cause:** archive-on-invoke step in evaluate's call path is not
gated on verdict and/or not gated on confirmed record-write completion.

**Fix direction (not yet scoped):** archive step should fire only after a
verdict is reached AND the corresponding record (BLOCKED or APPROVED path) is
confirmed written. Until fixed: after any evaluate call that times out on the
MCP side, check `signals\processed\<MMYY>_ProcessedJson.zip` for the packet
before assuming "no packet" and restore before re-running.

**Verification:** pending code review of evaluate_signal.py / screen.py archive
call site.

**RESOLUTION (2026-06-30):** Root cause confirmed -- `archive_packet()` was
called inside `evaluate_signal.py` (domain/application reconciliation
logic), decoupled from whether any downstream vault-record write later
succeeded or failed. config.py's own comment documented the *intended*
design ("After evaluate_signal() completes, the source JSON is appended...")
-- implementation had drifted from that intent.

Fix: removed both archive_packet() call sites from evaluate_signal.py
entirely; added single call sites at the true end of cli.py's cmd_evaluate()
(after all record-write attempts: stock BLOCKED, options, spread) and
cmd_spec() (after spec render) -- matching config.py's documented intent.
This pushed cli.py to 301 lines (over the 300 cap); split into
application\commands.py (cmd_* implementations, 220 lines) + cli.py
(argparse/main() only, 90 lines).

Live-verified: real evaluate run now shows the P400 record write (or
BLOCKED-write) printing BEFORE the archive log line, confirming reordering
took effect, not just passing tests. All 10 existing tests
(test_evaluate_signal.py, test_e2003.py) green after both the archive
move and the file split. No archive-timing-related test existed before
this fix (gap noted, not filled this session).
