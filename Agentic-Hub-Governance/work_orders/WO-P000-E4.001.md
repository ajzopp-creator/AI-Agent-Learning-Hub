## WHY

windows-mcp's PowerShell/Python transport has a hard ~4-minute timeout ceiling
that is not tunable from the session level. peh-handoff already documents this
firing on roughly 9 of 10 Python subprocess calls. P_300 SIP v3.1 Steps 5b
(catalog-summary) and 5c (LM Studio readiness check) both invoke Python via
windows-mcp:PowerShell from inside the live chat session -- exactly the call
shape that trips the ceiling. Every INIT run carries a near-certain stall risk
on two steps that produce small, predictable outputs.

Separately, session header format is not consistent Hub-wide. P_300's SIP v3.1
already specifies `[Project_ID] [Day], [Month] [DD], [YYYY] -- [HH:MM] ET` as
its header. No other project has confirmed it follows the same line. This
WO adopts that format as the Hub standard rather than inventing a new one.

- Any INIT step that needs Python output is moved out of the chat-session
  execution path entirely, using the same operating model already proven for
  P300AddPattern.bat and P300DailyEvalv2.bat -- run outside Claude, on Tony's
  own schedule.
- Pilot file: `C:\Users\Trader\AI-Agent-Learning-Hub\projects\P_300_Vantage_Point_Pattern_Recognition\P300_Preflight.bat`
  Runs catalog-summary and the LM Studio readiness check, writes results plus
  a timestamp to:
  `C:\Users\Trader\AI-Agent-Learning-Hub\projects\P_300_Vantage_Point_Pattern_Recognition\P_300_preflight_status.json`
- P_300 SIP v3.1 Steps 5b and 5c are rewritten to read that JSON via
  windows-mcp:FileSystem (mode=read) instead of invoking python via
  windows-mcp:PowerShell. No Python subprocess call remains inside INIT.
- Staleness rule: if the JSON timestamp is older than the last session close,
  INIT displays WARNING and asks Tony to re-run the bat -- same HALT/reconcile
  posture as today, triggered by a stale timestamp instead of a subprocess
  timeout. Exact threshold to be fixed during the P_300 implementation session.
- Once proven on P_300, the identical pattern is the default for any Python-
  dependent INIT step in P_115, P_116, P_117, P_118, P_400, or P_800.

### 2. Session Header Standardization (REVISED 2026-06-18)

- Canonical format, Hub-wide, every project, every session:
  `[Project_ID] [Day], [Month] [DD], [YYYY] [HH:MM] ET [optional session-type label]`
  Example (no label): `P_300 Wednesday, June 17, 2026 14:32 ET`
  Example (with label): `P_115 Thursday, June 18, 2026 07:50 ET Market Analysis`
- Original 2026-06-17 draft mandated a `--` separator and no trailing label,
  copied as-is from P_300. Revised after auditing P_115's live SIP
  (`SESSION_INITIALIZATION_PROMPT.md` v3.2): P_115's header has carried a
  trailing session-type label since v2.7 (2026-02-11) -- predates this WO and
  is genuinely load-bearing for distinguishing parallel sessions across
  Tony's multi-window setup. Rather than strip a working, older pattern to
  match a newer one chosen somewhat arbitrarily, the standard widened: `--`
  is no longer required, and a trailing label is explicitly permitted.
- P_300 updated to drop its `--` for consistency with the revised standard
  (see P_300 SIP changelog).
- P_115 audited: COMPLIANT under the revised standard, no change required.
- P_000 continues auditing P_116/117/118/400/800 INIT/SIP docs against the
  revised line; patch directly (trivial mismatch) or log a follow-on WO
  (non-trivial mismatch).
- Canonical format recorded in P_000_SYSTEM_DOCUMENTATION.md (Document Index
  or Standards section) so future projects inherit it by default.
