## WHY

P_805's KB mode (`--kb-mode summary|full`) writes email-newsletter-derived
notes via `write_to_vault("KB", {...})` into the same `KnowledgeBase\`
folder as Tony's manually-clipped research articles (Web Clipper output),
using the same `KB_Articles` schema and the same `KB_Articles.base`. Only
the `origin` field (`Email` vs `Web Clipper` etc.) distinguishes them --
nothing in the folder structure separates them, so newsletter notes and
research clippings would interleave by date. Confirmed live 2026-09-06
(Obsidian screenshot: a One Click Trading web-clipped guide sitting in
the same list a P_805 KB note would land in). Tony flagged this as
unwanted mixing in a P_805 session the same day.

## DECISIONS (2026-09-06)

1. Split by `origin` into two subfolders under `KnowledgeBase\`:
   `KnowledgeBase\Newsletters\` for P_805 email-derived notes
   (`origin: Email`); `KnowledgeBase\` root stays for manually-clipped /
   researched material (Web Clipper, PDF, AI Summary, Manual origins).
2. **No migration needed.** Confirmed live 2026-09-06 that P_805 has
   written zero real KB notes to date -- `--kb-mode` has never been run
   against an actual `.eml` file, only against Web Clipper content from
   an unrelated source. Clean cutover, not a data migration.
3. **Resolved 2026-09-06, no `.base` change needed:** `KB_Articles.base`'s
   filter is `file.inFolder("KnowledgeBase")`. Confirmed against
   Obsidian's own documentation/forum that `inFolder()` matches nested
   subfolders, so `Newsletters\` notes appear in the existing Base
   automatically. A second, separate `KB_Newsletters.base` was
   considered and not needed -- one Base already covers both.

**2026-09-06 (same day, P_805 session, live Windows-MCP access)** --
Criterion 4 closed out. Pulled a real message from an enabled sender
(`trading-protraderstrategies.com@shared1.ccsend.com`) out of the live
iCloud mbox via `mailbox.mbox()` (per P_805's mbox-reading standard --
never manual regex/seek), staged it as a standalone `.eml` in
`data\inbox\`, ran `cli.py --kb-mode full`.

First run FAILED validation: `KBRecord` requires `signal_date` and
`written_by` (neither auto-injected by `write_handler.py` -- it only
injects `run_date`/`run_ts`), but P_805's `build_kb_record()` only ever
set the deprecated `date` field and never set `written_by` at all. This
contradicts this WO's earlier "no P_805 code change expected" line --
one was needed. Every `--kb-mode` run to date would have hit this same
failure; it was never caught earlier because criterion 4 had never been
run against a real `.eml` until this session.

Fix: `application\p805_kb_writer.py` `build_kb_record()` now sets
`signal_date` (from the existing `mtime`, `.isoformat()`) and
`written_by: "P_805/kb_writer"` alongside the pre-existing `date` field.
Re-ran `--kb-mode full` against the same staged `.eml`: write succeeded,
note landed at `KnowledgeBase\Newsletters\2026-09-06_THE-EMAIL-47000-
TRADERS-READ-BEFORE-THE-.md` (confirmed via `Get-ChildItem` -- present in
`Newsletters\`, absent from `KnowledgeBase\` root), `.eml` deleted from
`data\inbox\` on success per design. All four acceptance criteria now
MET.

**Confirmed, end-to-end, all four Acceptance Criteria:**
- `config.py`: `KB_ORIGIN_SUBFOLDER_MAP = {"Email": "KnowledgeBase/Newsletters"}`
  is additive only -- `VAULT_FOLDER_MAP` and every other map in the file
  (`OUTPUT_FORMAT`, `JSON_FILENAME_SUFFIX`, `SCHEMA_VERSIONS`, `VERDICT_MAP`)

  branch checks `KB_ORIGIN_SUBFOLDER_MAP.get(data.get("origin"))` with an

  every other schema's branch (`P020`/`P115`/`P820`/`P300`/`P400`/
  `P400_PAPER`) untouched.

  `written_by` (`"P_805/kb_writer"`) are both set, matching the fix
  described in the Occurrence Log above.
- Decision 3 (no `.base` edit needed): independently re-confirmed against
  `help.obsidian.md/bases/functions` (not the forum post originally
  cited) -- `file.inFolder()` "Returns true if the file is in the
