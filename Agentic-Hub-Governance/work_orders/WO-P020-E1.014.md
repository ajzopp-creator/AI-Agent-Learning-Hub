# WO-P020-E1.014 -- Buying Power / Cash Available Silently Undated in P_000 Params File

**Status:** CLOSED -- Independent Review completed 2026-08-22, separate session from implementation. See Independent Review section below.
**Owner:** P_020
**Affects:** P_000 (file owner, reference numbers only, no code change), P_400 (reference consumer only, no code change)
**Depends On:** WO-P020-E1.009 (built the write path this WO adds a timestamp to)
**Related:** none

---

## WHY

`write_balance_to_p000_params()` (WO-P020-E1.009) overwrites the Buying Power
and Cash Available for Trading rows in `P_000_Account_Parameters_Current.md`
unconditionally, every time `cli.py balance --account AJZ` runs -- manual or
scheduled -- with no timestamp and no history log entry. The file's own
"Last Updated" header and Change Log are only touched by the separate,
threshold-gated `write_full_account_params()` (WO-P020-E1.011), which never
touches these two fields at all.

## FOUND LIVE -- 2026-08-19

A P_400 session's memory (dated informally to "Aug 4, 2026") carried Buying
Power as $39,296.76. The file on disk, header still reading "Last Updated:
August 04, 2026", showed $36,911.08. Traced to actual code, not assumed:
`grep`'d the full P_020 writer pipeline for "Last Updated" -- zero hits.
Confirmed `write_balance_to_p000_params()` never touches the header or
writes a history row; it only upserts the two value cells via
`upsert_active_parameter_rows()`. Both figures could have been genuinely
correct at different silent-write moments -- there is no way to tell which
one is current by reading the file, because the row's own timestamp doesn't
exist.

Separately confirmed Cash Available showing "N/A" is NOT a bug: Schwab
returns `None` for `cashAvailableForTrading` on this margin account
(documented in WO-P020-E1.009's own 2026-07-26 test note); the code
correctly writes "N/A" for that case by design.

## FIX -- 2026-08-19

`infrastructure/p000_params_writer.py`: `write_balance_to_p000_params()`
builds a `datetime.now()` timestamp and appends `" (pulled {ts})"` to both
the Buying Power and Cash Available for Trading value strings, so each cell
is self-dating instead of relying on a header that a different, unrelated
write path controls. Timestamp built from `.day`/`.hour`/`.minute` ints
directly (not `%-d`/`%-I` strftime flags), mirroring `write_full_account_params()`'s
existing platform-safe date formatting in the same file -- Windows `strftime`
doesn't support the Unix no-leading-zero flags.

**What did NOT change:** the underlying values themselves, the "N/A" logic,
`ensure_cash_note()`, or anything in `write_full_account_params()` / the
monthly-review path. Purely additive to the two existing value strings.

## ACCEPTANCE CRITERIA

  `balance --account AJZ` run. MET, 2026-08-20 -- Tony ran

  P_000_Account_Parameters_Current.md confirmed on disk:
  `| Buying Power | $39,260.34 (pulled Aug 20, 2026 10:32 PM) |` and
  `| Cash Available for Trading | $19,630.17 (pulled Aug 20, 2026 10:32 PM) |`.
- No change to `write_full_account_params()`'s threshold-gated behavior or
  the header/changelog it owns.
- Compile-clean under p140 warnings-as-errors.
- `tests/test_p000_params_writer.py` (new) covers: timestamp present in
  both fields; "N/A" case still tagged when a field is None; idempotent
  re-run overwrites rather than duplicating the row.
- Independent review confirms the fix in a separate session before CLOSED.
