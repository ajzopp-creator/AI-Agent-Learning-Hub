WHY:
The signal packet is a cross-project contract -- producers (P_115/P_300) -> router
(P_800) -> consumer (P_400). The canonical models (SignalV2 + SignalContext +
SignalMetadata) currently live inside P_800's domain layer
(obsidian_writers\domain\signal_schemas.py). Any consumer that imports them must
reach into P_800 internals, which breaks whenever P_800 reorganizes its tree
(it just did -- WO-P800-E3.001). A shared, neutral definition gives one source of
truth that neither project reaches into the other's package to use.

SCOPE:
  1. Move SignalContext, SignalMetadata, SignalV2 to
     shared_resources\python_utils\signal_schemas.py. Keep legacy P400SignalRecord
     there as well until the E2 dual-read cutover, then drop it with P400SIG.
  2. P_800 obsidian_writers\domain\signal_schemas.py becomes a thin re-export from
     the shared module. The facade (obsidian_writers.schemas) and SCHEMA_REGISTRY
     are unchanged -- no internal P_800 call site changes.
  3. Canonical consumer import documented:
     from shared_resources.python_utils.signal_schemas import SignalV2
  4. No behavior change to write/route. SIGNAL_V2 -> _v2.0.json and
     P400SIG -> _signal.json (legacy) remain exactly as today.

BLOCKED 2026-06-08 (P_800 session, E2.002 planning) -- import-resolvability finding

The prescribed consumer import "from shared_resources.python_utils.signal_schemas
import SignalV2" does NOT resolve under the current p140 editable install. The
editable finder maps exactly one top-level name -- hub_lib
(__editable__.hub_lib-0.1.0.pth; top_level.txt = hub_lib; pyproject
include = ["hub_lib*"]). shared_resources has no __init__.py and is neither a
mapped nor a namespace package. It is reachable today ONLY because
vault_interface.py does a runtime sys.path.insert of the P_800 python folder --
i.e. consumers reach the contract by going through P_800's runtime. Relocating
the models and calling that OWNER_DONE would encode the boundary violation E2 is
meant to remove (a layer reaching through another layer), and would repeat the E1
failure mode (passes a narrow path while the real import is broken).

Standing principle (operator, 2026-06-08): moving anything WITHIN a layer must
never affect any other layer. A neutral contract must resolve through the import
system, not a project sys.path side-channel.

RESOLUTION: shared_resources must become a real installed package first. That is
hub-wide install config = P_000 infrastructure (P_800 is read-only re other
projects, may not edit hub packaging). Authored WO-P000-E2.002 to do this.
