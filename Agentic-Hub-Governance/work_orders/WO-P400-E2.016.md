**Title:** Quant RR_BELOW_MIN message text does not disclose that the reported
R:R is spread-adjusted while the displayed "needs >=" required-target uses
clean (non-spread-adjusted) entry/stop -- message reads as self-contradictory
even though the underlying BLOCK is correct.

**Original misdiagnosis (struck through):** Initially filed as a suspected
variable-mismatch bug producing an incorrect R:R. RETRACTED after tracing
sizing.py realistic_fill_rr(). Verified by hand for INSW 2026-06-23:
  half_spread = (88.39-85.20)/2 = 1.595
  real_entry = 88.41+1.595 = 90.005 | real_target = 94.848-1.595 = 93.253
  risk = 90.005-85.191 = 4.814 | reward = 93.253-90.005 = 3.248
  R:R = 3.248/4.814 = 0.675 -- matches CLI-reported 0.68 exactly.
The BLOCK is correct: pre-market spread was ~half the full ATR, genuinely
collapsing realistic-fill R:R below 2.0. No sizing/council math defect.

**Actual issue (cosmetic):** council.py quant_vote()'s RC_RR_BELOW_MIN
reason_detail computes "needs >= {entry + reward_for_2x}" from the raw
entry/stop params (clean, pre-spread) while rr_at_t1 passed in was already
spread-adjusted upstream in evaluate_signal.py. Same message, two different
bases -- confusing on read, but the verdict it explains is sound.

**Fix direction (optional, not urgent):** either pass half_spread into
quant_vote() so the required-target display matches the spread-adjusted
basis, or relabel the message to clarify "(realistic-fill, spread-adjusted)"
vs "(clean/guideline)" so the two numbers in the sentence are visibly on the
same basis. No change recommended without Tony's review.

**Verification:** none needed for behavior -- behavior confirmed correct.
