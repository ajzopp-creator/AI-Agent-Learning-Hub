# WO-P400-E2.013 -- TAPE Role Double-Blocks on RC_ADVERSE_DRIFT When QUANT Already Covers R:R

**Status:** CLOSED
**Owner:** P_400
**Affects:** (none -- internal P_400 only; behavioral change to council output)
**Depends On:** None
**Acks:** N/A

---

## WHY

`tape_vote()` contained a BLOCK gate on `RC_ADVERSE_DRIFT`:

    if adverse_drift_pct > 0 and rr_after_drift < MIN_ACCEPTABLE_RR:
        return CouncilVote(role=Role.TAPE, decision=Decision.BLOCK, ...)

`quant_vote()` already blocks unconditionally when `rr_at_t1 < MIN_ACCEPTABLE_RR`.
When adverse drift collapses R:R below the minimum, both roles fired BLOCK --
producing two redundant BLOCK votes for the same underlying condition. QUANT owns
R:R math; TAPE's job is tape-reading (price freshness, market hours). The duplicate
block added noise to council output without any additional protective value.

Found during AEM evaluate on 2026-06-18: BLOCKED on QUANT (RC_RR_BELOW_MIN) and
TAPE (RC_ADVERSE_DRIFT), both pointing to the same R:R failure.

---

## FIX APPLIED

`domain/council.py` -- tape_vote(), adverse drift branch:
  BEFORE: decision=Decision.BLOCK
  AFTER:  decision=Decision.CAUTION

`test_council.py` -- test renamed and assertion updated:
  BEFORE: test_tape_blocks_adverse_drift / assert v.decision == Decision.BLOCK
  AFTER:  test_tape_caution_adverse_drift / assert v.decision == Decision.CAUTION

RC_ADVERSE_DRIFT reason code preserved -- still surfaces drift context in council
output. Change is BLOCK -> CAUTION only; QUANT still blocks when R:R < min.
