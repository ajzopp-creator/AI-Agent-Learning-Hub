--------------------------------------------------------------------------------
WHY
--------------------------------------------------------------------------------
`signal_horizon` is a required SIGNAL_V2 field (cli.py argparse,
`required=True`, no default) with no canonical source anywhere in the
codebase. "3-5 days" appeared in docstrings, CLAUDE.md, and the
architecture doc's cli.py example -- but was never a real default, config
value, or documented decision; it was a copy-pasted example that got
treated as a standard. 2026-08-17 session (P115-Monday-Aug17 "Mistaken
Emit Issue" chat) traced this: Tony didn't recognize the field, an
investigation found no source for "3-5 days" anywhere, and real trade
duration (CPAY ran ~11 trading days) supported "10-15 trading days"
instead -- Tony agreed to that value going forward. That agreement lived
only in chat history until 2026-08-18, when it was used stale again
(re-typed "3-5 days" from the doc) before being caught -- confirming the
root cause: no single source of truth, so every session either re-guesses
or re-reads a stale doc.
