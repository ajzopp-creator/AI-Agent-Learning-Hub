## WHY

Root cause investigation opened after a P_020 session reported checking
`Agentic-Hub-Governance\work_orders\` and finding it "empty for P_020,"
then finding the real WO under `04-Shared-Resources\work_orders\` instead.

Investigation found the junction itself was NOT broken -- both paths
resolved to the same 78 files at time of check. The P_020 session's
"empty" result was concluded to be a search-tool artifact (some file-search
methods don't traverse reparse points the way `Get-ChildItem` does), not a
structural fault. All four project INIT prompts checked (P_010, P_020,
P_115, P_400) already referenced the correct canonical path,
`Agentic-Hub-Governance\work_orders\` -- none referenced `04-Shared-Resources`
directly, so there was no init-prompt bug to fix.

However, `Agentic-Hub-Governance` was only ever a directory junction pointing
at the real folder `04-Shared-Resources` (created 2026-06-05 per
P_000_SYSTEM_DOCUMENTATION.md). Tony asked to eliminate the
`04-Shared-Resources` name entirely. Since the junction points FROM
`Agentic-Hub-Governance` TO `04-Shared-Resources`, simply deleting
`04-Shared-Resources` would have destroyed the governance ledger. Correct
fix: make `Agentic-Hub-Governance` the real folder and retire
`04-Shared-Resources` as a name entirely.
