# WO-P400-E5.005 -- Outside-Market-Hours Evaluation: Close-Priced Instead of Blocked

**Status:** CLOSED -- code built, both PEH verification passes GREEN (implementing session, 2026-08-10). Independently re-verified 2026-08-13 by a session that did not implement the fix, per WO_COMPLETION_GATE.md.
**Owner:** P_400
**Affects:** none -- internal P_400 only (council.py, schemas.py, fetch_snapshot.py, evaluate_signal.py + tests)
**Depends On:** None

## WHY

TAPE's `RC_MARKET_CLOSED` hard-BLOCKed every evaluate outside 9:30-16:00 ET
unless `pre_market_flag=True` -- but `pre_market_flag` was hardcoded `False`
in `evaluate_signal.py`, never wired to CLI or anywhere else. Effectively a
100% block outside regular hours, with a dead escape hatch. Original intent
(2026-07-27, Tony's call) was sound: Schwab's own docs say extended-hours
bid/ask are wider/less reliable, and the CAE 18.6%-spread incident is the
concrete case that drove the block. The block was solving a real data-
quality problem the wrong way -- by refusing to evaluate at all, rather
than sourcing more reliable data.

Tony's directive (2026-08-10): outside-hours evaluations should not be
blocked, and should use reliable data from the close instead.

## WHAT WAS BUILT

One rule, not a special case per closed-market scenario (after-hours,
pre-market, weekend, holiday all hit the same path): when
`is_market_open_now()` is False at snapshot time, skip the live quote
entirely and price off the most recent completed daily bar's close --
already fetched via `get_daily_bars()` for ATR, so no extra API call.

- `schemas.py`: `SnapshotDict` gets a new `price_basis: str = "live"`
  field (`"live"` | `"close"`).
- `fetch_snapshot.py`: branches on `is_market_open_now()`. Closed ->
  `price = bars[-1][2]` (last completed close), `bid = ask = price`
  (zero modeled spread -- a real printed close, not a live quote to
  model slippage against), `data_source="schwab_api_close"`,
  `price_basis="close"`. Open -> unchanged live-quote path,
  `price_basis="live"`.
- `council.py::tape_vote()`: dropped the dead `pre_market_flag` param,
  replaced with `price_basis`. Market closed + `price_basis=="close"` ->
  CAUTION (new `RC_USING_CLOSE_DATA`), not BLOCK. Market closed +
  `price_basis=="live"` (defensive only -- shouldn't occur once wired) ->
  still BLOCKs on `RC_MARKET_CLOSED`, same as before.
- `council_codes.py`: added `RC_USING_CLOSE_DATA`.
- `evaluate_signal.py`: `tape_vote()` call now passes
  `price_basis=snap.price_basis` instead of the dead `pre_market_flag=False`.

**Revised same day, 2026-08-10:** the zero-spread decision above was wrong
-- flagged by Tony directly ("why isn't this the rule when the market is
open too, and no synthetic spread"). Zero is itself a modeling choice (an
optimistic one), not "no spread" -- it gives close-priced evaluations a
free pass on friction that live evaluations pay for real, breaking the
"realistic fills" standard the rest of P_400 holds to. Fix: new
infrastructure/last_spread_cache.py persists each symbol's last observed
LIVE half-spread (written on every market-open fetch); the closed-market
path reads it back and reconstructs bid/ask as close +/- that real,
previously-observed half-spread. No cached spread for a symbol yet ->
fails loud, no file written (never fabricate) -- fetch that symbol live
at least once first. The CAUTION line (RC_USING_CLOSE_DATA) still fires
regardless -- it flags "this is close data", not "this has no spread
modeled" (those are separate facts now).
