## WHY

All three real ingest paths (Pipeline A `add-pattern`, bulk-scan merge,
`ingest-mined`) already check `(ticker, anchor_date)` for a collision --
but only at INSERT time, after Tony has already exported a VP grid and
run the ingest command. If it's a duplicate, the catalog stays untouched
and the error is clear, but the export work is already spent. No tool
today lets him check BEFORE pulling a chart whether a symbol/date is
already captured. Raised directly by Tony (2026-07-22) during a status
check on precheck coverage; filed rather than built immediately, per
plan-gate.

## SCOPE NOTE

- **Interface -- RESOLVED 2026-07-22 (Tony):** `--symbol X` listing
  mode, not an exact-date check. Show every anchor_date already
  captured for that ticker; Tony eyeballs it against whatever he's
  about to pull. No `--date` exact-match mode needed.
- **Bulk flexibility -- RESOLVED 2026-07-22 (Tony), input shape
  RESOLVED 2026-07-25 (Tony):** neither `bulk-extract` nor
  `P_300_RunBulkAddPattern.ps1` take a symbol-list CLI arg (both scan
  directories instead), so there was no existing shape to reuse.
  Tony's actual workflow: export "History Grid (SYMBOL).xlsx" files to
  `data/live/` manually, then wants to check all of them at once before
  deciding whether to run a bulk pattern export. Final design: default
  mode (no `--symbol`) scans `config.DATA_LIVE` for
  `History Grid (SYMBOL).xlsx` files and checks every ticker found;
  `--symbol` (comma-separated, e.g. `AAPL,MSFT`) remains available as
  an explicit override for an ad-hoc check with nothing exported yet.
- **Match semantics.** Kept exact-list-only (no fuzzy/near-duplicate
  detection), matching `pattern_exists_for_ticker_anchor()`'s own
  philosophy -- not introduced tolerance-window matching. Not revisited
  during build; stays a human decision per that function's own
  docstring rule.
- **Which catalog.** Defaults to `get_latest_catalog()`, `--catalog`
  override -- same pattern as `catalog-summary`/`inspect-pattern`.
