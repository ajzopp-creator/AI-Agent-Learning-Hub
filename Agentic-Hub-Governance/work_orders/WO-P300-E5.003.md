# WO-P300-E5.003 -- Pre-Export Pattern Lookup (check-pattern CLI command)

**Status:** PENDING (not planned, not built)
**Owner:** P_300
**Affects:** `python/cli_commands/` (new subcommand, likely lands in
  `utility.py` alongside `catalog-summary`/`inspect-pattern` -- read-only,
  no pipeline role), `infrastructure/catalog_writer.py` (reuse
  `pattern_exists_for_ticker_anchor()`, do not re-derive the collision
  logic -- M-082 discipline). No domain/schema changes expected.
**Depends On:** None.
**Acks:** N/A

---

## WHY

All three real ingest paths (Pipeline A `add-pattern`, bulk-scan merge,
`ingest-mined`) already check `(ticker, anchor_date)` for a collision --
but only at INSERT time, after Tony has already exported a VP grid and
run the ingest command. If it's a duplicate, the catalog stays untouched
and the error is clear, but the export work is already spent. No tool
today lets him check BEFORE pulling a chart whether a symbol/date is
already captured. Raised directly by Tony (2026-07-22) during a status
check on precheck coverage; filed rather than built immediately, per
plan-gate.

## SCOPE NOTE

- **Interface -- RESOLVED 2026-07-22 (Tony):** `--symbol X` listing
  mode, not an exact-date check. Show every anchor_date already
  captured for that ticker; Tony eyeballs it against whatever he's
  about to pull. No `--date` exact-match mode needed.
- **Bulk flexibility -- RESOLVED 2026-07-22 (Tony):** needs to work
  for both a single symbol (before running single-pattern
  `add-pattern`) and multiple symbols at once (before a bulk
  extraction/bulk capture run). Single-symbol case is `--symbol X`.
  Multi-symbol case not yet designed -- options include `--symbol`
  repeated, a comma-separated list, or reading the same kind of
  symbol list bulk-extract already consumes (check what
  `P_300_BulkExtract.bat`/bulk_extract_pipeline.py takes as input and
  reuse that shape rather than inventing a new one). Decide at build
  time, not guessed here.
- **Match semantics.** The existing guard is deliberately exact-match
  only, no fuzzy/near-duplicate detection (`catalog_writer.py`'s own
  docstring is explicit about this -- stays a human decision). This tool
  should inherit that same philosophy by default, not introduce new
  tolerance-window matching on top of it -- but worth confirming that's
  still the right call for a *pre*-check specifically, since a near-miss
  (e.g. same symbol, date off by a day or two) might be exactly the kind
  of thing worth surfacing here even though the insert-time guard
  correctly leaves it exact.
- **Which catalog.** Default to `get_latest_catalog()` like every other
  read-only command, with a `--catalog` override for consistency
  (`catalog-summary`/`inspect-pattern` both already follow this pattern).
