--------------------------------------------------------------------------------
BACKGROUND
--------------------------------------------------------------------------------
MODEL_MAP in `hub_lib\hub_lib\model_manager.py` currently hardcodes `lmstudio` as
the provider for `local_fast` and `local_smart` tasks with no awareness of which
machine is running the code. On AJZSTRATEGIESLG (LG Gram), which has no LM Studio
tier (confirmed during the hardware-spec restructuring, 2026-08-15 -- integrated GPU only, no usable offload path),
calling either task attempts to hit `localhost:1234` and fails, since nothing is
listening there. This blocks any project from safely calling `local_*` tasks when
run on the LG, and will block any future secondary machine the same way.

--------------------------------------------------------------------------------
DESIGN REQUIREMENT -- CAPABILITY CHECK, NOT A HOSTNAME WHITELIST
--------------------------------------------------------------------------------
Don't hardcode "if hostname == AJZSTRATEGIESLG, use cloud." That requires a new
WO every time a machine is added or replaced. Instead: a small machine-capability
config (hostname -> has_local_llm bool) that both this code and
P_000_LLM_Model_Hardware_Spec.md's Machines table agree with. Adding a third
machine later is a one-line config change, not new routing logic.

Routing rule: when a `local_*` task is requested on a machine without local LLM
capability, silently substitute the matching `cloud_*` task and log at INFO level
that a substitution happened. Never fail with no signal. Calling code stays
unaware of hostname -- it asks for `local_smart`, it gets a working model back,
which provider served it is a routing-layer concern only.

--------------------------------------------------------------------------------
LAYER PLACEMENT
--------------------------------------------------------------------------------
Hostname/capability detection is an infrastructure concern -- reads a config or
system value, no business logic, matches the LM Studio status check precedent
(WO-P300 -- moved out of application into infrastructure/lm_studio_status.py for
the same reason). Should not live inline inside model_manager.py's routing
function if that function already mixes routing logic with lookups.
