## WHY

Phase 1.5 (architecture doc Section 2.3, component C2) calls for Schwab API
as the live-data source, replacing the current web-fetch/manual-transcription
fallback. The hard part -- OAuth, browser-based re-auth, token refresh -- is
already built and live-tested in P_020 (`python\api\P_020_Schwab_Auth.py`,
`P_020_Schwab_Token_Manager.py`, using the `schwab-py` library). Rather than
build this from scratch or fork P_020's files, this WO generalizes that
pattern into a hub-shared module so both projects can call one
implementation with different config/token paths.

P_400 gets its own token file rather than sharing P_020's -- `schwab-py`
rewrites the token file on every refresh; two projects touching the same
file risks a race if both run near-simultaneously. One Schwab Developer
app registration covers both (`app_key`/`app_secret` reused, not
re-registered).

- Any market-data endpoint (quotes, price history, option chains) -- that's
  WO-P400-E4.002. This WO is authentication only.

  auth -- not unit-testable). Verification is a manual run, see below.

## DESIGN CHANGE -- 2026-07-24 (same session, after Execution Log above)

Tony's call: app_key/app_secret should live in exactly one place, not
duplicated across P_020 and P_400 -- one credential, one place to rotate
or secure it. Originally built with a separate P_400-local
`P_400_schwab_config.json` (per the WO's original SCOPE table); changed to
point `SCHWAB_CONFIG_PATH` directly at P_020's existing config file instead.

- `python\config.py`: `SCHWAB_CONFIG_PATH` now resolves to
  `projects\P_020_AJZStrategies_PerformanceAnalysisSystem\config\P_020_schwab_config.json`
  (cross-project reference, documented per python-project-architecture
  skill's Cross-Project File Access rule -- path confirmed via
  p020-project-context skill + direct file read, not guessed)
- `SCHWAB_TOKEN_PATH` unchanged -- stays P_400-local
  (`config\P_400_schwab_token.json`). Token file must not be shared
  (schwab-py rewrites it on every refresh; race risk if both projects
  run near-simultaneously) -- this was the one hard constraint, everything
  else was a preference call
- P_020 untouched -- no P_020 file modified, its Saturday weekly job
  unaffected, satisfies the WO's original Out-of-Scope boundary
- `config\P_400_schwab_config.json` (the placeholder created in the
  original Execution Log) is now dead/unreferenced -- left in place,
  not deleted, Tony's call whether to remove it later
- PEH-verified: SCHWAB_CONFIG_PATH resolves to an existing file with
  non-empty app_key/app_secret, SCHWAB_TOKEN_PATH still correctly
  P_400-local, schwab_client.py imports clean. PASS.

Trade-off flagged to Tony before making this change: a future path change
inside P_020 (e.g. another folder-name drift like the D_130->P_110 or
TradeManagement renames already in the Hub's history) would break P_400's
Schwab auth too, silently, since nothing currently guards against it.
Accepted as the right trade-off for one-credential/one-place.

**Acceptance criteria updated:** "P_400 has its own token file" still
holds (token stays separate). The config-file independence criterion from
the original WO text no longer applies -- superseded by this design change.
