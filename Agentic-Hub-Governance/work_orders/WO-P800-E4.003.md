# WO-P800-E4.003 -- Deprecated Pydantic `class Config` in signal_schemas.py

**Status:** PENDING
**Owner:** P_800
**Affects:** P_400, P_300, P_115 (and any other consumer importing
  `shared_resources\python_utils\signal_schemas.py::SignalV2`) --
  read-only impact, a warning not a behavior change; no action needed
  from those projects for this WO.
**Depends On:** none
**Related:** WO-P800-E2.002 (moved this file to its current shared-contract
  location); found 2026-08-08 in a P_400 session (WO-P400-E5.004) via a
  pytest warnings summary, unrelated to that WO's own work.

---

## WHY

`SignalV2` in `shared_resources\python_utils\signal_schemas.py` uses the
Pydantic v1-style nested `class Config: use_enum_values = True`, deprecated
since Pydantic v2.0 (`PydanticDeprecatedSince20`) in favor of
`model_config = ConfigDict(use_enum_values=True)`. Fires as a warning on
every import across every consuming project's test suite. Not a failure,
not urgent -- v2 still supports it -- but real drift against the library's
current API, and it's Hub-wide shared-contract code, not something a
consuming project should patch inline.

## SCOPE

1. In `signal_schemas.py`, replace:
   ```python
   class Config:
       use_enum_values = True
   ```
   with:
   ```python
   model_config = ConfigDict(use_enum_values=True)
   ```
   on `SignalV2`. Add `ConfigDict` to the existing
   `from pydantic import ...` import line.
2. Check `P400SignalRecord` and any other model in this file for the same
   pattern -- only `SignalV2` was confirmed at filing time, but the file
   wasn't fully audited for this specific pattern.
3. Re-run each consuming project's test suite (P_400 confirmed easiest --
   `pytest` from `python\` with no warnings in the summary is the pass
   condition) to confirm the warning is gone and `use_enum_values`
   behavior is unchanged (SignalV2 packets still deserialize
   asset_class/option_type as plain strings, not Enum members --
   `_check_asset_class_fields()` depends on that).

## OUT OF SCOPE

- Any other deprecation warnings in this file or elsewhere in
  `shared_resources\` -- this WO is scoped to the one warning found.
- The stray `.bak`/`_backup_` files sitting alongside this one in
  `shared_resources\python_utils\` (`signal_schemas.py.bak_pre_rename_2026-06-11`,
  `vault_interface.py.bak_pre_syspath_2026-06-11`,
  `xml_parser_backup_2026-06-30.py`) -- noticed in passing while filing
  this, not evaluated, not this WO's concern.

## ACCEPTANCE CRITERIA

- `signal_schemas.py` contains no `class Config:` block.
- A fresh `pytest` run in at least P_400's suite shows zero
  `PydanticDeprecatedSince20` warnings.
- `SignalV2`'s asset_class/option_type still behave as plain strings
  post-change (existing tests in each consuming project's suite covering
  `SignalV2` validation continue to pass unmodified).
