## Background

Surfaced 2026-09-21 in a P_115 session that started as a formatting cleanup of `P_115_BuytheDipTradingSystem\tasks\lessons.md` (blank-line spacing normalized, no content changed -- that fix already landed, unrelated to this WO). Tony then asked for something bigger: a hub-wide lessons repository, not a per-project silo, that is extremely fast -- quick access to an index, with large lesson text retrieved only when actually needed -- and supplemented by each project's own skill file, in his words "to make it a superpower."

A design was sketched in that chat as a starting point, not a decision: an `INDEX.md` summary table (one row per lesson, tagged, with a Related column linking recurrence pairs -- e.g. an original mistake linked forward to its later repeat) plus one file per lesson under a `tasks\lessons\` folder, using P_115's existing tasks\lessons.md (14 entries, 2026-06-09 to 2026-09-21) as source material for the split. Tony redirected to hub-wide scope before confirming that specific structure, so it is not binding.

## What This WO Would Need to Decide, Once Prioritized

- **Storage shape:** index + per-lesson files (as sketched) vs. some other structure that hits the "fast index, full text on demand" requirement.
- **ID scheme** for entries -- sequence letter (a/b/c), sequence number, or topic slug; left open at scope-change time.
- **Where the hub-wide index physically lives** (under Agentic-Hub-Governance\ or elsewhere) so any project's session can reach it regardless of which project is active.
- **Hook-in mechanism:** how each project's own SKILL.md "supplements" the shared repository -- e.g. a project-specific tag/filter into the shared index, vs. each project keeping a thin pointer file. Not yet decided.
- **Migration path** for existing per-project lessons files (P_115's tasks\lessons.md today; any equivalents elsewhere in the Hub) into the new structure without losing entries.
- **Retrieval pattern:** index-only read at INIT (cheap, per the speed requirement) vs. opening one lesson file mid-session when a tag matches the task at hand.

None of this is decided yet -- this WO is a placeholder for the scope, not the scope itself.
