WHY:
P_300's P_300_RunChaikinBatch.ps1 is coupled to two things that don't generalize: parsing
P_300_DailyEval_Messages.txt for "SIGNAL REPORT ... BUY|WATCH" lines, and a hand-built
{DATE}_{TICKER}.md path inside the LLM prompt itself (with a fallback-day caveat baked into
the prompt text, because P_300's anchor date commonly lags the run date). Tony needs the same
enrichment step for P_115 now, and eventually any project whose signals feed P_400.

Neither coupling is necessary. Every vault note already carries a normalized write_route field
(BUY/WATCH/PASS) in frontmatter -- P_800's own VERDICT_MAP guarantees this across P115/P300/P400
(confirmed live: 2026-07-24_PH.md has write_route: BUY, 2026-07-21_CIFR.md has write_route: BUY).
obsidian_writers.config.VAULT_FOLDER_MAP already knows which vault folder belongs to which schema.
So one schema-driven scanner replaces every project's own log-parsing logic: glob the schema's
vault folder over a lookback window, read write_route from frontmatter, skip any note that
already has a "## Chaikin Power Gauge" section (idempotency -- 2026-07-21_CIFR.md already carries
one, proving the check is required on re-runs). This also eliminates the old prompt's date-fallback
guesswork entirely, since Python resolves the exact note path before the prompt is ever built.

SCOPE:
  1. shared_resources\chaikin_enrichment\config.py (~40 ln) -- SCHEMAS_ENABLED = ["P115", "P300"],
     LOOKBACK_DAYS, CHAIKIN_SECTION_HEADER = "## Chaikin Power Gauge". Imports VAULT_FOLDER_MAP /
     VAULT_ROOT from obsidian_writers.config -- no path duplication, no hardcoding.
  2. infrastructure\note_reader.py (~60 ln) -- read frontmatter from a note path; detect an
     existing Chaikin section.
  3. infrastructure\vault_scanner.py (~50 ln) -- glob a schema's vault folder over the lookback
     window (filenames are already signal_date-keyed per filename_builder.py, so no date-guessing
     needed).
  4. domain\candidate_filter.py (~40 ln) -- pure logic, no I/O: write_route in {BUY, WATCH} AND no
     existing Chaikin section -> candidate.
  5. application\run_chaikin_batch.py (~90 ln) -- CLI entry point (--schema arg): orchestrates
     scan -> filter -> builds the prompt from exact (symbol, note_path) pairs, writes it to a temp
     file for the PowerShell wrapper to read. Prints candidate count / exit code for the wrapper to
     branch on (0 candidates = no-op, matches today's "nothing to run" message).
  6. chaikin_prompt_template.txt -- generalized: takes the resolved (symbol, note_path) table
     directly instead of {DATE}/{SYMBOLS} placeholders; drops the old "note might be filed under
     the prior session" caveat since the path is no longer guessed.
  7. RunChaikinBatch.ps1 (Hub root, replaces P_300's copy) (~35 ln) -- -Schema param; same
     `claude auth status --text` guard and `claude -p $prompt --chrome` call as today, unchanged
     mechanism, now schema-parameterized instead of P_300-hardcoded.
