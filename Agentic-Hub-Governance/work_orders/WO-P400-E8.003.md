## WHY

Found live 2026-09-15 (NFLX): Tony manually found a liquid option contract
after batch-2b had already routed NFLX to STOCK (auto-picked option failed
the liquidity gate, OI=32 < 150 min). The signal packet was archived by
then, so `evaluate --options` -- the only tool that runs the real
risk-budget sizer + options council -- could not be re-run. Tony sized 4
contracts by eye off the stock price instead. Retroactive check with the
real sizer: risk budget (OFF regime) = $220.94, actual risk per contract
$89.60, Gate 1 (RISK) = 2 contracts. He was 62% over budget on a loser.

Root cause: `evaluate_options()` requires a live `SignalV2` packet, but
only uses three scalar values off it (symbol, guideline_stop,
guideline_target) -- everything else (chain, snapshot, posture, params)
already comes from elsewhere. The packet dependency is incidental, not
structural, and it's what blocks any packet-free re-evaluation.

Separately, Tony also wants a T1/T2 scale-out order structure (sell half
at T1, ride the rest to T2, or T2 alone when that's the only target that
makes sense) -- not currently possible; Pattern A/B render one target
only. The vault schema already has an unused `target_2` field (seen null
on every P400 record written today), so this isn't a new schema need,
just unwired rendering + sizing.

## Approach Taken (built 2026-09-15)

1. `evaluate_options()`: drop `packet: SignalV2` param, take
   `symbol/stock_stop/stock_target` directly. Existing caller
   (`commands.py`'s `cmd_evaluate --options` path) passes
   `packet.symbol/guideline_stop/guideline_target` -- zero behavior change
   for the live-packet path.
2. New `application\size_option_standalone.py`: packet-free entry point.
   Reads snapshot + chain the same way `evaluate_options()` always has,
   computes `stock_rr` internally from the same entry/stop/target already
   required (no extra input needed), runs the real sizer -> options
   council -> macro earnings gate, renders the spec, builds its own
   eval_cache fields (no fake packet/stock_result -- a dedicated
   field-builder sourced from what it actually has).
3. `build_option_spec()` gains optional `target_2`; delegates to new
   `build_option_spec_scaleout.py` when target_2 is set or target_1 is
   omitted. Two independent OCO brackets sharing one stop (TOS can't do
   1-triggers-2-OCO-groups natively), contracts split floor/remainder-to-
   T2. Single-target callers (existing `evaluate --options` path) see no
   change in output.
4. `cli.py` gains `size-option` subcommand wiring all of the above.
