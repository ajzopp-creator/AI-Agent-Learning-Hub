## WHY

`db_utils.get_latest_catalog()` deliberately returns `str` (`return
str(catalog_files[0])`), and `db_connect.py` is the correctly-shielded
"single choke point for all catalog access" for anything that wants a
`sqlite3.Connection` -- it works precisely because `sqlite3.connect()`
accepts a raw string, so the shield never has to reach for `Path`-
specific behavior.

The gap: nothing shields callers that need the catalog's actual
filesystem path as a first-class `Path` -- for `shutil.copy2()`,
`atomic_move()`'s `.exists()` check, or a typed dataclass field another
function reads later. `get_latest_catalog()` is the only way in for
that need, and its `str` return means every one of those callers must
remember `Path(get_latest_catalog())` by hand. M-089 fixed one
forgotten instance. M-095 found three more in one session -- two in
`catalog_merge_pipeline.py` (one of which crashed a REAL production
promote), one in `ingest_mined_pipeline.py` (latent, hadn't crashed yet
only because `shutil.copy2`/`load_full_catalog` happen to tolerate
`str`). A convention that has to be remembered correctly at every call
site, with no compiler/test enforcement until this session's manual
static-scan test, isn't a fix -- it's a recurring bug with the same
signature waiting for the next caller that forgets.

## PROPOSED FIX (not yet built)

Add a typed sibling function to `utilities/db_utils.py`:

```python
def get_latest_catalog_path() -> Path:
    """Path-typed sibling of get_latest_catalog(). Use this when the
    caller needs the filesystem path itself (file copy, atomic move,
    a Path-typed field) -- use get_latest_catalog() (str) only for
    sqlite3.connect()-style DB-connection callers, or better, use
    db_connect.py's connection_context()/get_connection() directly and
    skip path resolution entirely."""
    return Path(get_latest_catalog())
```

Then migrate the 3 sites M-095 already hand-fixed (`catalog_merge_
pipeline.py` x2, `ingest_mined_pipeline.py` x1) to call
`get_latest_catalog_path()` instead of `Path(get_latest_catalog())` --
functionally identical, but the correct-by-construction call reads the
same everywhere and can't silently regress to unwrapped again.

**Does NOT change `get_latest_catalog()`'s existing `str` contract or
touch any of its current callers** (`db_connect.py`, `catalog_summary.py`,
`inspect_pattern.py`, `preflight_status.py`, etc.) -- those are either
DB-connection callers (correctly using the str form) or already wrap it
themselves. This is additive, not a breaking change.

**Open question for build time:** should `test_get_latest_catalog_path_
safety.py` (M-095's static-scan regression test, `tests/`) be updated to
check for `get_latest_catalog_path()` usage instead of the `Path(get_
latest_catalog())` pattern once this migrates, or should it check for
BOTH (so a reversion to either the raw-unwrapped form OR the manual-wrap
form both still fail)? Leaning toward checking for the raw-unwrapped
form only being absent (simpler, catches the actual crash-causing
mistake either way) -- decide during build.
