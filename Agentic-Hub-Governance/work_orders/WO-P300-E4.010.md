## WHY

`P_300_RunAllDailyEvals.ps1` printed "All N evaluations complete"
unconditionally, regardless of whether the underlying per-symbol
`.bat` calls actually succeeded -- confirmed real on 2026-07-21 (a run
where LM Studio wasn't loaded, all 3 symbols failed with `[ERROR]
daily-evaluate failed`, and the wrapper still reported "complete").

Root cause traced one level deeper than "the wrapper doesn't check
exit codes": `P_300_DailyEval_v2.bat` itself correctly detects
failures internally (`if errorlevel 1 (...) goto :done`) but never
called `exit /b` at the end -- it just fell through `pause` and the
script ended. CMD's default exit code when a `.bat` runs to
completion without an explicit `exit` is 0, independent of any
internal `[ERROR]` path. This means `$LASTEXITCODE` in the wrapper was
NEVER going to be a trustworthy signal, no matter what the wrapper
itself checked -- the honest signal didn't exist at the source yet.

---

## WHAT WAS BUILT

**`P_300_DailyEval_v2.bat`:** added `set "EXIT_CODE=0"` near the top;
both `[ERROR]` paths (`daily-evaluate failed`, `archive-eval failed`)
now also `set "EXIT_CODE=1"` before their existing `goto :done`; the
very end now calls `exit /b %EXIT_CODE%` after `pause` (previously the
script just ended with no explicit exit at all). `set` and `goto`
together inside the same parenthesized `if errorlevel 1 (...)` block
is NOT the M-032 trap (that was about *reading* a variable in the same
block it was set in) -- `%EXIT_CODE%` is only read later, in a
separate top-level statement, well after the block has finished
executing.

**`P_300_RunAllDailyEvals.ps1`:** captures `$LASTEXITCODE` right after
each per-symbol `cmd /c` call (now meaningful, because of the .bat
fix -- not despite it). Tracks failed symbols in an array. Final
summary is now honest: "All N complete" only when true; otherwise a
loud red banner with the real succeeded/failed counts, the actual
failed symbol names, and an explicit note that failed symbols were not
archived and won't appear in the Chaikin batch (which pulls BUY/WATCH
tickers from the log's own `SIGNAL REPORT` lines -- a symbol that
never produced one is already correctly excluded there, no separate
fix needed for that part).

**Scope discipline:** No change to `daily-evaluate`/`archive-eval`
themselves, no change to the Chaikin step (that's WO-P300-E4.009,
already closed separately), no change to what counts as
success/failure -- only to whether that fact is actually reported.
