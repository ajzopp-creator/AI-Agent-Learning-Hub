## WHY

Discovered 2026-09-13 (P_020 session) reviewing the regenerated dashboard:
P_210 showed 4 open trades, $0.00 P&L, despite two spreads (NDXP puts opened
2026-09-09, NDXP calls opened 2026-09-11) that should have settled same day
-- Tony confirmed P_210 trades are same-day (0DTE) options.

Root cause: 0DTE options don't generate a closing BOT/SOLD transaction when
they expire -- there's nothing to trade, the position simply ceases to
exist at expiration. The ingestion pipeline only closes a trade when it
matches an explicit closing transaction, so these sit `open` indefinitely
with `exit_pnl` never recorded, even though the trade has definitively
settled and Schwab knows the outcome.

Confirmed via the raw pull JSON
(`data\api_pulls\ajz_strategies\P_020_raw_AJZ_Strategies_2026-09-05_to_2026-09-12_20260912_113950.json`):
no `EXPIRATION`-type transaction exists anywhere in the file (only
`TRADE`), but each option's `instrument` block carries its own
`expirationDate` and `closingPrice` fields independent of the transaction
list -- e.g. all 4 P_210 legs show `closingPrice: 0.0001` (Schwab's floor
value for expired-worthless) with `expirationDate` already past the pull
timestamp. That data already answers "what did this option settle at,"
just not in transaction-record shape.

## PROPOSED FIX (superseded by Acceptance Criteria + Files Built below -- kept as the original framing)

For any open trade where the option's `expirationDate` has passed and no
matching closing `TRADE` transaction exists in the pull: use the
instrument's `closingPrice` as a synthetic exit price and close the trade
via the normal `calculate_exit_pnl()` / `insert_exit()` /
`update_trade_status()` path -- same math the manual stopgap script uses,
just triggered automatically during ingestion instead of by hand.

This generalizes past "expired worthless" -- `closingPrice` also covers
ITM cash-settled expirations (a real nonzero settlement value), so the
same mechanism should handle both without a separate "worthless" special
case.

**Scope risk, flag before building:** this is only safe for cash-settled
instruments (NDXP and similar index options -- P_210's actual product).
American-style equity options can be exercised/assigned at expiration,
which creates a stock position rather than a cash close -- a naive
"closingPrice as exit" would misrepresent an assignment as a cash exit and
lose the resulting stock position entirely. Scope this WO to cash-settled
index options only; equity assignment/exercise handling is a different,
larger problem and should not be folded into this fix.
