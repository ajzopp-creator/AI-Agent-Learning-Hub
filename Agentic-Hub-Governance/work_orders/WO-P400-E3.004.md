## WHY

`domain\vehicle_selector.py` `compare_vehicles()` defines:
  option_viable = (contracts > 0 OR override_required) AND rr_valid

This means a single-leg option that sizes to 0 contracts under
Chart-Based/Risk-Budget-First gate math (Gate 1 risk-budget collapse) is
still flagged `option_viable=True` and can WIN the recommendation against
a fully-sized, budget-respecting stock trade purely on R:R comparison --
with no surfaced warning that the "winning" vehicle is not actually
executable without an explicit override.

Found live during ADBE evaluation, 2026-06-29, posture=OFF:
  205C 17JUL26, delta=0.5406, mid=7.95
  risk_per_contract = (mid - option_stop)*100 ~= $680
  adjusted_risk_budget (OFF, 50%) = $245.02
  Gate 1 -> 0 contracts -> override_required=True
  Stock: 3 shares, $37.77 risk, R:R 5.59 (fully viable, no override)
  Option: 0 contracts, R:R 5.61, $0.00 displayed dollar risk

  cli.py compare ADBE --snapshot snapshot_ADBE.json --chain chain_ADBE.json --cash 6351
  Output: "RECOMMENDATION: OPTION / Reason: Option R:R 5.61 >= stock R:R 5.59
  -- option preferred"

The recommendation line gives no indication the option requires an
override or that taking 1 contract would mean accepting ~2.8x the
account's posture-adjusted risk budget for this trade. A user trusting
the headline recommendation without reading the Size row closely could
act on an unexecutable/over-risk vehicle choice.

Secondary, lower-priority note from the same session: the chain_SYMBOL.json
template (Architecture v2.1 Section 7.3) does not document expected units
for the `iv` field. `options_sizer.py` computes `chain.iv * 100`, requiring
a 0-1 fraction (e.g. 0.4069), but the template's placeholder `"iv": 0.00`
gives no unit hint -- a manually-entered percentage value (40.69) silently
produces a nonsensical displayed IV (4069.0%) and falsely triggers the
IV-rank-50 spread-preference flag. No code defect (units, once known, are
applied correctly) -- doc/template clarity issue only.

Third note, same session, higher severity than the iv-units item: there is
NO CLI-wired path to write a validated P400 vault record for an
options/override trade at all. `build_option_spec.py` (WO-P400-E3.001
deliverable) exists in the codebase but is not connected to any cli.py
subcommand -- `compare` only prints a sizing table, `evaluate` does not
accept `--options`/`--chain` despite the architecture doc and SIP both
describing that flag combination as if it were live. There is also no
options-aware override-annotation path in the writer pipeline
(obsidian_writers / record_writer) -- the stock-only override path
(council_verdict=APPROVED_BY_OVERRIDE) has no options-sizing-fields
equivalent (option_method, option_override, option_override_justification
etc. per Architecture Section 7.3 / 6.3 P400Record additions) wired to
an actual write call.

Live impact: ADBE 215C 17JUL26 override-approved by Tony in-session
(exact override phrase given), 1 contract, $384 defined risk, no resting
option stop (delta-translated stop computed to $0.01, i.e. degenerate --
exit is manual on stock price through $192.23 per P_000 Options Rule, not
a placed stop order). This trade has NO corresponding vault record path
once Tony reports the order_id back. Claude flagged this live rather than
hand-crafting an out-of-schema Obsidian write.

## SCOPE

1. `domain\vehicle_selector.py` `compare_vehicles()` -- when `recommended`
   resolves to "OPTION" (or "SPREAD") via the override-required path
   (contracts==0, override_required==True), do not let it silently outrank
   a fully-viable stock trade on R:R alone. Either:
   (a) downgrade recommendation to require Tony's explicit confirmation
       when the winning vehicle needs an override, or
   (b) add a loud `requires_override` flag to the comparison output and
       prefix the recommendation reason with "OVERRIDE REQUIRED -- " when
       applicable.
2. `cli.py cmd_compare` / `_format_comparison()` -- surface override-required
   state in the RECOMMENDATION line itself, not only in the Size row.
3. `chain_SYMBOL.json` template (Architecture doc Section 7.3) -- add inline
   comment or rename field to clarify `iv` expects a 0-1 fraction (e.g.
   `"iv": 0.00  // decimal fraction, e.g. 0.41 for 41% IV -- NOT a percentage`).
4. `test_options_sizer.py` / new test in vehicle_selector test suite --
   assert recommendation does not silently prefer an override-required
   0-contract option over a fully-viable stock trade without flagging it.
5. Options/override write path -- wire `build_option_spec.py` into
   `cli.py` (a `spec SYMBOL --options --chain FILE` path, or fold into
   `compare` as an explicit "render spec" mode), AND extend the
   obsidian_writers record path to accept options fields + override
   annotation (option_method, option_contracts, option_override,
   option_override_justification, option_entry_premium,
   option_stop_premium, option_target_premium per Architecture 6.3) so
   an options trade -- overridden or not -- has a real, schema-validated
   path to a written P400 record, matching what the stock path already
   has via `handle_write()`.

## OUT OF SCOPE

- Changing the override-required definition itself (Section 7.3 exception
  path is correct as designed -- 0 contracts requiring an explicit override
  is the intended behavior). This WO is about recommendation-display
  clarity only, not sizing logic.
- Re-running the ADBE trade under this WO -- Tony decides stock vs. override
  vs. alternate strike in-session; this WO is the structural fix only.

---

## ACCEPTANCE CRITERIA

- `compare` output cannot recommend an override-required 0-contract option
  over a fully-viable stock trade without the word "OVERRIDE" appearing in
  the recommendation line itself.
- Chain JSON template documents `iv` units explicitly.
- Regression: stock-only and fully-sized option comparisons unaffected.
- An options trade (override or standard) can be written to the vault via
  a schema-validated path with options fields populated -- not a manual
  Obsidian write outside the pipeline.
