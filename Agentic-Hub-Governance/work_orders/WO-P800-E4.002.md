## WHY

`python\tests\test_p115_write.py` fails to import: pydantic
`ValidationError` on `P115Record` -- `signal_date` and `written_by` are
`Field required`. Surfaced 2026-08-07 while adding pytest config to P_800
under WO-P000-E13.001 Phase 2.

Root cause confirmed via `obsidian_writers\config.py`'s own changelog
(line 100-101), not just asserted: the vault writer's v2.0 / "Note
Standard v1.1" schema upgrade added `signal_date`, `run_date`, `run_ts`,
`write_route`, `written_by`, `note_version`, and `write_route_history` as
fields on every md-schema record -- `P115Record`
(`obsidian_writers\domain\vault_schemas.py`) included. `test_p115_write.py`'s
`SAMPLE` dict (written before that upgrade) supplies `"date"` but not
`"signal_date"`, and has no `"written_by"` at all. Real schema drift, not
a test-logic bug.

**Structural note, same category as two other files WO-P000-E13.001 found
this session (`test_schwab.py` in P_020, `test_signal_v2_e2e.py` in
P_800):** `test_p115_write.py` has zero `def test_*():` functions -- it
is a module-level smoke-test script (`write_to_vault(...)` runs at import
time; its own header says "Run from any directory... python
test_p115_write.py"), not a real pytest test. Its `test_` filename prefix
makes pytest try to collect it anyway. Unlike the other two, this one was
deliberately NOT excluded via `conftest.py`'s `collect_ignore` during the
2026-08-07 unblock pass, per that handoff's explicit instruction --
because its failure is a real bug worth fixing, not permanent
script-shaped noise. This WO should decide whether to (a) fix the sample
data and leave it a script (still technically mis-collected by pytest,
still needing `collect_ignore` or a rename to stop that), or (b) take the
opportunity to convert it into a real `def test_p115_write_and_readback():`
-- matching what P_400's Phase 4 guard-repair (WO-P000-E13.001 Phase 4,
not yet authorized) is already doing for `test_p400_known_bugs.py`'s
equivalent problem.
