# WO-P300-E1.003 -- atr_adjusted_stop Formula Produces Invalid Stop When IntelliScan Support Sits Above Entry

**Status:** OWNER_DONE
**Owner:** P_300
**Affects:** P_400 (evaluate_signal.py reads atr_adjusted_stop as the preferred stop override -- a broken value here would silently corrupt sizing math)
**Depends On:** WO-P300-E1.001 (amends the formula introduced there)
**Acks:** N/A

---

## WHY

WO-P300-E1.001 (CLOSED 2026-06-16) introduced atr_adjusted_stop =
max(technical_stop, entry - 1x ATR), with technical_stop sourced from
IntelliScan support levels. The max() choice assumes the technical support
level sits below entry, picking whichever of the two valid below-entry
stops is tighter. That assumption fails when IntelliScan's support level
itself sits above entry.

**Evidence -- DRD, 2026-06-17:**
  entry = 25.40, guideline_stop (ATR-based) = 24.27 (valid, below entry)
  intelliscan_support_1 = 25.46 (above entry -- not a valid stop for a long)
  atr_adjusted_stop = max(25.46, 24.27) = 25.46 -- selected the invalid value

Full-batch check across all 8 remaining 2026-06-17 inbox packets found this
is isolated to DRD only -- not systemic across today's batch. But P_400's
stop resolution priority (snapshot override > atr_adjusted_stop >
guideline_stop, per WO-P300-E1.001's P_400 Ack) would use 25.46 silently if
this packet were evaluated normally -- negative risk, broken sizing math,
a position stopped out by construction at entry.

---

## RECOMMENDED FIX

- atr_adjusted_stop formula adds a guard: only consider the IntelliScan
  technical level as a candidate when it is below entry. If the technical
  level is at or above entry, atr_adjusted_stop = entry - 1x ATR (the ATR
  floor alone), ignoring the invalid technical candidate.

---

## ACCEPTANCE CRITERIA

- atr_adjusted_stop is always < guideline_entry for long signals.
- Add a packet-level validation check (P_300 emitter or P_400 reader) that
  flags/rejects any packet where atr_adjusted_stop >= guideline_entry,
  rather than passing it through silently.
- DRD-style case re-tested: confirms atr_adjusted_stop falls back to the
  ATR floor (24.27) when intelliscan_support_1 is above entry.
