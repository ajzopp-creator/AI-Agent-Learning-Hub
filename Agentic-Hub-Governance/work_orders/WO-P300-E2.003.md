## VERIFIED TECHNICAL GAPS (read directly from the real code, not assumed)

1. **No normalized columns in the research catalog.** Live catalog's
   `pattern_bars` stores raw VP fields PLUS the 9 normalized `_pct`
   columns (`close_pct_from_anchor`, `range_pct`, `body_pct`,
   `stdiff_pct`, `mtdiff_pct`, `ltdiff_pct`, `pred_high_pct`,
   `pred_low_pct`, `pred_range_pct` -- `domain/similarity.py`'s
   `SIMILARITY_FEATURES`, the only columns DTW matching reads).
   `research_catalog_io.py`'s `pattern_bars` DDL has raw fields only --
   nothing computes or stores normalized columns for bulk data today.
   `domain/normalization.py`'s `normalize_bar()` needs `open/high/low/
   close/volume/stdiff/mtdiff/ltdiff/pred_high/pred_low/pred_range` --
   every one of those fields is structurally compatible between
   `VPBarRaw` and `BulkBarRaw` (per `schemas_bulk.py`'s own docstring,
   the ONLY two confirmed field-shape differences are `neural_index`
   and Triple Cross, neither of which normalization touches).

2. **bar_offset needs reindexing, but the anchor framing is already
   correct.** Corrects an overstatement made when this was first raised
   verbally: `application/bulk_hit_writer.py` already slices
   `bars[window_start : hit.bar_index + 1]` -- the persisted window
   ALREADY ends at the detection/trigger day, same LAUNCH-anchor
   concept as the live catalog. The only real gap is
   `research_catalog_io.insert_pattern_bars_batch()` assigns
   `bar_offset = 0..len-1` ascending instead of the live convention
   (`0` = anchor/last bar, negative = setup bars before it) -- a
   mechanical reindex (`offset = i - (len(bars)-1)`) at merge time,
   not a conceptual rework.

3. **DataOriginType is a hard type boundary, by design.**
   `schemas.py`'s `DataOriginType` enum has only `PATTERN_IDENT` /
   `EVAL_SET` -- `BULK_SCAN` doesn't exist there (it's
   `schemas_bulk.py`'s separate `BulkDataOriginType`, deliberately
   type-isolated per that module's own docstring). `catalog_reader.py`
   hard-filters `WHERE data_origin_type = ?` defaulting to
   `PATTERN_IDENT` for everything Pipeline B's similarity search reads.
   Merged rows are invisible to Pipeline B unless (a) the live enum
   gains a `BULK_SCAN` member and the reader query is updated to
   include it, or (b) merged rows are written as `PATTERN_IDENT`
   (loses the audit trail of which patterns came from a curated
   identification vs. a mechanical scan -- NOT recommended).

4. **Scale mismatch changes what "an analog" means.** Live catalog:
   487 patterns / 297 symbols (curated `PATTERN_IDENT`). Research
   catalog: 3111 instances (495 STRICT / 2616 RELAXED) across 126
   symbols (mechanically detected `BULK_SCAN`). A full merge makes
   bulk-origin patterns outnumber curated ones roughly 6:1 in the same
   analog pool every BUY/WATCH/PASS decision draws from --
   `BUY_MIN_WIN_RATE`/`BUY_MIN_Z_SCORE` were calibrated (most recently
   M-034, 2026-06-28) against the curated-only baseline win rate
   (~61%). RELAXED-tier patterns are a materially looser detection
   (drop the triple-cross-down reversal condition, condition 7 of 9) --
   mixing them in undifferentiated risks diluting analog quality below
   what the current thresholds assume.

## DECISIONS (resolved 2026-07-10, Claude's recommendation, Tony confirmed after flagging the isolation was original 2026-07-08 scope, not drift)

1. **Tier scope: STRICT only** (495 instances). RELAXED merge is a
   follow-on WO once STRICT-merge behavior is confirmed safe.
2. **Recalibration: staging copy + walk-forward eval, reviewed as a
   RESULT not a mid-build approval gate.** Claude builds the staging
   merge and runs the eval in the same pass; Tony reviews the eval
   report before the separate, explicit promote step. Not a second
   file-plan-style checkpoint.
3. **DataOriginType: add `BULK_SCAN`** to `schemas.py`'s enum;
   `catalog_reader.py` and `eval_io.py` (both currently PATTERN_IDENT-
   only, confirmed by reading the code) updated to include it.
4. **Collision handling: exact symbol+anchor_date dedup**, skip +
   log count, don't insert a duplicate.
5. **feature_set_id: register `bulk_scan_v1`** as its own row in the
   live catalog's `feature_sets` table.
