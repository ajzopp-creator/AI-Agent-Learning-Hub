## WHY

Twice in one session, 2026-07-24: SXT (P_115) reported earnings that
same morning, 8:30am CDT -- guideline_entry was set pre-move, live
price had drifted 6.99% by evaluate time, R:R collapsed to -0.02,
correctly BLOCKED on TAPE ADVERSE_DRIFT. CLF (P_300) reported Q2 2026
earnings the prior session (Jul 23, before open), stock up +14.44% the
next day on the beat -- guideline_entry (10.96) was set the same day as
the report, R:R was already sitting at the bare 2.0 floor before the
move was even known.

Both slipped through Tier-1 screen as clean PASS. Neither Council nor
screen.py has any concept of "this symbol just reported earnings" --
only forward-looking earnings-in-holding-period is checked (Section
4.4). Both catches this session came from Claude noticing during the
Bucket B web search (next-earnings-date lookup happens to surface the
most recent past report too), not from any deterministic mechanism --
that's a lucky catch, not a system guarantee.

Common swing/day-trading practice: avoid opening fresh positions for
2-4 sessions after a name reports -- pre-report structure (S/R, MAs,
ATR) is invalidated by the gap, spreads/IV stay elevated the first
session or two, and same-session entries risk buying into the gap-fade
before the real post-earnings-drift direction asserts itself.

P_115 already has an analogous rule (V110.3, 3-session stabilization
window) -- but it's a signal-*scoring* filter inside P_115's own
engine, and never applied to CLF because CLF is a P_300 signal. Tony's
call, 2026-07-24: this belongs in P_400 (Council), not left to each
source project to reimplement -- same Authority Rule (Section 3.1)
logic already governing sizing/stops/targets. One fix covers every
current and future signal source (P_115, P_300, P_116/P_118/P_910/P_920
when those come online) instead of requiring each to remember it
independently. P_115's V110.3 stays as-is -- different question
(should this even be scored as a signal) at a different layer (signal
generation, not execution).

## Root Question -- Not Yet Decided, Needs Tony's Call

**Severity: hard BLOCK (convertible to CAUTION via explicit
confirmation, mirroring the existing forward-looking earnings pattern
in 4.4) vs. CAUTION-only from the start?**

Forward-looking earnings-in-window is a BLOCK today because the risk is
categorically different (unknown future event) and Tony has a defined
override path (confirm reduced size / defined-risk structure). Backward-
looking risk (gap-fade, spread/IV settling, invalidated structure) is a
different kind of risk -- arguably better suited to CAUTION-first so
Tony can eyeball the chart and decide, rather than a hard stop every
time. Needs an explicit decision before build, not an assumption.
