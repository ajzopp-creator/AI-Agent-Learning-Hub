# WO-P400-E4.005 -- market_open Never Actually Computed (Hardcoded True)

**Status:** OWNER_DONE (2026-07-26) -- PEH verify passed clean, see final Verify note below

## WHY

Found live 2026-07-26 during a Tier-2B batch (CLF/AGNC/PSA/CAE/CDPYF).
`schemas.py`'s `SnapshotDict.market_open` defaults to `True`, and nothing
in `application\fetch_snapshot.py` or `infrastructure\schwab_market_data.py`
ever computed the real value or passed it explicitly -- every fetch-snapshot
call wrote `market_open: true` regardless of actual session state, including
across a full Sunday session. TAPE's MARKET_CLOSED block (architecture
Section 2.5, exception #3) has effectively never been able to fire through
the automated Schwab-fetch path since it replaced manual TOS transcription.

Tony's call after diagnosis: build directly rather than file-then-defer,
since the fix was unambiguous (unlike E4.004's Root Question). Also
established: Schwab's own Extended Hours Trading documentation confirms
wider spreads / less reliable quotes outside regular hours -- documented
behavior on their end, not a hidden defect, but our code wasn't accounting
for it, which is also part of what let E4.004's bad CAE spread do damage.

## Fix

Computed independently of Schwab's own fields (Tony's explicit reasoning:
the API itself is documented as less reliable off-hours, so don't trust
its session metadata either -- wall-clock only).

| File | Change |
|---|---|
| config.py | `MARKET_OPEN_TIME_ET` / `MARKET_CLOSE_TIME_ET` constants |
| domain\market_hours.py (NEW) | `is_market_open_now()` -- US/Eastern wall-clock, Mon-Fri 9:30-16:00, no holiday calendar (flagged limitation, same accepted pattern as WO-P400-E2.023) |
| application\fetch_snapshot.py | Import + pass `market_open=is_market_open_now(now)` into `SnapshotDict(...)` (previously omitted entirely) |
| test_market_hours.py (NEW) | 7 boundary tests: weekday midday, Saturday, Sunday (the actual live bug date), 1 min before open, at-open boundary, at-close boundary, 1 min before close |

**Correction during same-session explanation to Tony:** `--pre-market` does
NOT flow through `tape_vote()`'s `pre_market_flag` parameter as originally
described -- checked `commands.py`: it directly forces
`snapshot["market_open"] = True` before `evaluate_signal()` runs.
`pre_market_flag` stays hardcoded `False` in evaluate_signal.py, effectively
dead. Net effect on the MARKET_CLOSED gate is the same either way, but the
implementation detail was wrong in the first explanation -- corrected live.
