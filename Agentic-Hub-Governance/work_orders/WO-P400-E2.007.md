**Status:** CLOSED

## WHY

`quant_vote()` uses strict `<` to compare `risk_per_share` against `atr_14 * MIN_STOP_ATR_MULTIPLE`.
When stop is derived as exactly `entry - 1xATR`, floating point rounding causes
`risk_per_share` to be fractionally smaller than `atr_14`, triggering a false
`STOP_TOO_TIGHT` block.

## TEMPORARY FIX APPLIED

2026-06-13: Patched council.py with `- 0.01` tolerance:
```python
if atr_14 > 0 and risk_per_share < (atr_14 * MIN_STOP_ATR_MULTIPLE) - 0.01:
```
This unblocks the EME paper trade session but is not a clean fix.

## PROPER FIX

Replace magic constant with `round()`-based comparison or explicit tolerance constant
in config.py. Recommended:

```python
STOP_ATR_TOLERANCE = 0.005  # in config.py

if atr_14 > 0 and risk_per_share < (atr_14 * MIN_STOP_ATR_MULTIPLE) - STOP_ATR_TOLERANCE:
```

Add `STOP_ATR_TOLERANCE` to `config.py`. Remove the hardcoded `- 0.01` from `council.py`.

## ACCEPTANCE CRITERIA

1. Stop set at exactly 1xATR passes Quant without block
2. Stop set at 0.99xATR still blocks correctly
3. `STOP_ATR_TOLERANCE` defined in config.py, not hardcoded in council.py
4. Existing council tests still pass (61/61)

## FILES

- `python/domain/council.py` ? replace `- 0.01` with `- STOP_ATR_TOLERANCE`
