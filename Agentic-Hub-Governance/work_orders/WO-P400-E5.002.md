## WHY

Every Tier-2B batch requires Claude to manually web-search earnings date +
sector per symbol before `fetch-snapshot`, since Schwab's market data API
(price/ATR/volume/chain -- already automated) doesn't carry an earnings
calendar or sector classification. This repeats every session, costs
several search calls per batch, and is the one input in the Tier-2B flow
that currently blocks running the screen-all -> snapshot -> evaluate
sequence unattended.

## Approach

Filed 2026-07-29 at Tony's explicit direction: build incrementally, not a
full spec up front. Log friction points below as they actually surface
across sessions; only design a fix once the real pattern of need is
visible. Do not let this WO accumulate a premature scope table.

## Build Summary (2026-08-08)

Overrode the log-only/no-spec directive above -- Tony's explicit call
2026-08-08, after a concrete buildable path (Nasdaq public API) surfaced
mid-session. Live-verified end to end same session.

**Data source, and why it changed mid-build:** Started with Financial
Modeling Prep (free "Personal Use" tier). Live-tested and rejected: the
bulk `earnings-calendar` endpoint capped free-tier coverage to ~73 large-cap
symbols regardless of date range -- CGON, a real live signal that day and
confirmed to have reported inside the pulled window, was absent. The
per-symbol fallback (`/stable/earnings`) is paywalled, 402. Switched to
Nasdaq's public, unauthenticated endpoints (`api.nasdaq.com/api/calendar/earnings`
and `.../company/{symbol}/company-profile`) -- no key, no signup. Live-tested:
585 companies for a single day, CGON present with the correct 2026-08-06
report date; sector confirmed via company-profile ("Health Care" for CGON).
Full 91-day refresh: 3,326 symbols, zero blocked/failed calls.

**Design correction made mid-build:** first pass treated a symbol absent
from the cache as an honest null (safe to treat as "no imminent earnings").
That was reasoned under FMP's narrow coverage, where absence meant "not a
mega-cap" -- unrelated to earnings timing, and would have silently disabled
MACRO's earnings-BLOCK gate for most real signals. Corrected to a hard fail
(`EarningsDataMissing`) before shipping, matching the original manual
file's fail-loud philosophy. Kept even after switching to Nasdaq's much
broader coverage, as the correct default regardless of source.

**Scope:** earnings dates (next + last) via a monthly-refreshed local cache;
sector via a live per-PASS-symbol lookup at batch-2b run time (not bulk --
would be one call per symbol in a 3,000+ symbol calendar). Cache freshness:
fixed-monthly-schedule check, no live spot-verification (Tony's call).
