# WO-P805-E1.001 — LLM Caller Architectural Fix: Remove Application-Layer LLM Coupling

**Status:** COMPLETE
**Verified:** 2026-06-14
**Owner:** Claude
**Depends On:** —
**Affects:** P_805

---

## Problem

`phase35_enrich.py` (application layer) was directly fetching the LM Studio model ID
and passing LM Studio connection params (`lm_url`, `lm_model`, `timeout`) into
`classify_direction()`. This violated the layering rule: the application layer should
not know or care which LLM is active — that is config and infrastructure's job.

## Root Cause

When `lm_studio_caller.py` was rewritten to support Gemini (primary) + LM Studio
(fallback), the parameter rename (`url` → `lm_url`, `model` → `lm_model`) exposed
the coupling that was already present in `phase35_enrich.py`.

## Fix

1. Move `_get_model_id()` logic into `lm_studio_caller.py` — caller owns LM Studio
   connection details entirely.
2. All LM Studio config values (`LM_STUDIO_URL`, `LM_STUDIO_MODEL`,
   `LM_STUDIO_TIMEOUT`) read from `config.py` inside the caller — never passed in
   from application layer.
3. `classify_direction()` public signature reduced to `(ticker, context)` only.
4. `phase35_enrich.py` calls `classify_direction(ticker, context)` — no LLM params.
5. `_get_model_id()` removed from `phase35_enrich.py` entirely.

## Files Changed

| File | Change |
|------|--------|
| `python/infrastructure/lm_studio_caller.py` | Added `_get_lm_model_id()`; hardened defaults from config; simplified public signature |
| `python/application/phase35_enrich.py` | Removed `_get_model_id()`, removed LLM params from `enrich_signals()` and call site |

## Verification

- `python cli.py --phase 35` runs without TypeError
- Log shows `Gemini classified` lines (or LM Studio fallback if Gemini unreachable)
- No LLM params appear in `phase35_enrich.py`
