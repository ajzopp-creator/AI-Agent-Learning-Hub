# WO-P920-E1.001 — P_920 Earnings Filter (V2.1) Confirmed Inert

**Status:** CLOSED
**Owner:** Tony
**Depends On:** —

---

## Problem

P_920_BuyersinControl_EOD.V2.1 (updated 5/8/26) added a `noRecentEarnings` filter using
`Sum(HasEarnings(), earningsLookback) == 0`, with header comments describing it as
actively excluding same-day + 2-prior-session earnings-reaction tickers.

This directly contradicts STRATEGY_CHANGE_LOG_V110.md (V110.3 section), which documents
that `HasEarnings()` is not supported in TOS Stock Hacker scans (silently fails or errors),
and that the scan filter attempt was reverted to V2.0 with earnings checking moved to the
review layer (Claude's stockanalysis.com fetch during Fund verification).

V2.1 was confirmed live in production on 6/19/26 (triggered the MTN/SUNB/VIRT batch that
session). The changelog block in the V2.1 script itself does not reflect the documented
revert — it reads as if the earnings filter works.

## Root Cause (Confirmed)

`HasEarnings()` is non-functional in the Stock Hacker scan engine. Tony ran V2 and V2.1
side by side on 6/19/26 — identical result counts. This confirms `noRecentEarnings`
evaluates true unconditionally; the filter is a permanent no-op and has been since 5/8/26.

It did not affect the 6/19/26 MTN/SUNB/VIRT batch specifically — none of those three had
earnings within the 3-bar lookback window regardless (MTN earnings 8 sessions prior, SUNB
earnings upcoming 6/23/26 not yet reported, VIRT not until 7/29/26) — but the scan has been
running on a dead filter for ~6 weeks (5/8/26 to 6/19/26) believing it had earnings
protection it did not have.

## Resolution

- V2.1 retired by Tony (6/19/26).
- V2 (pre-earnings-filter version) confirmed as the live script going forward — no code
  change required since V2/V2.1 are behaviorally identical.
- Earnings filtering continues at the review layer only (Claude's mandatory
  stockanalysis.com earnings-date check on every BUY/ASYM, per V110.3) — this layer
  works and was never affected by the scan-side bug.
- STRATEGY_CHANGE_LOG_V110.md V2.1 entry superseded — see new entry dated 6/19/26.
