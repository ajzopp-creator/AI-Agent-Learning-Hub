## WHY

Step 0.5 of system-doc-initializer previously identified the active project from
the system prompt's imported-knowledge/project-context block only, with a
single fallback: ask Tony if no project is attached or it's ambiguous. That
single-step fallback didn't distinguish "nothing attached" from "attached but
the title doesn't carry a clean P_XXX prefix" or other ambiguous-but-not-empty
cases, and offered no way to recover context from the conversation itself
before interrupting Tony.

Real trigger, same day: a P_400 session opened with "I have no visibility into
which project is attached to this session... which project are we running,"
and asked Tony directly -- the only fallback that existed. Working as
designed, not a bug in the old rule, but the design never tried the
conversation's own recent-chat titles or the target project's doc header
first.

This WO's design was approved in chat on 2026-08-11, in a session whose MCP
connection died before the fix could be written to disk. Nothing was lost --
the approved design was captured and refiled OPEN in this file, same chat,
then executed later the same session. (See also EC-003: a session mislabeled
as P_000 despite P_800 attached, 2026-07-08 -- a related but distinct failure
shape that Step 0.5 already addressed; this WO hardens the same step for the
ambiguous/missing-title case.)

## WHAT -- Built

Four-step fallback chain added to Step 0.5, `system-doc-initializer` SKILL.md:

1. `recent_chats(n=1)` -- check the most recent chat title for a P_XXX prefix.
2. If that title is missing or ambiguous, widen to `recent_chats(n=3-5)` and
   look for a consistent P_XXX pattern across them.
3. If still zero results, check the attached Project's architecture doc
   header (on-demand doc, e.g. P_XXX_SYSTEM_DOCUMENTATION.md or equivalent)
   for its Project ID field.
4. If no doc exists either, ask Tony directly -- unchanged from the prior
   single-step fallback.

Noted directly in the skill: this chain recovers a missing/ambiguous Project
ID from conversation or doc context. It does NOT help when no Claude.ai
Project is attached to the chat at all (a Project-settings issue) -- that
case still lands on step 4/ask Tony, same as before. Distinguishing those two
failure shapes was flagged as worth checking before assuming this fix covers
every "which project" incident.
