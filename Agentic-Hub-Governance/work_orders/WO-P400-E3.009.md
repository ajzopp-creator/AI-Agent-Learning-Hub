# WO-P400-E3.009 -- spec Depends on Un-Archived Packet; Re-Running evaluate Internally Creates Duplicate Archive Entries

**Status:** CLOSED
**Owner:** P_400
**Affects:** none -- internal P_400 only
**Depends On:** None
**Acks:** N/A

---

## WHY

Found live 2026-07-09 running BP through the full STEP 4-6 pipeline.

**Issue 1 -- sequencing gap:** `cli.py evaluate SYMBOL` archives the inbox
packet (`*_v2.0.json` -> monthly zip) as a side effect of running, same
pattern as the known "evaluate archives even on BLOCKED verdicts" behavior.
`cli.py spec SYMBOL` reads from the live inbox only -- it has no path to
the archive. Once `evaluate` has run for a symbol, `spec` fails outright
("no packet found") even though the trade was just APPROVED and Tony
wants the order spec seconds later. Workaround used this session: manually
restore `2026-07-08_BP_v2.0.json` from `2607_ProcessedJson.zip` back into
the inbox via PowerShell `ZipFile` extract before re-running `spec`.

**Issue 2 -- non-idempotent re-run:** `spec` does not read a cached result
from the prior `evaluate` call -- it re-runs `evaluate` internally against
the restored packet, which re-archives it, producing a second, duplicate
`2026-07-08_BP_v2.0.json` entry in `2607_ProcessedJson.zip` (surfaced as a
`UserWarning: Duplicate name` at runtime). Not currently harmful --
`Select-Object -Last 1` / existing duplicate-retrieval convention still
resolves to the correct entry -- but the zip accumulates redundant entries
every time `spec` is called after `evaluate` for the same symbol, and this
is exactly the shape of prior duplicate-archive bugs already fixed
elsewhere in the archiver.

## Fix Direction (not yet built)

Option A -- `spec` reads the cached result `evaluate` already wrote
(WO-P400-E3.006 added `eval_cache.py` per-symbol cache for this class of
problem -- confirm whether `spec` already has access to it and isn't using
it, or whether cache scope needs extending to cover spec's inputs).
Option B -- `spec` accepts a `--from-archive` / explicit packet path flag
so it never needs to trigger a second `evaluate` pass.
Whichever direction: `spec` must not independently re-archive a packet
`evaluate` already archived in the same session.

## Verify

One APPROVED symbol: `evaluate` then `spec` back-to-back, zero manual zip
restores needed, zero duplicate entries in the monthly zip afterward.
