## Problem

At INIT on 2026-06-16, a conflict was detected between the JSON `risk_mode` field and the avg_posture arithmetic rule:

- `risk_mode` in P_010_RiskConfig.json = **OFF**
- `avg_posture` = **-0.718201**
- P_000 account parameters table defines OFF as `avg_posture < -1.0`
- -0.718 does NOT satisfy < -1.0 ? by arithmetic, this should be STANDARD or HALF

P_010_RiskConfig.json is the authoritative source per trading rules, but the JSON value and the derivation rule disagree. This creates ambiguity at every INIT.

## Root Cause (Hypothesis)

The `risk_mode` field in the JSON is likely set by P_300 VantagePoint Grid logic or a separate posture script using different thresholds or override logic than what is documented in P_000. The written rule in P_000 (-1.0 threshold) may be stale or the Grid may apply additional factors (VXX signal, qualitative override, etc.) that shift the mode.

## Decision Required (Tony)

Choose one:

**Option A ? JSON Always Wins (no change to logic, update docs)**
`risk_mode` in JSON is authoritative regardless of avg_posture arithmetic.
Update P_000 table to remove the avg_posture threshold column or add a note:
"Thresholds are illustrative only ? JSON field is the actual mode."

**Option C ? Manual Override Flag**
Add an `override` boolean field to the JSON. If `override: true`, Claude honors risk_mode even when arithmetic disagrees. If `override: false` or missing, arithmetic governs.
