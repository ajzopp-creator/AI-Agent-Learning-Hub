## WHY

Two separate P_400 functions approximate market-calendar behavior using
wall-clock/weekday math only, with no actual US market holiday calendar
anywhere in the codebase:

1. `domain\market_hours.py`'s `is_market_open_now()` (WO-P400-E4.005) --
   Mon-Fri 9:30-16:00 ET, no holiday check. On a weekday holiday (July 4th,
   Thanksgiving, Christmas, Labor Day, etc.) this returns `market_open: true`
   when the market is actually closed -- TAPE's MARKET_CLOSED gate
   (architecture Section 2.5, exception #3) can't fire on those days, and
   Schwab quote/price-history data would also be stale/unavailable with
   nothing catching it.

2. `application\evaluate_signal.py`'s `_sessions_since_earnings()`
   (WO-P400-E2.023) -- weekday-count approximation, explicitly flagged in
   that WO's own Execution notes as `no holiday calendar`. Feeds the
   `POST_EARNINGS_STABILIZATION_SESSIONS` MACRO caution (default 3
   sessions) -- a holiday inside that window makes the count wrong by one
   session per holiday, silently shortening or lengthening the caution
   window.

Both were built and flagged independently, in different sessions, same
root gap, never connected until this review.

## Root Question -- Needs Tony's Call Before Build

**Approach A -- hardcoded holiday list.** A small constant/module (e.g.
`US_MARKET_HOLIDAYS` in config.py, or a new `market_holidays.py`), one
line per year, sourced from NYSE's published calendar. Zero new
dependencies. Needs a manual update each year (or listed several years
out at once). Simple, auditable, matches the Hub's existing bias toward
explicit values over hidden logic.

**Approach B -- calendar library.** e.g. `pandas_market_calendars` or
`exchange_calendars` (pip-installable in p140). Handles NYSE holidays,
early closes, and year-rollover automatically, no manual maintenance. New
third-party dependency in the p140 conda env -- import surface neither
current module has today.

Leaning Approach A given the Hub's existing bias against new dependencies
where a short static list does the job (same reasoning behind E4.005's
own wall-clock-only, don't-trust-the-API's-own-session-metadata choice) --
but this is explicitly Tony's call, not decided here.

## Root Question -- DECIDED 2026-07-27

Approach C, not A or B: pure rule-based computation in plain Python, zero
dependencies, zero per-year data to maintain. Every NYSE holiday reduces
to Nth-weekday-of-month, last-weekday-of-month, a fixed date with
weekend-shift, or Good Friday via the Anonymous Gregorian Easter
algorithm. All rules verified against NYSE's published 2026-2028 calendar
(web search + a standalone script) before any file was written -- every
date matched, including the 2027 Juneteenth weekend-shift and the 2028
New Year's Day non-observance exception. This beats Approach A (hardcoded
list) because a hardcoded list needs annual manual maintenance and fails
silently (not loudly) if forgotten -- exactly the class of bug this
session spent most of its time on for an unrelated reason (WO-P800-E3.003
skill drift). It beats Approach B (calendar library) because it needs no
new dependency in p140 for logic this small and this verifiable.

**Two unrelated bugs found and fixed during PEH verification, not part of
this WO's original scope but blocking a clean run:**

1. ``test_schwab_market_data.py``'s ``_mock_client()`` helper only
   configured ``client.get_quote`` (singular). Production code was
   switched to ``client.get_quotes`` (plural) earlier this same session
   (BRK/B slash-symbol fix, undocumented WO -- ``get_quote()`` can't
   handle non-alphanumeric symbols per schwab-py's own docstring). Test
   mock was never updated to match, so it silently exercised an
   unconfigured MagicMock instead of the real mocked response. Fixed:
   mock now configures both.
2. ``test_sessions_since_earnings_weekday_count`` (originally patched by
   WO-P400-E4.005's addendum) was itself weekday-of-today-dependent --
   that patch was verified only against a Sunday and silently broke on
   the next weekday "today" (Monday 2026-07-27, this WO's own PEH run:
   got 6, expected 5). Root cause: the old backward-walk never accounted
   for ``_sessions_since_earnings()`` counting today itself when today is
   a weekday. Fixed with Tony's explicit go-ahead: new construction finds
   the N most recent qualifying days working back from today (today
   included if it qualifies) -- correct regardless of today's weekday.
   Assertion value unchanged (``target = 5``); only the date-construction
   method changed.
