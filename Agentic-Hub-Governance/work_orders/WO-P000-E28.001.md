## Background

Raised by Tony at the close of a P_000 session, 2026-09-09, immediately after WO-P000-E21.001 landed: "we probably need to rethink INIT's in their entirety."

Chain that led here: Tony wanted multi-project INIT to run async so it wasn't sequential and slow (E21.001). Cowork was evaluated and ruled out -- Cowork VM sessions don't reliably forward desktop-extension/stdio MCP servers like windows-mcp. Parallel Claude Desktop chat windows were also ruled out -- Desktop is single-window, and there's a filed regression where switching sessions mid-generation interrupts the response. The actual fix that shipped was a Hub-wide WO status scanner (`hub_wo_status_scan.ps1`) that does the mechanical WO/gate-check pull for all 9 projects in one PowerShell pass, no Claude session required. That fix works, but it only replaced one piece of what INIT currently does -- the rest had never been reexamined with "some of this doesn't need a live session at all" as the lens. This WO was filed to scope that rethink before building anything further.

## Answer to Question 5 (2026-09-09) -- this is what got built

Tony's direction, given directly in-session: after the scanner runs, per-project INIT kicks off automatically via headless Claude Code, each project writing its own boot file. Refined twice during build:
- Scope is not all 9 projects reflexively -- Tony's actual daily set is **P_115, P_300, P_400**. Other projects get added/removed from the daily run as needed, not run by default.
- Cost and usage-limit exposure matter: confirmed via Settings > Usage (screenshot review) that headless runs bill against the metered usage-credit pool (`costBasis: list`), not flat plan allowance, and the weekly Claude Code limit was already at 79% under a temporary boost expiring Sept 13. Narrowing to 3 daily projects instead of 9 was the chosen mitigation over setting a hard account spend cap.

## Built (2026-09-09)

- **`hub_wo_status_scan.ps1`** (`Agentic-Hub-Governance\utils\`) -- from E21.001, unchanged, used as step 1 here.
- **`P_000_DailyProjects.txt`** (`Agentic-Hub-Governance\utils\`) -- plain list, one project ID per line, `#` comments supported. Default: P115, P300, P400. Edited directly to add/remove a project from the daily run; no script change needed.
- **`P_000_StartUp_ClaudeDesktop.ps1`** (`Agentic-Hub-Governance\utils\`, ~150 lines) -- orchestrator:
  1. Runs the WO scanner (informational -- annotates each daily project with its open-WO status, no longer gates whether it launches).
  2. Resolves each daily project ID to its real folder from disk (`projects\P_<id>_*`), not a hardcoded map.
  3. Launches one headless `claude -p` per daily project via `Start-Process -WorkingDirectory <project folder>`, scoped with `--allowedTools "Read,Grep,Glob,Write" --disallowedTools "Bash,Edit" --restricted --add-dir "<HubRoot>" --permission-mode acceptEdits --permission-prompts none --max-budget-usd 0.50 --max-turns 15 --output-format json`.
  4. Waits on all of them (default 480s each), verifies each expected boot file actually exists AND has a fresh mtime (not a stale leftover) before calling it OK -- never trusts exit code alone.
  5. Prints a per-project summary line, then launches Claude Desktop (`-SkipDesktopLaunch` available to suppress, for testing).
  - `-Projects <list>` overrides the daily file for a single ad-hoc run (e.g. add a project for one day without editing the file).
- **Addendum (2026-09-10):** each boot file now opens with a deterministic `**Suggested chat name:**` line (script-generated from the run timestamp, not model-generated -- matches system-doc-initializer's Step 3 format). Raised by Tony after the pilot: boot files weren't producing the usual chat-name heading. This is the narrow fix (puts the name in the file for Tony to use); it does not make system-doc-initializer itself boot-file-aware -- that's WO-P000-E29.001.

## Bugs found and fixed during build (real, caught by testing before they mattered)

1. Used `$pid` as a project-ID loop variable -- collides with PowerShell's built-in read-only `$PID`. Renamed to `$projId`.
2. Scanner output parsing used `^...$` regex against un-split multi-line strings -- matched nothing. Fixed by joining and re-splitting on newlines first.
3. First live attempt at a headless call hung 4 minutes with no permission mode set -- root cause confirmed once Tony ran `claude -p` directly: no `--cwd` flag exists in this CLI version (verified via `claude --help`, not assumed from docs); working directory is `Start-Process -WorkingDirectory`, not a claude.exe flag.
4. First corrected pilot run: all three projects failed cleanly with a real, self-diagnosed error -- `--restricted` confines file tools to the working directory *and* `--add-dir` list, and only the boot folder was in that list. Governance files (WO ledger, skill files, account params, risk config) were unreadable. Fixed by pointing `--add-dir` at the Hub root instead of just the boot folder.
5. `Start-Process -PassThru` process objects returned an unreliable/blank `.ExitCode` after `WaitForExit` -- fixed by retaining `.Handle` immediately after launch (known .NET quirk) and wrapping the read in try/catch. Status classification also reordered so a missing/stale boot file is the primary failure signal, not a possibly-unreliable exit code.

## Pilot Result (verified, 2026-09-09, not self-reported -- checked independently)

Ran `P_000_StartUp_ClaudeDesktop.ps1 -SkipDesktopLaunch` against the real ledger and real project folders. All three produced fresh, substantive boot files (3.7-4.7 KB each, timestamps matching the run):

- **P115_Boot.md**: real account balance, live risk_mode with reason, both open WOs correctly stated, and caught a real code bug -- `tracker_writer.py` imports four names (`TRACKER_PATH`, `WRITTEN_BY`, `REQUIRED_FIELDS`, `COLUMN_MAP`) that don't exist in `config.py`. Also flagged an overdue weekly review against a hard Sept 16 gate date.
- **P300_Boot.md**, **P400_Boot.md**: same pattern, not individually quoted here -- file sizes and fresh timestamps confirmed, full read not required to trust given P115's depth.

Total pilot cost: **$1.1464** across the three (P115 $0.305, P300 $0.399, P400 $0.442) -- billed against usage credits per the Settings > Usage check above, not flat plan allowance.
