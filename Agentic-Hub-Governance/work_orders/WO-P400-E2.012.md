# WO-P400-E2.012 -- BOOK_DIR Points to a Dead Folder; Risk Gate Has Been Reading an Empty Book

**Status:** CLOSED
**Owner:** P_400
**Affects:** (none -- internal P_400 only; book_loader output feeds Council
  Risk role gates within the same project)
**Depends On:** None
**Acks:** N/A

---

## WHY

config.py: `BOOK_DIR = VAULT_ROOT / "TradeOrderManagement" / "P400"`
config.py: `PAPER_BOOK_DIR = VAULT_ROOT / "TradeOrderManagement" / "P400" / "paper"`

Every real P400 lifecycle record is actually landing in
`trading_journal\TradeManagement\P400\` (no "Order") -- per
obsidian_writers/config.py VAULT_FOLDER_MAP["P400"] = "TradeManagement/P400",
which is the live, P_800-managed write path used by write_to_vault(). This
matches the convention already used for P115/P300/P020 -- "TradeManagement"
(no "Order") is the real vault namespace for lifecycle notes.
"TradeOrderManagement" is correctly reserved for the raw JSON signal-packet
folder (signals/) only -- BOOK_DIR copied that segment by mistake.

book_loader.load_book() defaults to BOOK_DIR and globs `*_P400.md`. Even if
the folder were correct, the glob would still never match -- actual filenames
built by obsidian_writers/domain/filename_builder.py are `{date}_{ticker}.md`,
no "_P400" suffix at all.

**Impact:** load_book() is called unconditionally inside
application/evaluate_signal.py (both the main sizing path and the
ENTRY_MISSED early-return path) -- it is in the live Council Risk role
path on every single evaluate() run, real or paper. Since the split, it has
been returning an empty list every time. Portfolio heat cap (12%), max
concurrent positions (8), and sector concentration (2/sector) checks have
been evaluating against a phantom empty book, not the real one.

**Evidence -- live records sitting in the correct (TradeManagement/P400)
folder that load_book() has never seen, found while chasing a separate
question about RGLD's record-write status:**
  2026-06-08_HAL.md (written 6/12), 2026-06-12_COF.md (written 6/15),
  2026-06-15_ACLS.md, 2026-06-15_CMCSA.md, 2026-06-15_WDC.md,
  2026-06-15_WWD.md, 2026-06-16_AGI.md, 2026-06-16_CTVA.md,
  2026-06-16_EDVMF.md, 2026-06-16_EQX.md, 2026-06-16_OESX.md,
  2026-06-16_PAAS.md, 2026-06-16_RGLD.md (today, MANUAL_PASS drop).
  13 real lifecycle records, ~5-6 trading days, invisible to every Risk
  gate check that ran in that window.

**Secondary finding, same root cause area:** write_p400_record() never
branches on trade_mode when calling write_to_vault() -- PAPER and REAL
records both land in the same TradeManagement/P400 folder, distinguished
only by the lifecycle_status frontmatter field. PAPER_BOOK_DIR is
unreferenced dead config; paper records are not actually segregated into
a separate folder despite memory/documentation describing them as routed
to P400\paper\. Flagging for awareness -- not blocking this WO's fix.

---

## RECOMMENDED FIX

- config.py: BOOK_DIR = VAULT_ROOT / "TradeManagement" / "P400"
- book_loader.py: glob pattern *_P400.md -> *.md
- PAPER_BOOK_DIR: leave as a documented gap (separate WO) rather than
  silently repointing it without a real paper-segregation design decision.

## ACCEPTANCE CRITERIA

- load_book() returns all 13 known real records above on next run.
- A live evaluate() run with an open position shows nonzero portfolio heat
  in the Risk role's narration (no longer ALL_CLEAR-by-construction on an
  empty book).
- Old TradeOrderManagement\P400\*_P400.md files (pre-cutover, ~6/08-6/13)
  reviewed for whether they need migrating into TradeManagement/P400 or are
  fine left as historical/orphaned.
