## WHY

Live 2026-09-11, 12:06 ET: `record EXPD --order-id 15108638441 --paper` wrote the
P_400 vault record cleanly (SUBMITTED, vault_write=OK) but the P_020 order write
failed: `cannot import name 'Exit' from 'schemas'` pointing at P_400's own
`python\schemas.py`, not P_020's.

Root cause: `db_order_writer.py` (P_020's own file) does `from schemas import
Exit, Order, Trade` -- unqualified, meant to resolve against P_020's
`database\schemas.py` once `_load_p020()` inserts that folder at the front of
`sys.path`. But `sys.modules` caches by bare name process-wide; P_400's own
`schemas.py` was already loaded into `sys.modules['schemas']` earlier in the
same process (for P_400's own trade-spec models), so Python returned the
cached P_400 module instead of re-resolving via the path insert. P_400's
schemas.py has no Order/Trade/Exit, so the import failed on the first missing
name.

Same bug class as two prior live incidents in this same bridge file:
`infrastructure`/`domain` (WO-P400-E6.001, 2026-09-07) and `config`
(2026-09-09) -- each time, a P_020 module import collided with a same-named
P_400 module already cached, and each time the fix was adding the colliding
name to `_load_p020()`'s `_COLLIDING_PACKAGES` stash/restore tuple. `schemas`
was explicitly excluded from that tuple based on a comment claiming "no
caller in this Hub has a same-named top-level module" -- false as of this
incident.

## WHAT

1. Add `"schemas"` to `_COLLIDING_PACKAGES` in `p020_order_writer.py`'s
   `_load_p020()` -- same stash/restore mechanism already used for
   `infrastructure`/`domain`/`config`.
2. Correct the now-false docstring sentence claiming no caller has a
   same-named `schemas` module.
3. Update the module-level comment above `_COLLIDING_PACKAGES` with a dated
   note matching the existing `config`/`infrastructure`/`domain` entries, so
   the incident history stays in one place.
4. Per Regression Test Governance (python-project-architecture skill,
   Hub-wide non-negotiable): a permanent `tests/test_p020_order_writer.py`
   encoding this fix as an assertion -- not yet written.
