## WHY

The Chaikin Power Gauge enrichment batch repeatedly spends real browser
time on symbols Chaikin structurally cannot rate, then reports them as
failures. Two distinct classes have now been confirmed across four
separate sessions:

**Class 1 -- ETFs.** Power Gauge does not rate ETFs at all. Confirmed
directly 2026-08-03 from the live site: `members.chaikinanalytics.com/pgr/etf/XYLD`
loads normally and shows `Rating: None` with the text "This ETF is
unrated." Prior instances: BITX and CRPT, 2026-07-07 (`todo_archive.md`,
2026-07-07 entry -- both ETFs, both "failed cleanly with no partial
writes"), same pair recorded again in `P_300_Session_Transcript_2026-07-08.md`.
`WO-P300-E2.002` also references "ETFs skipped cleanly" as established
behavior.

**Class 2 -- OTC mirror tickers with a non-US primary listing.** CDPYF
(2026-07-24) and CNSWF (2026-07-27 and 07-29) are OTC pink-sheet mirrors
of TSX-primary Canadian companies (Canadian Apartment Properties REIT /
CAR.UN and Constellation Software / CSU respectively). Root-caused from
Tony's own Chaikin UI screenshots and closed under the WO-P300-E4.009
FOLLOW-UP: Chaikin simply does not carry them. Permanent, not retryable.
Tony's call at that time was that no per-symbol detection code was
needed -- this WO is the different, cheaper direction: never send them.

## THE REAL COST -- not just wasted time

Wasted browser time is the visible cost and the smaller one. The larger
problem is signal dilution in the failure detector built by WO-P300-E4.009:

- On 2026-08-03 the batch banner named 17 symbols as "likely did not
  complete." Two of them (XYLD, EDVMF) could never have succeeded under
  any conditions. The real failure -- an expired Chaikin login -- affected
  the other 15.
- A detector whose failure list routinely includes symbols that are not
  actually failures trains the operator to discount it. WO-P300-E4.009's
  banner is explicitly best-effort text matching; it does not need extra
  noise on top of its known limits.

Filtering unratable symbols upstream makes every future banner mean
"something is genuinely wrong," which is the whole point of that WO.

## SCOPE NOTES

- **RESOLVED 2026-08-03 -- where the list lives:** `data\reference\chaikin_skip_list.csv`.
  Same folder already holds `sector_map.csv` -- an operator-maintained,
  config-pathed, symbol-keyed CSV solving the identical shape of problem
  (WO-P300-E2.002 precedent, reused per M-082). Neither `.ps1` script
  imports `config.py` today and won't need to -- both already hardcode
  path constants (`$LOG`, `$PROMPT_TEMPLATE`); a `$SKIP_LIST_CSV`
  constant follows the same pattern. No Python/PowerShell coupling
  introduced.
- **RESOLVED 2026-08-03 -- detection vs. enumeration:** enumeration-only,
  hand-maintained. Forced by Class 2: OTC mirrors have no programmatic
  tell, so a purely-derived list can never cover them regardless of
  effort spent on Class 1 (ETF) detection. Same precedent as
  `sector_map.csv`, which is itself hand-maintained.
- **RESOLVED 2026-08-05 -- both call sites, duplicated block, no shared
  module.** The CSV is the single source of truth for the list itself;
  the read+filter code (~15 lines) is small enough that duplicating it
  in both scripts matches the existing per-script hardcoded-constant
  convention (`$LOG`/`$PROMPT_TEMPLATE` aren't shared today either) and
  avoids introducing a new dot-sourced file. Both scripts import the
  same CSV, so classification can't drift between them even though the
  reading code is duplicated.
- **A skip must be visible, not silent.** Built as `[SKIP] <symbol> --
  <reason> (permanent skip list, WO-P300-E5.007)`, printed to console at
  both call sites and additionally logged via `Add-Content` in
  `P_300_RunAllDailyEvals.ps1` (which already writes that log; the
  standalone script only reads it). The "nothing to run" message at both
  sites was also split to distinguish "no BUY/WATCH today" from "all
  BUY/WATCH were on the skip list" -- the same silent-narrowing concern
  applies to that message, not just the skip line itself.
- **Not a decision-path change.** Chaikin enrichment is vault-note
  content only. Nothing in this WO touches BUY/WATCH/PASS (NFR-1) --
  confirmed by construction: the filter runs after `$actionable` is
  already derived from the DailyEval log, downstream of any signal
  classification.
