# WO-P800-E2.004 ? Add REVIEWED_NO_TRADE to P400 VERDICT_MAP

**Status:** CLOSED
**Owner:** P_800
**Affects:** P_400
**Depends On:** None
**Acks:**
  P_400: done 2026-06-16 -- auto-write path verified (WO-P400-E2.011 OWNER_DONE); all four verdicts now map cleanly

---

## WHY

When P_400 writes a REVIEWED_NO_TRADE record via write_to_vault("P400", ...),
the write_handler cannot map council_verdict = "REVIEWED_NO_TRADE" to a vault
folder because it has no entry in the P400 VERDICT_MAP. The note files under
PASS as a fallback. This causes Obsidian folder filtering to misclassify
reviewed-but-not-traded signals as ordinary PASS verdicts.

Discovered: 2026-06-15 (P_400 session, ACLS ENTRY_MISSED record).

---

## WHAT

Add "REVIEWED_NO_TRADE" -> "PASS" (or a dedicated folder if Tony wants one)
to the P400 VERDICT_MAP in write_handler.py or wherever the map lives in P_800.

Decision needed: should REVIEWED_NO_TRADE file under PASS (simplest), or get
its own vault subfolder (e.g. TradeOrderManagement/P400/reviewed/)?

Default recommendation: map to PASS for now. Open a follow-on WO if a
dedicated folder is wanted after seeing the volume of these records.

---

## ACCEPTANCE CRITERIA

- write_to_vault("P400", {..., "council_verdict": "REVIEWED_NO_TRADE", ...})
  files the note without fallback warning
- write_to_vault("P400", {..., "council_verdict": "APPROVED", ...})
  files the note without fallback warning
- write_to_vault("P400", {..., "council_verdict": "APPROVED_WITH_CAUTION", ...})
  files the note without fallback warning
- write_to_vault("P400", {..., "council_verdict": "BLOCKED", ...})
  files the note without fallback warning
- No existing P400 records affected
- test_signal_v2_e2e.py still passes (or equivalent P_800 smoke test)
