## Problem

`SignalMetadata` in `shared_resources/python_utils/signal_schemas.py` carries two fields
with a hard-coded `p115_` prefix:

```
p115_session_date: str    # YYYY-MM-DD of generating P_115 session
p115_chart_timeframe: str # 1D | 4H | 1H | etc
```

The prefix is a P_115 origin artifact. The schema is shared by both producers (P_115 and
P_300). A live P_300 packet emits `p115_session_date` for a P_300 eval date -- correct
data, misleading key. The top-level `signal_source` field already identifies the producer
correctly; the prefix is redundant and wrong.

---

## Decision: No version bump

v1.0 is retired. No v2 consumer (P_400 reader) exists. Rename in place as a coordinated
same-WO change across all producers. Spec doc updated in-place; no packet version bump.
