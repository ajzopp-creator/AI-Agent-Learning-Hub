## Problem

Entry 011 (P_805 doc, 2026-07-14): the Outlook/Microsoft 365 tenant rejects
Basic Auth (plain IMAP `LOGIN` with an app password) entirely. Thunderbird
itself authenticates this account via OAuth2. `MOVE_SKIP_ACCOUNTS =
{"outlook"}` was added to permanently skip Outlook in Phase 5.3 (server-side
move to `ExtractedNewsletterFolder`). Phase 3 (mbox read) is unaffected —
Outlook mail is still fully scanned and produces signals; those messages
just stay in Inbox instead of being auto-filed.

Tony wants Outlook included in the live move, to any destination folder.
Destination doesn't change the blocker — the auth mechanism does. Fix
requires OAuth2 (`msal` + one-time browser consent + token cache/refresh),
then `AUTHENTICATE XOAUTH2` instead of `LOGIN` for the outlook account only.

## Prerequisite — Tony's action, not Claude's

Same principle as IMAP app-password credentials: Claude never handles
sign-in. OAuth2 needs a one-time Azure AD (Microsoft Entra) app
registration that only Tony can do, in his own browser, logged into his
own Microsoft account:

1. Go to entra.microsoft.com (Microsoft Entra admin center) → App
   registrations → New registration.
2. Name it anything (e.g. "P805 IMAP OAuth"). Supported account types:
   single tenant is fine (personal Microsoft 365 account).
3. Platform config → Add a platform → "Mobile and desktop applications" →
   redirect URI `http://localhost`.
4. API permissions → Add a permission → APIs my organization uses →
   "Office 365 Exchange Online" → Delegated permissions →
   `IMAP.AccessAsUser.All`.
5. Authentication → enable "Allow public client flows" = Yes.
6. Copy the "Application (client) ID" from the Overview page — this is
   not a secret, it's fine to store in `config.py` like `IMAP_USERNAMES`.

Once Tony has the client ID, code work (below) can proceed independently
of whether he's finished this step, but nothing is testable until he has.
