## Corrected understanding (verified this session, not assumed)

The parent WO framed this as "add a construction-time guard, currently
enforced only by written skill-file rule." Reading the actual code changed
the picture in two ways:

1. **The SIGNAL_V2 emit path (`emit_signal.py` -> `signal_builder.py`) is
   NOT the source of the CDNA/INCY/MA/V incidents.** Its `signal_source`
   defaults to `config.DEFAULT_SOURCE` ("P_115") -- but `config.py`'s own
   2026-07-24 comment confirms this is correct by design: this emitter
   only ever sends P_115's own stock signals to P_400; P_116/117/118/
   910/920 "should never appear in signal_source" here. Not a bug.
2. **What IS a real, separate gap:** `signal_source` on the live path has
   ZERO validation. `config.py` defines `VALID_SOURCES = frozenset({"P_115",
   "P_300", "manual"})`, but its own comment says this is dead code --
   only the retired `P400SignalRecord` validator ever checked it
   (archived 2026-07-24); the live `SignalV2` schema has no restriction on
   `signal_source` at all (confirmed by reading `signal_schemas.py`
   directly -- every other field there has a `field_validator`; this one
   doesn't). A typo or garbage value would sail through today.
3. **The actual CDNA/INCY/MA/V incidents live in the 27-column Tracker
   Dashboard (Excel), not the SIGNAL_V2 path** -- that's a manually-filled
   spreadsheet during chat sessions, matching the skill file's own
   description. `tracker_writer.py` reads whatever SignalSource value is
   already in the sheet and forwards it verbatim; it has no way to
   independently know whether "P_115" or "P_118" was the correct value
   for a given row, so it structurally cannot catch a valid-but-wrong
   attribution -- only a validity check (rejecting values that aren't a
   real Signal Source ID at all) is achievable in code here. The rest
   stays a session-discipline problem, which is what the skill file rule
   already targets; this WO doesn't oversell a full code fix for that half.
4. **Unrelated bug found while reading this file, flagging separately:**
   `tracker_writer.py` imports `TRACKER_PATH`, `WRITTEN_BY`,
   `REQUIRED_FIELDS`, `COLUMN_MAP` from `config.py` -- none of these names
   exist anywhere in the current `config.py`. As written, this script
   raises `ImportError` on the first line and cannot currently run. Either
   it's dead/superseded code, or `config.py` lost these constants in a
   refactor. Needs a decision (fix it or archive it) before item 3 above
   can be built on top of it -- included in this WO's scope since it
   blocks that item, not because it's part of the attribution standard.
