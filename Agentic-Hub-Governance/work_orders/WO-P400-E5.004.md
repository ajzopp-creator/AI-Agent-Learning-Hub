## WHY

`p400-project-context` SKILL.md's Bugs Already Fixed table has rows for
both E4.005 and E4.006. Neither has a matching `test_e4005_*` or
`test_e4006_*` function in `tests\test_p400_known_bugs.py` -- the
cross-cutting regression guard that table is supposed to mirror. Found
2026-08-08 by WO-P000-E13.001 Phase 4's own correspondence check
(`table_guard_correspondence`), the same automated check that Finding 6
led to for E2.016.

Root cause: when E4.005 (2026-07-26) and E4.006 (2026-07-27) were built,
WO-P020-E1.003's Hub-wide rule ("every fixed bug gets a matching
regression test in the same session") was satisfied by dedicated test
files -- `test_market_hours.py`, `test_market_holidays.py`,
`test_evaluate_signal.py` -- which is real coverage, not missing. But
neither session added the *separate* entry the guard file needs, because
at the time nothing checked for that specific desync. Same shape as
Finding 6, different WOs.

**Not a coverage gap, a mirroring gap.** `is_market_open_now()` and
`_sessions_since_earnings()`'s holiday handling are both genuinely tested
elsewhere. This WO is about the guard file specifically, not about
writing new behavioral coverage from scratch.

## SCOPE

1. Add one guard test to `tests\test_p400_known_bugs.py` covering the
   *current* state of `domain\market_hours.py`'s `is_market_open_now()` --
   which is E4.006's holiday-aware version, since E4.006 supersedes
   E4.005's wall-clock-only behavior the same way the existing
   `test_e2012_*` tests already test E2.012's current (superseded) state
   rather than each historical increment separately.
2. A single combined test is enough -- name it so both WO tokens are
   present (e.g. `test_e4005_e4006_market_open_wall_clock_and_holiday_aware`)
   rather than writing two near-duplicate functions for what is, in the
   current code, one function's behavior.
3. Suggested shape (confirm exact signature against the live file before
   writing -- this WO does not re-verify `is_market_open_now()`'s current
   parameters): BEHAVIOR test asserting `is_market_open_now()` returns
   `False` on a real 2026 weekday holiday (e.g. Labor Day, 2026-09-07,
   during normal trading hours -- wall-clock alone would say open) and
   `True` on an ordinary weekday during trading hours. Mirrors the
   boundary already proven in `test_market_holidays.py`, just added to
   the guard's own file per its cross-cutting-mirror purpose.
4. Re-run the correspondence check (or just grep) to confirm `e4005` and
   `e4006` no longer appear in WO-P000-E13.001's "gaps" list if that check
   is re-run.

## OUT OF SCOPE

- Writing new coverage for holiday logic itself -- `test_market_holidays.py`
  already has 13 dedicated tests (WO-P400-E4.006 Execution log). This WO
  only adds the guard's mirror entry.
- The `E3.011` correspondence-check item from the same Phase 4 run -- that
  one was confirmed a naming artifact of the combined
  `"E3.010/E3.011 (4th recurrence)"` table row, not a real gap. No action
  needed there.
- Early-close days (day after Thanksgiving, Christmas Eve) -- explicitly
  out of scope in E4.006 itself, stays that way here too.
