# WO-P400-E3.006 -- No Vault Write Path for APPROVED Trades (Stock or Options): Missing order_id Field, No Submitted/Declined Disposition
**Status:** CLOSED
**Owner:** P_400
**Affects:** (none -- internal P_400 only; vault_schemas.py, record_writer.py, cli.py)
**Depends On:** None
**Acks:** N/A

---

## WHY

`write_p400_record()` in `record_writer.py` is generic (any verdict), but
`commands.py cmd_evaluate()` only calls it when `verdict == "BLOCKED"` --
there is no call site for a stock trade that comes back APPROVED. Same
gap on the options/spread side: `write_options_eval_record()` and
`write_spread_eval_record()` map PASS/CAUTION/BLOCK to APPROVED/
APPROVED_WITH_CAUTION/BLOCKED and DO get called regardless of verdict
(WO-P400-E3.004 fixed that half), but neither function nor `P400Record`
itself has any field to hold a broker order_id once Tony actually submits
the trade.

Found live 2026-07-05: MSTR evaluate --pre-market came back APPROVED (7
shares, R:R 3.08), spec rendered, Tony typed it into Schwab and reported
back order_id=5365031365. There is no schema-validated place to put that
order_id -- `P400Record` has no `order_id` field, and the stock path has
no APPROVED call site to write anything at all.

Second gap surfaced in the same conversation: if Tony declines an
APPROVED signal instead of executing it, there is currently no record of
that decision either -- an approved-but-skipped trade and an
approved-but-executed trade both currently produce zero vault entries on
the stock path. The two states need to be distinguishable after the fact
(e.g. for P_020 expectancy review of Council accuracy), not both silently
absent.

---

## SCOPE

1. `vault_schemas.py` `P400Record` -- add `order_id: Optional[str] = None`.
2. `vault_schemas.py` `P400Record` -- add lifecycle/drop_reason values to
   distinguish "approved, executed" from "approved, declined": either a
   new `lifecycle_status` value (`SUBMITTED`) plus a new `drop_reason`
   value (`MANUAL_DECLINE`), or equivalent -- Tony's call on naming during
   implementation, consistent with existing enum-like string conventions
   already in the schema comments.
3. `record_writer.py` -- extend `write_p400_record()` signature to accept
   `order_id: Optional[str] = None`; update `_resolve_lifecycle_status()`
   to return `SUBMITTED` when an order_id is present and verdict is
   APPROVED/APPROVED_WITH_CAUTION.
4. `cli.py` / `commands.py` -- new subcommand, e.g.
   `cli.py record SYMBOL --order-id ID` (submitted path) and
   `cli.py record SYMBOL --decline` (declined path), both writing via
   `write_p400_record()` with the appropriate verdict/lifecycle_status
   carried over from the prior evaluate/spec run for that symbol.
5. Options/spread parity -- `write_options_eval_record()` and
   `write_spread_eval_record()` gain the same `order_id` passthrough and
   declined-disposition support so an options/spread trade has the same
   submitted-vs-declined distinction as stock.
6. Tests -- `test_record_writer.py` additions: order_id populates and
   round-trips; SUBMITTED lifecycle_status resolves correctly; declined
   disposition writes with correct drop_reason; regression that existing
   BLOCKED-path tests are unaffected.

## OUT OF SCOPE

- Any change to Council verdict logic itself -- this WO is disposition/
  audit-trail plumbing only, not a sizing or block-condition change.
- Automated Schwab order-status polling / fill confirmation -- order_id
  capture here is manual (Tony reports it back), matching the rest of
  P_400's manual-execution Phase E2/E3 scope boundary.

## ACCEPTANCE CRITERIA

- An APPROVED stock trade that Tony executes has a schema-validated
  vault record with order_id populated and lifecycle_status=SUBMITTED.
- An APPROVED stock trade that Tony declines has a schema-validated
  vault record distinguishable from a submitted one (different
  lifecycle_status/drop_reason), not silence.
- Same two dispositions available on the options and spread paths via
  the existing write_options_eval_record / write_spread_eval_record
  call sites.
- Regression: BLOCKED-path stock/options/spread writes unaffected.
