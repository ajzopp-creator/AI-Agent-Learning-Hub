## WHY (2026-07-08 session)

Operator has been running IntelliScan `P300_Potential Crossover_v12` manually and
reviewing each hit -- slow, and the curated catalog grows ~5-40 patterns per
session. VP licenses ~1,500 symbols and exports 10-year History Grids per symbol.
A deterministic Python encoding of the scan, run against bulk exports, replaces
the manual review loop for research purposes and builds a statistically valid
outcome baseline stratified by sector.

**Phase 0 verified (3 sample files: SPY, AAPL, DE):**
- Exports span 10 years (2,512 bars) but ALL predictive columns (ST/MT/LT Diff,
  Predicted High/Low, Triple Cross, Neural Index) are zero/blank before
  2021-07-14 and fully populated after -- VP backfills predictions exactly
  5 years. Usable window = ~1,250 bars/symbol. Detection must guard the boundary
  (detect dynamically per file: first persistently-nonzero ST Diff).
- Export layout: 22 columns, 3 unnamed (Neural Index is text up/down; Triple
  Cross is 3 columns short/medium/long). New reader module required -- do NOT
  reuse vp_xlsx_reader.

**Phase 1 verified (scan decoded from .isc XML):** Potential Crossover v12 =
AND of: (1) MT crossover up exactly 1 bar ago (MTDiff <=0 -> >0);
(2,3,4) ST/MT/LT Diff trend up; (5) Neural Index up; (6) Predicted range
direction up (PredHighDiff>0 AND PredLowDiff>0); (7) last Triple Cross
crossover DOWN (reversal context); (8) PredHigh > Close;
(9) Close < Verified Resistance Zone -- NOT replicable from grid exports
(IntelliScan-proprietary); approximated via nearest swing-high above close,
tagged approximate. Optionable = metadata, ignored.

**Live detection rates (decoded rules vs sample files, 5-yr windows):**
STRICT ~0.16-0.56%/bar (2-7 hits per symbol per 5 yr); RELAXED (drops only the
triple-cross-down condition -- continuation variant) ~2.6-3.1%/bar (~35/symbol).
Detections cluster on market-wide regime days (2023-05-05 fired on SPY and DE).

## APPROVED DECISIONS (Tony, 2026-07-08)

1. Resistance-zone condition: approximate with swing-high. APPROVED.
2. Two-tier detection: every detection tagged STRICT or RELAXED. APPROVED.
3. Scope: ~12-15 symbols/sector, ~250-300 manual exports, incremental --
   start after build. APPROVED ("we can always add once Bulk AddPattern is built").

## SCOPE

- NEW `research_catalog.db` -- same 7-table schema as live catalog PLUS:
  `symbols.sector` (TEXT), `pattern_instances.detection_tier` (TEXT
  STRICT|RELAXED), `forward_labels.significant_move_15` (INTEGER 0/1),
  `pattern_instances.data_origin_type = 'BULK_SCAN'`.
- Forward horizons unchanged: 5/7/10/15/20 days; return_pct stored as decimal
  fraction (M-020).
- Spacing rule: no second detection within N bars (config, default 5) of a
  prior detection on the same symbol+tier -- prevents overlapping-window n
  inflation.
- Sector sourced from operator-maintained mapping file
  `data/reference/sector_map.csv` (symbol,sector) -- grid export carries no
  sector metadata.
- Input naming: `10_Pattern_<SYMBOL>.xlsx`, sheet name = symbol, dropped in
  `data/bulk/` (new folder). Checkpoint/resume so a crash at file N does not
  restart from zero.
- Lock + Temp-DB + Atomic Move for every write batch (Must-rule #2).
- Operator launcher `P_300_BulkExtract.bat` -- goto-label pattern, no delayed
  expansion (M-032).
- Pipeline B NEVER reads research_catalog.db under this WO. Any merge or
  analog-pool use is a separate future WO gated on Phase 5 validation.

## OUT OF SCOPE

- Any change to live *catalog.db, Pipeline A (AddPattern), or Pipeline B.
- Sector-level result analysis (Phase 5, after scale-out).
- 2016-2021 price-only half of exports (retained in DB bars for label math
  only; no detections there).
