# WO-P020-E1.001 -- Exit Matching: Skip-Bug + Qty-Aware Allocation

**Status:** PENDING
**Owner:** Claude
**Affects:** P_020
**Depends On:** --

---

## WHY

Two compounding bugs in the live trade ingestion pipeline mean closed positions
are not reflected in the database, and P&L is misattributed when they are.

1. `ingest_pipeline.py` `run_ingest()`: when `insert_trade()` returns None
   because the entry's `schwab_transaction_id` already exists (true every week,
   since the weekly pull re-fetches the full year from 2026-01-01), the loop
   does `skipped += 1; continue` -- it never builds or inserts exits for that
   entry, even when the position has since closed. Once a trade's entry is
   first inserted, it can never be marked closed again no matter how many
   times the weekly update runs.

2. `schwab_mapper.py` `_match_exits_to_entries()`: matches exits to entries by
   chronological order within a `full_symbol` group, but has no concept of an
   entry's remaining quantity. When a contract has more than one separate
   entry (e.g. two 1-lot buys on the same option, days or hours apart), the
   first entry processed greedily consumes up to 3 exits regardless of its
   own qty, can be marked "closed" using qty that doesn't belong to it, while
   the sibling entry gets zero exits and stays open forever.

Confirmed via direct trace on AA (two separate 1-lot round trips on the same
contract, 6/8-6/10/26) and via a DB scope check: 8 of 21 open/partial AJZ6348
trades have unrecorded closes sitting in the most recent raw pull, including
all five of P_116's nominally "open" positions.

---

## SCOPE

1. `db_writer.py` -- add `get_trade_id_by_schwab_id(conn, schwab_transaction_id)`
   returning the existing trade_id, or None.

2. `ingest_pipeline.py` `run_ingest()` -- when `insert_trade()` returns None,
   look up the existing trade_id instead of skipping. Build exits against it
   (`insert_exit()` already dedupes safely per `(trade_id, exit_number)`),
   recompute status from total qty closed, and update `total_commissions` to
   reflect the full round trip (currently only entry commission is stored on
   first insert).

3. `schwab_mapper.py` `_match_exits_to_entries()` -- replace the chronological
   grab-up-to-3 with a qty-aware allocator:
   - Group entries and exits by `full_symbol`.
   - Within each group, process entries oldest-first by open_date.
   - Consume exits against each entry's remaining qty; split a single exit
     fill across entries if its qty exceeds one entry's remaining capacity
     (weight price/commissions proportionally to qty on the split).
   - Cap remains 3 exit slots per entry (schema limit). If a 4th distinct
     exit chunk is needed for one entry, merge it into exit_3 as a weighted
     average rather than dropping it, and log clearly that a merge occurred.
   - Fix the orphan-exit log message so a 4th-exit-truncation case isn't
     described as "predates all entries."

## ACCEPTANCE CRITERIA

- Re-running the scope-check script against AJZ6348 after the fix: zero
  open/partial trades with unrecorded closes in the latest raw pull.
- AA's two separate round trips (6/8 entry->6/8 exit, and 6/8 entry->6/10
  exit) land as two distinct closed trades with correct individual P&L --
  not one trade absorbing both exits.
- LION, AAL, ADM close correctly with exit qty matching entry qty exactly.
- Existing already-closed trades in the DB are unchanged after a re-run
  (idempotent -- insert_exit dedup prevents double-counting).
- Audit log clearly distinguishes "duplicate entry, exits updated" from
  "duplicate entry, no new exits" from genuine new inserts.
