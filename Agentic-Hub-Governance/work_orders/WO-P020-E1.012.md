# WO-P020-E1.012 -- Session INIT Command Block Is Non-Functional (`Start-Job` Does Not Survive an MCP Tool Call)

**Status:** IN_PROGRESS
**Owner:** P_020
**Affects:** P_020 only (`docs\P_020_MASTER_SYSTEM_DOCUMENTATION_v1_0.md` Section 9.6, Section 8;
  `SESSION_INITIALIZATION_PROMPT_v2_9.md` Step 2)
**Depends On:** none
**Related:** SIP v3.1 changelog (2026-06-18) -- "Start-Process -NoNewWindow reference
  removed (banned per ERROR 002)". That change correctly banned `-NoNewWindow`, but the
  replacement it installed (`Start-Job + cmd /c`) was never verified end-to-end from a
  live MCP session. It has been the documented INIT path since 2026-06-18.

---

## WHY

Every P_020 session opens by running the INIT block. The block documented in Section 9.6
does not work and has not worked since it was written.

Observed 2026-08-03 at session start:

1. Ran the Section 9.6 block verbatim. `Start-Job` returned a job object, reported
   "job started", exited clean.
2. Separate MCP call with `Start-Sleep 20; Get-Content "C:\Temp\init_out.txt"` --
   relay stalled and burned the full 4-minute MCP timeout.
3. `Write-Output "ping"` at 15s confirmed the relay itself was healthy.
4. `Test-Path "C:\Temp\init_out.txt"` returned false. The file was never created.

**Root cause:** each Windows-MCP PowerShell call is an isolated process. The background
job is a child of that process and is torn down when the call returns -- before `cmd /c`
ever flushes output to disk. This is the same failure mode already recorded in the
`peh-handoff` skill ("Start-Job/Get-Job do not survive across separate MCP tool calls"),
but Section 9.6 was never reconciled with it. Two governance documents contradicted each
other, and the wrong one was the one INIT tells Claude to follow.

**Secondary defect:** putting `Start-Sleep` in the read-back call is what stalled the
relay. The sleep must not be inside an MCP call.

## WHAT WAS DONE

Working pattern, confirmed live this session -- INIT ran and returned the full block:

```
$ts = Get-Date -Format "HHmmss"
Start-Process -FilePath "<p140 python>" -ArgumentList '"<script>"' `
  -WindowStyle Hidden -RedirectStandardOutput $out -RedirectStandardError $err
```
then `Get-Content $out -Raw` in a **separate** call, no sleep.

`-WindowStyle Hidden` is not the banned `-NoNewWindow`. The ban stands.

Changes applied by `Agentic-Hub-Governance\verify\run_this.py`:

1. **Section 9.6** -- replaced the `Start-Job` block with the `Start-Process
   -WindowStyle Hidden` + redirect block. Rule line now bans `Start-Job` alongside
   `-NoNewWindow`, and states the no-`Start-Sleep`-in-MCP-call and unique-filename rules.
2. **Section 8 (Error Corrections Log)** -- new permanent entry.
3. **SIP Step 2** -- pointer text updated to name the correct pattern.
4. **SIP changelog** -- v3.2 entry.

Backups written alongside each file as `*_backup_2026-08-03.md` before any write.
