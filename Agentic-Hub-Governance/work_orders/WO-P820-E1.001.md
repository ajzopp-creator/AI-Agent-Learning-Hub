## WHY

P_400's `record` command only submits a cached APPROVED/APPROVED_WITH_CAUTION/
APPROVED_WITH_SEVERE_WARNING verdict -- confirmed live 2026-09-04 on CRUS
(P_300 signal, entry 113.45/stop 109.80/target 119.94, BLOCKED on R:R
~1.78:1, no eval_cache present for the symbol on disk). No path exists in
P_400 to record a trade Tony executed despite/without a Council approval.
P_820 already owns the vault-write mechanism and holds the highest-priority
slot in P_020's attribution resolver -- the natural fallback record path
rather than building a duplicate mechanism inside P_400.

## DECISIONS (2026-09-04)

1. `why_code` stays the trade's true origin project (e.g. `P_300`), never
   `P_820` or `OVERRIDE` -- same principle as the existing P_117
   fundamentals-recheck rule (a P_820 write doesn't change attribution).
2. Override context (BLOCKED reason, R:R, "no eval_cache present", etc.)
   goes in free-text `notes` -- no dedicated schema field yet.
3. Quantity and paper-vs-real have no `P820Record` schema field currently
   -- captured in `notes` as free text until a follow-on P_800-owned WO
   adds them properly. Not opened this WO -- scope here is documentation
   only.
