# WO-P400-E2.019 — Fix Paper Trade Record Routing

**Status:** CLOSED
**Owner:** P_400
**Affects:** P_800
**Depends On:** none
**Related:** WO-P400-E2.005 (stays OWNER_DONE, not CLOSED, until this closes)

---

## Problem

`record_writer.py` never got the routing branch E2.005 was supposed to add.
Paper trades and real trades write into the same book. `portfolio.py` heat
and exposure math has been commingling paper and real risk on every paper
session run so far — this is a live bug, not stale config.

E2.005's original acceptance criteria (flag parses, sizing unaffected)
still hold. The gap is narrower: routing was never wired.

## Fix

One function. `record_writer.py` branches on `trade_mode_value` and passes
the `PAPER_BOOK_DIR` path (or a folder override) into the `write_to_vault`
call instead of hardcoding P400 schema resolution.

## Governance Note

`write_to_vault`'s folder resolution lives in P_800's `handle_write()`.
This likely needs a P_800 Ack before CLOSED, per Section 3.12 (schema/path
changes touching P_800-owned code require P_800 Ack).

## Acceptance Criteria

- [x] Paper trades write to `PAPER_BOOK_DIR`, never the real book
- [x] Real trades unaffected -- same path as today
- [x] `portfolio.py` heat/exposure math reads only the real book by default
- [x] Test added covering both routing branches
- [x] P_800 Ack received on `handle_write()` folder-resolution change -- 2026-07-21, see Ack note below
