# WO-P400-E2.014 -- Gate 3 (Concentration) Ignores Posture Multiplier on max_position$

**Status:** CLOSED
**Owner:** P_400
**Affects:** (none -- internal P_400 only; sizing math)
**Depends On:** None
**Acks:** N/A

---

## WHY

`domain\sizing.py` `three_gate_size()` -- Gate 3 (Concentration) appears to size
against the STANDARD/FULL max_position$ value ($1,633.47) regardless of the
current `risk_mode` read from P_010_RiskConfig.json, instead of applying the same
posture multiplier Gate 1 (Risk) correctly applies.

Found during AVGO live evaluate, 2026-06-22, posture=HALF (75% multiplier per
P_000 Risk Mode Adjustments table):

  cli.py evaluate AVGO --snapshot snapshot_AVGO.json --cash 6073

  Result: Shares=4, gate=CONCENTRATION

  Expected at HALF: max_position$ = $1,225.10 (75% of $1,633.47)
    $1,225.10 / $393.40 entry = 3.11 -> floor = 3 shares

  Actual behavior implies: max_position$ = $1,633.47 (STANDARD/FULL, unreduced)
    $1,633.47 / $393.40 entry = 4.15 -> floor = 4 shares

Gate 1 was not binding on this trade (risk-based share count was much higher than
4), so this is the first live evaluate where Gate 3 was the deciding gate while
posture was below STANDARD -- the bug was latent until this combination occurred.

If uncorrected, every concentration-bound trade while posture is HALF or
OFF/CORRECTION will be oversized vs the account parameters in P_000 (~33% over
at HALF, ~100% over at OFF/CORRECTION).

---

## SCOPE

1. `domain\sizing.py` `three_gate_size()` -- confirm whether Gate 3 reads
   `max_position$` from a posture-adjusted source or a hardcoded/STANDARD value.
   Apply the same risk_mode multiplier table Gate 1 already uses (OFF/CORRECTION
   50%, HALF 75%, STANDARD/FULL 100%, HOT tiered) to Gate 3's cap.
2. `test_sizing.py` -- add a case asserting Gate 3 cap scales with risk_mode
   (HALF and OFF/CORRECTION at minimum), not just Gate 1.
3. No change to Gate 1 or Gate 2 -- this is Gate 3 only, based on current evidence.
