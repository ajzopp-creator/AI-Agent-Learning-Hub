# WO-P400-E5.006 -- compare() NEITHER Disposal Gap

**Status:** CLOSED -- code built, unit-tested, live-verified same session (implementing session, 2026-08-11). Independently re-verified 2026-08-13 by a session that did not implement the fix, per WO_COMPLETION_GATE.md.
**Owner:** P_400
**Affects:** none -- internal P_400 only (compare_vehicles.py, commands.py, tests\test_compare_vehicles.py)
**Depends On:** none

---

## WHY

Found live 2026-08-11: `batch-2b` hard-failed on a Nasdaq earnings-calendar
gap (neither HAL nor VKTX had an officially-confirmed next-earnings date),
so the session fell back to the manual `fetch-snapshot` / `fetch-chain` /
`compare` flow for both symbols. Both returned `RECOMMENDATION: NEITHER`
(R:R below 2.0 on every vehicle). Both packets then sat in the live signal
inbox indefinitely -- `cmd_compare()` prints the comparison table and
returns; it never calls `archive_packet()` or writes a record, on any
recommendation. Every future `screen-all` would keep re-surfacing them,
re-fetching live Schwab data (re-billed) every session, forever.

This is not the same bug the 2026-08-07 disposition fix
(`batch_2b_disposition.py`) covers -- that fix wires disposal into
`batch-2b`'s own per-symbol `evaluate_signal()` loop only. `cmd_compare()`
was never touched by it and never had any disposition wiring in the first
place. Same recurring failure shape as E3.010/E3.011 (Must Not #7 in
`p400-project-context` SKILL.md): a result value (`NEITHER`, from
`domain\vehicle_selector.py::compare_vehicles()`) that a downstream
consumer never got wired to. At least a 5th recurrence of that class.

Tony's directive (2026-08-11): once a signal reaches P_400 it is either a
trade or it is not -- there is no hold-and-recheck state anywhere else in
the architecture (Tier-1 FAIL, BLOCKED, and ENTRY_MISSED all dispose
immediately via `archive_packet()` + a written record). `NEITHER` must
behave identically. Re-qualification, if a symbol genuinely deserves
another look later, is the trade-selector projects' job (P_115/P_300/
P_118 emitting a fresh signal) -- not P_400 holding a stale packet.

## WHAT WAS BUILT

- `compare_vehicles.py`: `run_comparison()` gained a required `trade_mode:
  TradeMode` parameter. New `_dispose_if_neither()` helper -- no-op
  (returns `""`) for every recommendation except `NEITHER`; on `NEITHER`,
  calls the existing `drop_signal(packet, "RR_INVALID", trade_mode)`
  (`application\drop_signal.py`, unchanged), which archives the packet and
  writes a `REVIEWED_NO_TRADE` record, then appends a confirmation line to
  the printed table matching the exact message shape `cmd_evaluate()`'s
  `--drop-reason` path already uses. No new `drop_reason` enum value
  needed -- `RR_INVALID` already existed in `drop_signal()`'s docstring
  enum, unused until now.
- `commands.py`: `cmd_compare()`'s call site updated to pass
  `TradeMode.REAL` (already imported at module level -- net-zero line
  change, file stays at the existing 300-line cap).
- No CLI changes. No new `council_codes.py` entry (this is a disposal
  path, not a Council verdict).

## NOT IN SCOPE

- `--paper` flag for `compare` -- never existed before this WO; `trade_mode`
  is hardcoded `TradeMode.REAL` at the `cmd_compare()` call site. Nothing
  in today's session used `--paper` anywhere. Revisit only if paper-mode
  `compare` is ever actually needed.
- `OPTION_OVERRIDE_ONLY` disposal -- SIP already routes that recommendation
  through the manual override protocol (arch doc Section 2.5 item 5),
  unchanged; it is not a terminal STOP the way `NEITHER` is.
- `batch-2b`'s separate, unrelated earnings-calendar hard-fail (found live
  the same session, on the same two symbols, before this fix): not a code
  defect -- `refresh-earnings-calendar` and the hard-fail-rather-than-assume
  behavior are both working exactly as WO-P400-E5.002 designed them. Fixed
  via documentation only, same session: `p400-project-context` SKILL.md
  updated to describe batch-2b's Nasdaq-cache-only earnings source and the
  now-dead manual bridge file. No WO needed for that half of the finding.
