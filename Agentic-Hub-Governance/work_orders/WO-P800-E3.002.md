# WO-P800-E3.002 -- Same-day same-symbol filename collision in vault_writer (P020 schema)

**Status:** CLOSED (2026-07-24, independent review this session -- all Acceptance Criteria verified against live code/vault/archive; see Independent Review section below)
**Owner:** P_800
**Affects:** P_020 (vault export notes silently overwrite on collision)
**Depends On:** None

---

## Context

Filed from a P_020 session (2026-07-11) while closing out WO-P020-E1.005
(Obsidian vault integration -- `write_to_obsidian.py`). During the first
real `--commit` run (197 closed/partial 2026 trades), 197 trades produced
only 190 files. 7 were lost to filename collisions.

## The bug

`filename_builder.py`'s P020 path builds `YYYY-MM-DD_SYMBOL.md` from
`signal_date` (mapped from `close_date`) + `symbol` only. It does not
consider `system` or `trade_id`. When two different trades on the same
underlying close on the same calendar date -- e.g. a P_115 position and a
P_300 position both closing AAPL the same day, or the same symbol traded
twice intraday under the same system -- the second `write_to_vault` call
overwrites the first note via `overwrite=True`. No error, no warning,
just silent data loss of the earlier trade's record.

**Observed in production, 2026-07-11 commit run:**
- `2026-03-11_POWL` -- 3 separate P_118 trades collapsed into 1 note
- `2026-01-28_VSAT` -- 2 separate P_118 trades collapsed into 1 note
- `2026-01-13_GOOG` -- 2 separate P_118 trades collapsed into 1 note

This is not unique to P_020 -- any schema keyed on `date + symbol` alone
(P115, P300, P400 all follow the same pattern in `filename_builder.py`)
has the same theoretical exposure. P_020 is the first place it's been
observed to actually happen, because P_020 can have multiple independent
trading systems opening and closing the same ticker same day, which the
signal-generation schemas (P115/P300/P400) don't really do.

## Why P_800, not P_020

`filename_builder.py` and the filename convention it enforces are P_800's
contract, same as every other schema. P_020's `write_to_obsidian.py`
already calls the public `write_to_vault()` interface correctly -- it has
no way to influence the filename from the outside, and per project
boundary rules P_020 doesn't edit `obsidian_writers/` files directly.

## Options (P_800 owner to decide, not prescribed here)

1. **Add `trade_id` (or equivalent per-schema disambiguator) to the P020
   filename**, e.g. `YYYY-MM-DD_SYMBOL_TRADEID.md`. Fully fixes it for
   P020. Requires `trade_id` to flow through to `filename_builder.py`
   (it's already in the source data, just not passed in the current
   `write_to_obsidian.py` payload -- would need adding to the call).
2. **Detect collision and warn instead of silently overwriting** -- lower
   effort, doesn't fix data loss but at least surfaces it in the log
   instead of failing silently. Could be a stopgap while (1) or (3) is
   scoped.
3. **Leave as-is, document the limitation** -- if same-day multi-system
   closes on one symbol are rare enough that Tony would rather manually
   check the audit summary counts (written vs. total) after each run than
   pay for a schema change. `write_to_obsidian.py` already prints
   `Total` vs `Written` counts, though today those match even when
   collisions occurred, since `write_to_vault` returns `True` on every
   successful write -- **note: the count mismatch (197 written vs 190
   files) isn't currently visible from the script's own output; only
   found by `Get-ChildItem` on the vault folder afterward.** If option 3
   is chosen, `write_to_obsidian.py` should at minimum be updated
   (P_020-side fix, separate small item) to detect and log same-key
   collisions within a single run before calling `write_to_vault`, so the
   summary reflects reality without needing a P_800 change.

## P_800-Side Implementation (2026-07-21)

Files changed (archived before edit, same folders as originals):
- `obsidian_writers\domain\vault_schemas.py` -- added `trade_id:
  Optional[str] = None` to `P020Record`. 260 -> 261 lines.
- `obsidian_writers\domain\filename_builder.py` -- `_get_identifier()`
  now appends `trade_id` to the P020 filename when present
  (`SYMBOL_TRADEID` instead of `SYMBOL`); falls back to symbol-only when
  absent, so legacy callers and pre-fix notes are unaffected. P115/P300/
  P400/KB identifier logic untouched. 179 -> 198 lines (incl. docstring/
  changelog updates).
- `obsidian_writers\test_filename_builder.py` -- NEW, 5 tests: different
  trade_id -> different path; same trade_id -> same path (idempotency);
  missing trade_id -> old symbol-only behavior (regression guard);
  P115 and P300/P400 identifier logic unchanged even when a trade_id
  key happens to be present in the payload.

PEH-verified via Claude Code, 2026-07-21: 13/13 passed (5 new +
test_vault_schemas.py + test_write_route.py, run as a full regression
pass since vault_schemas.py is shared across every project). No fixes
