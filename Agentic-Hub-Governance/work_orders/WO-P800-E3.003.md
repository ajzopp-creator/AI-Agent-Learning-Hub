# WO-P800-E3.003 -- Rename TradeManagement -> TradeOrderManagement (Vault Folder Taxonomy)

**Status:** PENDING
**Owner:** P_800
**Affects:** P_115, P_300, P_400, P_020
**Depends On:** none
**Related:** WO-P400-E2.019 (paper/real routing -- uses current TradeManagement/P400
  path for now, not blocked on this WO)

---

## WHY

Tony's call: `TradeManagement` (no "Order") is the wrong name for the vault
namespace holding P115/P300/P400/P020 lifecycle notes. It should be
`TradeOrderManagement`, consistent with the P_400 project name and the
existing `TradeOrderManagement\signals\` folder.

Note this reverses the direction WO-P400-E2.012 (2026-06-17) concluded --
that WO found P_400's own config.py pointed at the wrong root
(`TradeOrderManagement\P400`, a dead folder) and corrected it to match the
already-live `TradeManagement\P400` used by P_800's VAULT_FOLDER_MAP. This
WO is not reopening that defect -- E2.012's diagnosis was correct given the
naming at the time. This WO changes the naming itself, hub-wide, by
deliberate decision.

## CURRENT STATE

`trading_journal\TradeManagement\` contains:
  _archive\, P020\, P115\, P300\, P400\
`trading_journal\TradeOrderManagement\` contains:
  signals\ (raw SIGNAL_V2/P400SIG JSON packets -- correctly named today)
  P400\ (pre-cutover archive only, per E2.012 disposition -- not live)

Live write path today: obsidian_writers/config.py `VAULT_FOLDER_MAP` maps
P115/P300/P400/P020 all to `TradeManagement/<project>`.

## SCOPE (proposed, not yet applied -- needs Tony sign-off on approach
before any file moves)

1. Physically move `TradeManagement\{P115,P300,P400,P020,_archive}` into
   `TradeOrderManagement\` (folder rename/merge -- `TradeOrderManagement`
   already exists with `signals\` and the old `P400\` pre-cutover archive
   in it, so this is a merge, not a clean rename).
2. `obsidian_writers/config.py` -- update all four `VAULT_FOLDER_MAP`
   entries (P115, P300, P400, P020) from `TradeManagement/...` to
   `TradeOrderManagement/...`.
3. P_400's own `config.py` -- `BOOK_DIR` currently hardcodes
   `TradeManagement/P400` independently of P_800's map (not derived from
   it). Needs the same update, plus `PAPER_BOOK_DIR` (see WO-P400-E2.019).
4. Audit P_115, P_300, P_020 project code for any hardcoded
   `TradeManagement` path references outside the shared config (same class
   of bug E2.012 found -- projects sometimes carry their own copy of a path
   instead of reading P_800's map).
5. Obsidian-side: check `Bases\*.base` files (e.g. `P020_Performance.base`)
   and any dataview queries for hardcoded `TradeManagement` folder
   references that would break silently on move.
6. Decide disposition of `TradeOrderManagement\P400\_pre_cutover_archive\`
   (pre-existing folder at the merge target) -- collision check before
   move.

## OUT OF SCOPE

- Any change to `TradeOrderManagement\signals\` -- already correctly named,
  not touched by this WO.
- WO-P400-E2.019's paper-book routing fix -- proceeds now against the
  current `TradeManagement/P400` root; will follow this WO's rename when it
  lands, not block on it.

## ACCEPTANCE CRITERIA

- All four VAULT_FOLDER_MAP entries point at `TradeOrderManagement/...`.
- No live files left behind in old `TradeManagement\` paths (verified
  empty or explicitly archived).
- A live evaluate() + record write for a real symbol lands in the new path
  and is read back correctly by book_loader.py (P_400 heat/exposure gate
  regression check, same class of verification as E2.012).
- Obsidian vault opens with no broken links/Bases queries referencing the
  old path.
- P_115, P_300, P_020 each confirm (Ack) their own code has no orphaned
  hardcoded `TradeManagement` references left over.
