## WHY

WO-P000-E4.002's 2026-08-29 Hub-wide audit found `docs\SESSION_INITIALIZATION_PROMPT.md`
carrying 3 changelog versions inline (v3.6, v3.4, v3.3) against the Hub
standard of current + prior version only, even though
`docs\P_115_SIP_CHANGELOG_ARCHIVE.md` already exists as the destination.
v3.3 was simply never moved over when v3.4/v3.6 landed.

Separately found in the same audit: the doc's footer reads "End of P_115
SIP v3.4" while the document header and Version field both say v3.6 --
stale by two version bumps. Bundled into this WO since it's a one-line fix
touching the same file.

Per WO-P000-E4.002's own design, this corrective edit happens in a P_115
session, not the P_000 session that found it.

## WHAT

1. Move the v3.3 changelog entry ("Full rewrite to P_300 SIP pattern...")
   from the live doc into `docs\P_115_SIP_CHANGELOG_ARCHIVE.md`.
2. Update the live doc's changelog to hold only v3.6 + v3.4 inline.
3. Update the "Pre-v3.3 history" pointer text to reflect the new boundary
   (archive now covers v3.3 and earlier).
4. Fix footer: "End of P_115 SIP v3.4" -> "End of P_115 SIP v3.6".

## ACCEPTANCE CRITERIA

- Live SIP changelog section holds exactly 2 version headers: v3.6, v3.4.
- Archive file contains the v3.3 entry, in order, nothing lost.
- Footer version matches document header/Version field.
- Backup of pre-edit file retained (`.backup_<timestamp>` convention).
