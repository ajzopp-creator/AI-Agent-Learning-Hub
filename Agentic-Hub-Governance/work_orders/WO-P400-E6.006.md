## WHY

Tony asked directly, live, looking at a real batch-2b run: "where is Option
evaluation??" -- reasonable question, because the printed table gave him no
way to tell. Both approved SBLK candidates showed `VEHICLE=STOCK` with zero
accompanying reason. Manual `compare` has always printed the full options
council verdict (BLOCK reason, spread%, OI, etc.) for exactly this
situation; batch-2b's summary table never did.

## FOUND LIVE -- 2026-08-19

Verified options evaluation was NOT actually missing -- `chain_SBLK.json`
existed on disk, timestamped during the run, with a real fetched contract
(Sep 18 $30 call, bid 0.65/ask 0.85, OI 747, spread_pct_of_mid=26.67%,
comfortably over the 10% max viability threshold). The evaluation ran
correctly and rejected the option correctly. The bug is pure reporting: the
reason for that rejection never made it into the printed output, so from
Tony's side it looked indistinguishable from options never being checked
at all -- a legitimate, serious-looking gap that turned out not to be a
correctness bug once traced.

**Root cause:** `domain/vehicle_selector.py`'s `compare_vehicles()` already
builds a complete, human-readable `recommendation_reason` string on its
`VehicleComparison` return object -- the exact text manual `compare`
prints. `application/batch_2b_scoring.py`'s `_vehicle_comparison()` helper
extracts only `(vehicle, rr, quantity, dollar_risk)` from that object and
discards `recommendation_reason` entirely before it ever reaches
`_build_candidate()` or the final report. The data existed the whole time;
it just never got carried past this one extraction point.

## FIX -- 2026-08-19

1. **`schemas.py`** (273 -> 277 lines): `RankedCandidate` gains
   `vehicle_reason: str`.
2. **`application/batch_2b_scoring.py`** (270 -> 279 lines):
   `_vehicle_comparison()` return type extended to include the reason on
   every path -- both the normal `compare_vehicles()` route (returns
   `comparison.recommendation_reason` verbatim) and the early-exit path
   where the chain fetch itself fails (previously returned no reason at
   all; now explicitly says so: "options chain fetch failed... -- stock
   used"). `_build_candidate()` takes the new param and includes it in the
   candidate dict. `_process_symbol()`'s call site updated to unpack and
   pass through the fifth tuple value.
3. **`application/batch_2b.py`** (207 -> 208 lines): `_print_ranked_table()`
   prints `c.vehicle_reason` on an indented line directly under each
   candidate's row.

**What did NOT change:** the actual vehicle-selection logic itself --
`compare_vehicles()`, the options council, sizing -- none of it was
touched. This is purely a reporting fix; the underlying decision was
always correct.
