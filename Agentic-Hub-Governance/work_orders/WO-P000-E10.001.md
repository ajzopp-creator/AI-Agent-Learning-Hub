## WHY

WO-P115-E3.001 added CALLER PROPAGATION and IMPERATIVE SWEEP checks to
`WO_COMPLETION_GATE.md` on 2026-08-03. Those checks bind future closures
only. They do not look backward at work already closed under the old
checklist.

A retroactive AST audit (349 production .py files, 2026-08-03) searched for
the WO-P115-E2.001 bug class: optional parameters a function accepts that
no production caller anywhere in the Hub ever passes. That is the signature
of a capability built into the owning layer and never wired into the layer
that calls it.

Result: 106 raw hits. The overwhelming majority are legitimate injection
defaults (`argv=None`, config paths, `now`/`today`/`as_of`, tuning
constants) and require no action. Roughly 12 carry domain data or behavior
switches and need per-item confirmation by the owning project.

This WO directs that triage. It does NOT assert the items are defects.

---

## SCOPE BOUNDARY -- READ BEFORE STARTING

**These are CANDIDATES, not confirmed bugs.** A default can be correct and
deliberate. During the audit the single item that was actually verified --
`write_p400_record()` with 16 orphaned option_*/spread_* params -- proved
to be a FALSE POSITIVE: it is called as `write_p400_record(**fields)`, and
AST cannot see keywords inside dict unpacking.

Each item below requires the owning project to answer one question:

> Is the default correct and intentional, or was a caller supposed to
> supply this and never did?

Record the answer either way. "Default is correct" is a valid, closing
outcome and should be written down so the item is not re-audited later.

**Known blind spot:** this audit finds parameters nothing passes. It does
NOT find the inverse -- a caller passing a value the function silently
ignores. Same family, different shape, out of scope here.
